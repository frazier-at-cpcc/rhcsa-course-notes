### Groups and /etc/group
- The objective: ==create, delete, and modify local groups and group memberships==
- A ==group== is a named GID that permissions can point at
  - Give the `devops` group write access to `/srv/app` once, then add or remove people
- Each group is one line in ==/etc/group==: `name:x:GID:member,member`
  - The member list holds supplementary members only
  - `/etc/gshadow` holds the group password (rarely used) and group administrators
- GID ranges match UIDs: 201 to 999 for system groups (`groupadd -r`), 1000 and up for regular groups
- Groups are plain files, so they persist across reboots with no extra step

### Primary and supplementary groups
- Every user has exactly one ==primary group==
  - Stored as the GID in the user's `/etc/passwd` line
  - New files the user creates get this group
  - By default the user private group (`alice` for alice)
- A user can have many ==supplementary groups==
  - Stored in the member list of each `/etc/group` line
  - Grant access to files owned by those groups; they do not change new-file ownership

:::figure 9.2-primary-supplementary.svg | `id` merges both sources: the GID in /etc/passwd and every /etc/group line that lists the user.

```console label="Terminal"
$ id alice
uid=2001(alice) gid=2001(alice) groups=2001(alice)
$ sudo usermod -aG devops alice
$ id -Gn alice
alice devops
$ grep ^devops: /etc/group
devops:x:3000:alice
```

- `id -Gn alice` lists group names only; `groups alice` does the same

### Creating, changing, and deleting groups

| Command | Does |
|---|---|
| `groupadd devops` | next GID above the highest in use (1000 and up) |
| `groupadd -g 3000 devops` | a specific GID |
| `groupadd -r backup` | system group, GID under 1000 |
| `groupmod -n ops devops` | rename |
| `groupmod -g 3100 ops` | change the GID |
| `groupdel ops` | delete |

```console label="Terminal"
$ sudo groupadd -g 3000 devops
$ sudo groupadd dbadmin
$ grep -E '^(devops|dbadmin):' /etc/group
devops:x:3000:
dbadmin:x:3001:
```

- ==groupmod -g== changes the number in `/etc/group` and the primary GID of its users, but files on disk keep the old number
  - Fix with `find / -gid 3000 -exec chgrp ops {} +`
- ==groupdel== refuses to remove a group that is someone's primary group

```console label="Terminal"
$ sudo groupdel ops
groupdel: cannot remove the primary group of user 'bob'
```

### Membership with usermod and gpasswd
- ==usermod -aG== appends supplementary groups; ==usermod -G== alone replaces the whole list
  - Forgetting `-a` silently drops the user from `wheel` and everything else
- `usermod -g` changes the primary group; `useradd -g` and `-G` set both at creation

```console label="Terminal"
$ sudo usermod -G dbadmin alice; id -Gn alice
alice dbadmin
$ sudo usermod -aG devops,dbadmin alice
$ id -Gn alice
alice devops dbadmin
$ sudo useradd -G devops -g dbadmin dave
$ id -gn dave; id -Gn dave
dbadmin
dbadmin devops
```

- ==gpasswd== edits one group's list without touching the user's other groups

| Command | Does |
|---|---|
| `gpasswd -a carol devops` | add one member |
| `gpasswd -d alice dbadmin` | remove one member |
| `gpasswd -M alice,carol dbadmin` | set the full member list |
| `gpasswd -A alice devops` | make alice a group admin |

```console label="Terminal"
$ sudo gpasswd -a carol devops
Adding user carol to group devops
$ sudo gpasswd -d alice dbadmin
Removing user alice from group dbadmin
```

- A group administrator can run `gpasswd -a` and `-d` on that group without sudo
  - Listed in the third field of the group's line in `/etc/gshadow`

### newgrp, sg, and when membership takes effect
- Group membership is read at login
  - A shell that was open before `usermod -aG` still has the old list
  - Log out and back in (or `su - alice`) to pick up the change; `id` with no name shows the current session
- ==newgrp devops== starts a new shell whose primary group is `devops`
  - New files belong to `devops`; `exit` returns to the old shell
- `sg devops -c "command"` runs one command the same way
- Only for groups the user already belongs to; others prompt for a group password, which is normally unset

```console label="Terminal"
$ touch a.txt; sg ops -c "touch b.txt"
$ ls -l a.txt b.txt
-rw-r--r-- 1 alice alice 0 Oct 21 19:43 a.txt
-rw-r--r-- 1 alice ops   0 Oct 21 19:43 b.txt
```

- For a directory where every new file should belong to the team, use setgid on the directory instead (10.2)

:::exam
- "Add alice to the sysadmin group" means a supplementary group: `usermod -aG sysadmin alice`. Leaving out `-a` removes her from every other group, including any the task set up earlier.
- Tasks often give a GID ("group sysadmin with GID 40000"). Check the result with `grep sysadmin /etc/group` and `id alice`.
- `id` in your own shell may be stale after a change. Check with `id alice`, which reads the files.
:::
