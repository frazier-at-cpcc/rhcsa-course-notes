### Accounts and the files behind them
- The objective: ==create, delete, and modify local user accounts==, change passwords, and adjust password aging
- Each local account is one line in ==/etc/passwd== and one in ==/etc/shadow==
  - `/etc/passwd`: readable by everyone; name, UID, primary GID, comment, home, shell
  - `/etc/shadow`: root only; the password hash and every aging value
- Plain files, so accounts survive a reboot with no extra step
  - Change them with the tools below; `vipw` and `vipw -s` lock the file if a hand edit is unavoidable
- UID ranges come from `/etc/login.defs`
  - 0 is root; 201 to 999 are ==system accounts== for services; people start at `UID_MIN` 1000

:::wide
| File | Fields, separated by colons |
|---|---|
| `/etc/passwd` | name, `x`, UID, GID of the primary group, comment (GECOS), home directory, login shell |
| `/etc/shadow` | name, hash, last change, min, max, warn, inactive, account expiration, reserved |
:::

- Shadow dates count days since 1 January 1970; an empty field means no limit
- The hash prefix names the algorithm: `$y$` is ==yescrypt==, the RHEL 10 default (`ENCRYPT_METHOD YESCRYPT`)
  - `!` in front of the hash means locked; `!!` means no password was ever set

### Creating users
- `useradd` fills in whatever you leave out
  - ==/etc/login.defs==: UID and GID ranges, `HOME_MODE 0700`, aging defaults, hash method
  - `/etc/default/useradd`: home base, shell, `/etc/skel`; print it with `useradd -D`

| Option | Sets |
|---|---|
| `-u 2001` | UID |
| `-g devops` | primary group (must exist) |
| `-G wheel,web` | supplementary groups |
| `-c "Alice Admin"` | comment (full name) |
| `-d /srv/alice` | home directory path |
| `-s /sbin/nologin` | login shell |
| `-e 2026-12-31` | account expiration date |
| `-r` | system account, UID under 1000 |

- With no `-g`, RHEL creates a ==user private group== with the same name and number
- The home directory is copied from `/etc/skel` with mode `0700`

```console label="Terminal"
$ sudo useradd -u 2001 -c "Alice Admin" alice
$ id alice; grep alice /etc/passwd
uid=2001(alice) gid=2001(alice) groups=2001(alice)
alice:x:2001:2001:Alice Admin:/home/alice:/bin/bash
$ sudo useradd -r -s /sbin/nologin -M webapp
$ id webapp
uid=998(webapp) gid=998(webapp) groups=998(webapp)
```

### Modifying users
- ==usermod== uses the same letters as `useradd`: `-c`, `-s`, `-u`, `-g`, `-G`, `-e`
  - `-d /new/home -m` changes the home path and moves the files
  - `-l newname` renames the login; the private group keeps its old name (`groupmod -n` fixes it)
- Running sessions keep the old values until the user logs in again

```console label="Terminal"
$ sudo usermod -c "Bob Builder" -s /bin/sh bob
$ sudo usermod -l robert -d /home/robert -m bob
$ grep ^robert: /etc/passwd
robert:x:2002:2002:Bob Builder:/home/robert:/bin/sh
```

### Setting passwords
- `sudo passwd alice` sets another user's password (prompts twice)
- Plain `passwd` changes your own and asks for the current one first
  - Naming another account as a regular user: `passwd: You may not view or modify password information for alice.`
- Scripted: `echo 'Rh10-exam!' | sudo passwd --stdin alice`, silent on success
  - On RHEL 10, `/usr/bin/passwd` belongs to shadow-utils; the separate `passwd` package is gone
- `passwd -S alice` prints one status line: `P` usable password, `L` locked, `NP` none

### Password aging with chage
- ==Password aging== limits how long a password stays valid; set it per user with ==chage==

| Option | Field | Meaning |
|---|---|---|
| `-m 7` | min | days before another change is allowed |
| `-M 90` | max | days until the password expires |
| `-W 14` | warn | days of warning before that |
| `-I 5` | inactive | days after expiry before lockout |
| `-E date` | expire | account expiration date; `-1` clears |
| `-d 0` | last change | force a new password at next login |

:::figure wide 9.1-password-aging.svg | The password clock starts at the last change. The account expiration date is a separate, fixed date that ends all logins.

:::wide
```console label="Terminal"
$ sudo chage -M 90 -m 7 -W 14 alice
$ sudo chage -E 2026-12-31 alice
$ sudo chage -l alice
Last password change					: Oct 21, 2026
Password expires					: Jan 19, 2027
Password inactive					: never
Account expires						: Dec 31, 2026
Minimum number of days between password change		: 7
Maximum number of days between password change		: 90
Number of days of warning before password expires	: 14
$ sudo getent shadow alice | cut -d: -f3-
20747:7:90:14::20818:
```
:::

- 20747 is 21 October 2026 (the last change); 20818 is 31 December 2026 (`-E`)
- ==chage -d 0== sets the last change to day zero, so the next login demands a new password
  - `passwd -e alice` does the same
  - `chage alice` with no options prompts for every field

```console label="Terminal"
$ sudo chage -d 0 alice
$ sudo getent shadow alice | cut -d: -f3-
0:7:90:14::20818:
```

- Defaults for new accounts: `PASS_MAX_DAYS`, `PASS_MIN_DAYS`, `PASS_WARN_AGE` in `/etc/login.defs`
  - Copied in when the account is created; existing accounts keep their values
  - In `passwd -S`, the fifth field is the maximum age

```console label="After editing /etc/login.defs"
$ grep ^PASS_MAX_DAYS /etc/login.defs
PASS_MAX_DAYS	90
$ sudo useradd bob
$ sudo passwd -S bob; sudo passwd -S student
bob L 2026-10-21 0 90 7 -1
student L 2026-10-21 0 99999 7 -1
```

### Locking and deleting accounts
- ==usermod -L== (or `passwd -l`) puts `!` in front of the hash; `usermod -U` removes it
  - Password logins fail, but SSH keys still work (10.3)
  - `chage -E 0` expires the account and stops every login method
- A ==nologin shell== keeps the account for services and file ownership but refuses interactive logins

```console label="Terminal"
$ sudo usermod -L robert; sudo passwd -S robert
robert L 2026-10-21 0 90 7 -1
$ sudo usermod -U robert
$ sudo usermod -s /sbin/nologin alice
$ sudo su - alice
This account is currently not available.
```

- ==userdel== removes the account lines only
  - The home directory stays, owned by a bare UID that the next new user could inherit
  - `userdel -r` deletes the home directory and mail spool too

```console label="Terminal"
$ sudo userdel robert; ls -ld /home/robert
drwx------ 2 2002 bob 4096 Oct 21 19:52 /home/robert
```

:::exam
- Tasks give exact values: "UID 2001", "no interactive shell", "the password must be changed every 90 days". Check each one with `id`, `grep user /etc/passwd`, and `chage -l` before moving on.
- "All new users" points to `/etc/login.defs`; "user alice" points to `chage`. Editing `login.defs` does not change accounts that already exist.
- "Force a password change at first login" is `chage -d 0`. "The account expires on" is `chage -E`, a different field.
:::
