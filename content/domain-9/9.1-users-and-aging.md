### Accounts and the files behind them
- Every local account is a line in ==/etc/passwd== plus a line in ==/etc/shadow==
  - `/etc/passwd`: readable by everyone, seven colon-separated fields
  - `/etc/shadow`: root only, the password hash and all aging values
- Accounts are plain files, so they survive a reboot with no extra step
  - Edit with the tools below, never with `vi /etc/passwd`
  - `vipw` and `vipw -s` lock the file if a hand edit is truly needed
- UID ranges come from `/etc/login.defs`
  - 0 is root; 201 to 999 are ==system accounts== for services; regular users start at `UID_MIN` 1000

:::wide
| File | Fields, in order | Example |
|---|---|---|
| `/etc/passwd` | name : `x` : UID : GID (primary group) : comment (GECOS) : home : shell | `alice:x:2001:2001:Alice Admin:/home/alice:/bin/bash` |
| `/etc/shadow` | name : hash : last change : min : max : warn : inactive : expire : reserved | `alice:$y$j9T...:20747:7:90:14::20818:` |
:::

- Shadow dates count days since 1 January 1970
  - 20747 is 21 October 2026; an empty field means no limit
- The hash prefix shows the algorithm: `$y$` is ==yescrypt==, the RHEL 10 default (`ENCRYPT_METHOD YESCRYPT`)
  - `!` or `!!` in front of the hash means locked or never set

### Creating users
- `useradd` fills in anything you leave out from two files
  - ==/etc/login.defs==: UID and GID ranges, `HOME_MODE 0700`, `UMASK`, password aging defaults, hash method
  - ==/etc/default/useradd==: home base, shell, skeleton directory; view it with `useradd -D`

```console label="Terminal"
$ sudo useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
```

| Option | Sets |
|---|---|
| `-u 2001` | UID |
| `-g devops` | primary group (must exist) |
| `-G wheel,web` | supplementary groups |
| `-c "Alice Admin"` | comment (full name) |
| `-d /srv/alice` | home directory path |
| `-s /sbin/nologin` | login shell |
| `-e 2026-12-31` | account expiration date |
| `-r` | system account, UID under 1000 |
| `-M` / `-m` | skip / force the home directory |

- With no `-g`, RHEL creates a ==user private group== named after the user, same number
- The home directory is copied from `/etc/skel` and set to mode `0700`

```console label="Terminal"
$ sudo useradd -u 2001 -c "Alice Admin" alice
$ id alice; grep alice /etc/passwd
uid=2001(alice) gid=2001(alice) groups=2001(alice)
alice:x:2001:2001:Alice Admin:/home/alice:/bin/bash
$ sudo useradd -r -s /sbin/nologin -M webapp
$ id webapp
uid=998(webapp) gid=998(webapp) groups=998(webapp)
```

### Modifying and deleting users
- ==usermod== takes the same letters as `useradd` for most fields
  - `-c`, `-s`, `-u`, `-g`, `-G`, `-e` change one field each
  - `-d /new/home -m` changes the home path and moves the files
  - `-l newname` renames the login; the private group keeps its old name (fix it with `groupmod -n`)
- Changes take effect at the user's next login; running sessions keep the old values

```console label="Terminal"
$ sudo usermod -c "Bob Builder" -s /bin/sh bob
$ sudo usermod -l robert -d /home/robert -m bob
$ grep ^robert: /etc/passwd
robert:x:2002:2002:Bob Builder:/home/robert:/bin/sh
```

- ==userdel== removes the account lines only
  - The home directory stays, owned by a bare UID that a future user could inherit
  - `userdel -r` also deletes the home directory and mail spool

```console label="Terminal"
$ sudo userdel robert; ls -ld /home/robert
drwx------ 2 2002 bob 4096 Oct 21 17:12 /home/robert
```

### Setting passwords
- `sudo passwd alice` sets another user's password, prompting twice
- A regular user runs plain `passwd` and must give the current password first
  - Naming another account fails: `passwd: You may not view or modify password information for alice.`
- Scripted: `echo 'Rh10-exam!' | sudo passwd --stdin alice`
  - On RHEL 10 `passwd` comes from shadow-utils (the separate `passwd` package is gone) and prints nothing on success
- `passwd -S` shows status: `P` usable password, `L` locked, `NP` none

```console label="Terminal"
$ sudo passwd -S alice
alice P 2026-10-21 0 99999 7 -1
```

### Password aging with chage
- ==Password aging== limits how long a password stays valid; set per user with ==chage==

| Option | Field | Meaning |
|---|---|---|
| `-m 7` | min | days before the user may change it again |
| `-M 90` | max | days until the password expires |
| `-W 14` | warn | days of warning before expiry |
| `-I 5` | inactive | days after expiry before lockout |
| `-E date` | expire | account expiration date (`-1` clears) |
| `-d 0` | last change | force a change at next login |

:::figure wide 9.1-password-aging.svg | The password clock starts at the last change. The account expiration date is a separate, fixed date that ends all logins.

```console label="Terminal"
$ sudo chage -M 90 -m 7 -W 14 alice
$ sudo chage -E 2026-12-31 alice
```

:::wide
```console label="Terminal"
$ sudo chage -l alice
Last password change					: Oct 21, 2026
Password expires					: Jan 19, 2027
Password inactive					: never
Account expires						: Dec 31, 2026
Minimum number of days between password change		: 7
Maximum number of days between password change		: 90
Number of days of warning before password expires	: 14
```
:::

- ==chage -d 0== sets the last change to day zero, so the next login demands a new password
  - `passwd -e alice` does the same thing
- `chage` with no options walks through every field interactively
- `passwd -n`, `-x`, `-w`, `-i` set min, max, warn, inactive too

```console label="Terminal"
$ sudo chage -d 0 alice
$ sudo chage -l alice | head -2
Last password change					: password must be changed
Password expires					: password must be changed
```

- Defaults for new accounts: `PASS_MAX_DAYS`, `PASS_MIN_DAYS`, `PASS_WARN_AGE` in `/etc/login.defs`
  - They are copied in at creation time only; existing accounts keep their values

```console label="Terminal"
$ sudo sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS\t90/' /etc/login.defs
$ sudo useradd bob
$ sudo chage -l bob | grep Maximum
Maximum number of days between password change		: 90
$ sudo chage -l student | grep Maximum
Maximum number of days between password change		: 99999
```

### Locking accounts and nologin shells
- ==usermod -L== (or `passwd -l`) puts `!` in front of the hash; `-U` (or `passwd -u`) removes it
  - Password logins fail, but SSH keys still work; expire the account too to stop everything
- `usermod -e 1` or `chage -E 0` expires the account outright
- A ==nologin shell== keeps the account for file ownership or services but refuses interactive logins
  - `-s /sbin/nologin` at creation or with `usermod`

```console label="Terminal"
$ sudo usermod -L robert; sudo passwd -S robert
robert L 2026-10-21 0 90 7 -1
$ sudo usermod -U robert
$ sudo usermod -s /sbin/nologin alice
$ sudo su - alice
This account is currently not available.
```

:::exam
- Tasks give exact values: "UID 2001", "a supplementary member of sysadmin", "no interactive shell", "password expires every 90 days". Check each with `id` and `chage -l` before moving on.
- "All new users must change their password every 90 days" means `/etc/login.defs`; "user alice must" means `chage`. Some tasks want both.
- "Force a password change at first login" is `chage -d 0`. "Expire the account" is `chage -E`, a different field.
:::
