### Packages, repositories, and DNF
- An ==RPM package== is one file: software, metadata, scripts, and a signature
  - File name: `name-version-release.arch.rpm`
  - `tree-2.1.0-8.el10.x86_64.rpm`: name `tree`, version `2.1.0`, release `8.el10`
- A ==repository== is a directory of RPMs plus a `repodata/` index
  - Reached over `http://`, `https://`, or a local `file://` path
- ==DNF== reads the index, resolves dependencies, then hands the RPMs to `rpm`
  - `rpm` alone installs one file and stops at a missing dependency
- RHEL 10 ships ==DNF 4==: `dnf --version` prints `4.20.0`
  - DNF 5 is a Fedora tool; every command here is DNF 4 syntax
  - `yum` is a symlink to `dnf`; `dnf module` is deprecated

:::figure wide 2.1-dnf-install.svg | dnf install reads the .repo files, fetches each repository's index, resolves dependencies, checks signatures, and lets rpm write the files and the package database. rpm -q queries only that database.

### Configure access to RPM repositories
- ==createrepo_c== turns a directory of RPMs into a repository
  - It writes `repodata/`; `-g comps.xml` adds package groups

```console label="Terminal"
$ cd /srv/labrepo
$ sudo createrepo_c -g /srv/comps.xml .
Directory walk started
Directory walk done - 2 packages
```

- Each ==.repo file== in `/etc/yum.repos.d/` defines repositories
  - One `[repo-id]` section per repository; a file can hold several
  - The ==baseurl== says where the `repodata/` lives
  - Global defaults, including `gpgcheck=1`, sit in `/etc/dnf/dnf.conf`
  - Read on every `dnf` run, so a saved file persists across reboots

:::wide
| Key | Meaning |
|---|---|
| `[labrepo]` | Repo ID: unique, no spaces, used with `--enablerepo` and `--disable` |
| `name=` | Human-readable label shown by `dnf repolist` |
| `baseurl=` | Where `repodata/` lives: `http://...`, `https://...`, `file:///path` |
| `enabled=` | `1` to use the repository, `0` to keep it defined but ignored |
| `gpgcheck=` | `1` to verify package signatures (the default from `dnf.conf`) |
| `gpgkey=` | URL or `file://` path of the public key that signed the packages |
:::

```console label="Terminal"
$ cat /etc/yum.repos.d/labrepo.repo
[labrepo]
name=Lab
baseurl=file:///srv/labrepo
enabled=1
gpgcheck=1
gpgkey=file:///srv/labrepo/RPM-GPG-KEY
$ dnf repolist
labrepo                                   Lab
```

- `dnf repolist --all` adds disabled ones; `dnf repoinfo ID` shows the baseurl and package count
- `/etc/pki/rpm-gpg/` holds the distribution's keys on RHEL (`RPM-GPG-KEY-redhat-release`)

### dnf config-manager --add-repo
- ==dnf config-manager --add-repo URL== writes the `.repo` file for you
  - Repo ID and file name come from the URL: `/srv/tools` becomes `srv_tools`
  - The file gets `name`, `baseurl`, and `enabled=1`, and no `gpgcheck` line
- No `gpgcheck` line means the global `gpgcheck=1` applies
  - Unsigned packages then fail with ==GPG check FAILED==
  - Signed ones need a `gpgkey` line (or `rpm --import KEY`)

```console label="Terminal"
$ sudo dnf config-manager \
    --add-repo file:///srv/tools
Adding repo from: file:///srv/tools
$ cat /etc/yum.repos.d/srv_tools.repo
[srv_tools]
baseurl=file:///srv/tools
enabled=1
$ sudo dnf -y install labtools 2>&1 | tail -2
Package labtools-1.0-1.noarch.rpm is not signed
Error: GPG check FAILED
$ sudo dnf config-manager --save \
    --setopt=srv_tools.gpgcheck=0
$ tail -1 /etc/yum.repos.d/srv_tools.repo
gpgcheck=0
$ sudo dnf -y -q install labtools && labcheck
lab ready
```

- Fix it the way the task asks: add `gpgkey=URL`, or set `gpgcheck=0` when told the packages are unsigned
  - Editing the file with `vim` works just as well as `--setopt`
- `dnf config-manager --disable srv_tools` sets `enabled=0`; `--enable` turns it back on
### Install and remove RPM software packages
- ==dnf search==: match names and summaries (`dnf search WORD`)
- ==dnf provides==: which package ships a file, installed or not
  - Globs work: `dnf provides '*/labcheck'`
  - `@System` in the output means already installed
- `dnf info PKG`: version, size, repository, description
- `dnf install PKG` and `dnf remove PKG`; `-y` answers yes
  - `remove` also drops dependencies nothing else needs

```console label="Terminal"
$ dnf -q search shell
bash.x86_64 : The GNU Bourne Again shell
zsh.x86_64 : Powerful interactive shell
$ dnf -q provides '*/labcheck'
labtools-1.0-1.noarch : Lab helper scripts
Repo        : @System
labtools-1.0-1.noarch : Lab helper scripts
Repo        : srv_tools
$ sudo dnf -y -q install tree
Installed:
  tree-2.1.0-8.el10.x86_64
$ sudo dnf -y -q remove tree
```

### Groups and history
- A ==package group== installs a named set of packages
  - `dnf group list`, `dnf group info "NAME"`, `dnf group install "NAME"`
  - `dnf install @lab-shells` is the same thing by group ID
- ==dnf history== lists every transaction with an ID
  - `dnf history info last` (or an ID) shows what changed
  - `dnf history undo last` reverses one transaction

```console label="Terminal"
$ sudo dnf -y -q group install "Lab Shells"
$ sudo dnf history info last
Command Line   : -y -q group install Lab Shells
Packages Altered:
    Install tree-2.1.0-8.el10.x86_64 @labrepo
    Install zsh-5.9-15.el10.x86_64   @labrepo
    Install @lab-shells
$ sudo dnf -y -q history undo last
```

### Query the RPM database
- `rpm -q` reads the local ==RPM database==; it never contacts a repository
  - RHEL 10 keeps it in `/usr/lib/sysimage/rpm`; `/var/lib/rpm` is a symlink
- ==rpm -qf== maps a file back to its package
- Add `p` to query a package file instead: `rpm -qip`, `rpm -qlp`

| Command | Answers |
|---|---|
| `rpm -q tree` | Is it installed? Which version? |
| `rpm -qa` | Every installed package |
| `rpm -qi tree` | Description, version, signature |
| `rpm -ql tree` | Files the package installed |
| `rpm -qf /usr/bin/tree` | Which package owns a file? |
| `rpm -qc` / `rpm -qd` | Its config files / its docs |

```console label="Terminal"
$ rpm -q tree
tree-2.1.0-8.el10.x86_64
$ rpm -qf /etc/dnf/dnf.conf
dnf-data-4.20.0-22.el10_2.alma.1.noarch
$ rpm -q zsh
package zsh is not installed
```
