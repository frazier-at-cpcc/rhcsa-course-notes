### Flatpak on RHEL 10
- The objective: ==configure access to Flatpak repositories== and install and remove Flatpak software packages
- ==Flatpak== is a second packaging system that sits beside RPM
  - An ==app== (`org.gnome.Calculator`) runs on a shared ==runtime== (`org.gnome.Platform`), a base set of libraries
  - Each app runs in a sandbox that sees the runtime's libraries in place of the host's `/usr`
  - `dnf` never sees Flatpak apps, and `rpm -qa` does not list them
- RHEL 10 leans on it for desktop software
  - A Server with GUI install gets Firefox as a Flatpak
  - The `flatpak` tool itself is an RPM: `sudo dnf install flatpak` on a minimal system
- A ==remote== is a Flatpak repository, the counterpart of a dnf repo

:::figure wide 2.2-flatpak.svg | Each installation keeps its own list of remotes. A remote added with sudo feeds the system installation; a --user install needs a remote added with --user.

### Configure access to Flatpak repositories
- ==flatpak remote-add== NAME LOCATION defines a remote
  - LOCATION is usually a ==.flatpakrepo== file: it carries the URL, title, and signing key
  - `--if-not-exists` makes a rerun harmless, handy in a script
  - Run it with `sudo` for the system installation
- `flatpak remotes` lists remotes and the installation each belongs to
- System remotes are a section in ==/var/lib/flatpak/repo/config==
  - A plain file on disk: the remote survives a reboot with nothing to enable

```console label="Terminal"
$ sudo flatpak remote-add --if-not-exists \
  flathub \
https://dl.flathub.org/repo/flathub.flatpakrepo
$ flatpak remotes
flathub	system
$ grep -A3 'remote "flathub"' \
  /var/lib/flatpak/repo/config
[remote "flathub"]
url=https://dl.flathub.org/repo/
xa.title=Flathub
gpg-verify=true
```

- Look before you install: `flatpak remote-ls REMOTE --app` lists every app; `flatpak search WORD` matches names and descriptions
- A brand-new remote has no ==appstream== data yet, so `search` comes back empty
  - `sudo flatpak update --appstream` downloads it; `remote-ls` works either way

```console label="Terminal"
$ flatpak remote-ls flathub --app \
  --columns=application | grep -E \
  '^org\.gnome\.(Calculator|TextEditor)$'
org.gnome.Calculator
org.gnome.TextEditor
$ flatpak search calculator
No matches found
$ sudo flatpak update --appstream
Updating appstream data for remote flathub
```

- `flatpak remote-modify --disable NAME` keeps a remote but ignores it; `--enable` restores it
- ==flatpak remote-delete== NAME removes access to the repository

### Install and remove Flatpak software packages
- ==flatpak install== REMOTE ID pulls the app plus any runtime it needs
  - `-y --noninteractive` answers every prompt (scripts, the exam)
  - Related refs come along: locale data, GL drivers, codecs
- `flatpak list` shows apps and runtimes; `--app` or `--runtime` narrows it
- `flatpak info ID` shows the version and the remote it came from

```console label="Terminal"
$ sudo flatpak install -y --noninteractive \
  flathub org.gnome.Calculator 2>&1 | tail -4
Installing runtime/org.gnome.Platform/x86_64/51
Installing app/org.gnome.Calculator/x86_64/stable
```

- ==flatpak run== ID starts the app in its sandbox
  - `--command=sh` opens a shell inside it instead
  - Inside, `/etc/os-release` belongs to the runtime

```console label="Terminal"
$ flatpak run --command=sh \
  org.gnome.Calculator \
  -c 'echo running inside the sandbox;
  cat /etc/os-release | head -1'
running inside the sandbox
NAME="GNOME"
```

- `sudo flatpak update` updates every app and runtime from its remote
- ==flatpak uninstall== ID removes the app and its own extensions
  - The runtime stays behind for other apps
  - `flatpak uninstall --unused` sweeps up runtimes nothing needs
- Below, `flatpak list` and `flatpak remotes` print nothing: no refs and no remotes are left

```console label="Terminal"
$ sudo flatpak uninstall -y --noninteractive \
  org.gnome.Calculator 2>&1 | tail -2
Uninstalling app/org.gnome.Calculator/x86_64/stable
Uninstalling runtime/org.gnome.Calculator.Locale/x86_64/stable
$ sudo flatpak uninstall -y --noninteractive \
  --unused 2>&1 | tail -2
Uninstalling runtime/org.gnome.Platform.Locale/x86_64/51
$ flatpak list
$ sudo flatpak remote-delete flathub; \
  flatpak remotes
```

### System and user installations
- The ==system installation== is the default (`--system`)
  - Lives in `/var/lib/flatpak`; every account can run its apps
  - Changing it takes `sudo` (or a polkit prompt on a desktop)
- A ==user installation== belongs to one account (`--user`)
  - Lives in `~/.local/share/flatpak`; no root needed
  - Other accounts, root included, never see it
- Remotes are per installation
  - A system remote is invisible to `--user` commands

```console label="Terminal (system flathub only)"
$ flatpak install --user -y --noninteractive \
  flathub org.gnome.Calculator 2>&1 | tail -2
error: No remote refs found for ‘flathub’
```

- Add the remote with `--user` first, then install

```console label="Terminal"
$ flatpak remote-add --user --if-not-exists \
  flathub \
https://dl.flathub.org/repo/flathub.flatpakrepo
$ flatpak remotes
flathub	system
flathub	user
$ flatpak install --user -y --noninteractive \
  flathub org.gtk.Gtk3theme.Adwaita-dark \
  2>&1 | tail -1
Installing runtime/org.gtk.Gtk3theme.Adwaita-dark/x86_64/3.22
$ flatpak list \
  --columns=application,branch,installation
org.gtk.Gtk3theme.Adwaita-dark	3.22	user
```

### Red Hat's Flatpak remote
- ==Flathub== is the public community catalog; Red Hat publishes RHEL-built apps and runtimes as a remote named ==rhel==
  - Defined by `https://flatpaks.redhat.io/rhel.flatpakrepo`
  - Served as container images: `flatpak remotes` shows the `oci` option

```console label="Terminal"
$ sudo flatpak remote-add --if-not-exists \
  rhel \
  https://flatpaks.redhat.io/rhel.flatpakrepo
$ flatpak remotes
flathub	system
rhel	system,oci,no-gpg-verify
$ sudo flatpak remote-ls rhel --app \
  --columns=application
org.mozilla.Thunderbird
org.mozilla.firefox
```

- Anyone can list it; installing from it needs a Red Hat login
  1. `podman login flatpaks.registry.redhat.io` with a Customer Portal account or a registry service account token
  2. That login lasts until you log out; copy `$XDG_RUNTIME_DIR/containers/auth.json` to `/etc/flatpak/oci-auth.json` to keep it for the system installation
  3. `sudo flatpak install rhel org.mozilla.firefox`

:::exam
- "Configure the Flatpak repository at URL and install APP so that all users can use it" means a system remote and a system install, both with `sudo`. A `--user` install passes your own check and fails the grader's check run as another account.
- Remotes and apps are files under `/var/lib/flatpak`, so they persist across reboots with no service to enable. Confirm with `flatpak remotes` and `flatpak list --app`.
- Keep the two removals apart: `flatpak uninstall` removes software; `flatpak remote-delete` removes access to the repository.
:::
