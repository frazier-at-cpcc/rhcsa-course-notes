### GRUB 2 and BLS entries
- The objective: ==modify the system bootloader==
- RHEL 10 boots with ==GRUB 2==; three files decide what it does, and each has its own tool

:::figure wide 7.5-grub-config.svg | Each tool owns one file. grubby edits the per-kernel BLS entries and the saved default; grub2-mkconfig rebuilds only the menu script.

- Menu items come from ==Boot Loader Specification== (BLS) snippets, one file per kernel
  - Location: ==/boot/loader/entries/==
  - File name: the machine ID from `/etc/machine-id`, a dash, the kernel version, `.conf`
  - Keys inside: `title`, `version`, `linux` (the kernel), `initrd`, and ==options== (the kernel arguments)
  - Installing a kernel package adds an entry; `grub.cfg` itself lists no kernels
- The entries directory is readable by root only
  - As a regular user, `ls /boot/loader/entries/` fails with `Permission denied`
  - In `sudo cat .../$(ls ...)` the `$( )` still runs as you; use a root shell or `grubby`

### What GRUB will boot
- ==grubby== reads and edits BLS entries; it needs root
  - `--default-kernel` and `--default-index`: the entry booted when no one touches the menu
  - `--info=ALL` or `--info=DEFAULT`: one block per entry
- ==/proc/cmdline== holds the arguments the running kernel actually received

```console label="Terminal"
$ sudo grubby --default-kernel
/boot/vmlinuz-6.12.0-211.67.1.el10_2.x86_64
$ sudo grubby --default-index
0
```

:::wide
```console label="Terminal"
$ sudo grubby --info=ALL | grep -E '^(index|kernel|args|title)'
index=0
kernel="/boot/vmlinuz-6.12.0-211.67.1.el10_2.x86_64"
args="console=ttyS0,115200n8 no_timer_check crashkernel=2G-64G:256M,64G-:512M"
title="Rocky Linux (6.12.0-211.67.1.el10_2.x86_64) 10.2 (Red Quartz)"
index=1
kernel="/boot/vmlinuz-0-rescue-e1efc03b2eb54461826a66afe9ac7122"
$ cat /proc/cmdline
BOOT_IMAGE=(hd0,gpt3)/vmlinuz-6.12.0-211.67.1.el10_2.x86_64 console=ttyS0,115200n8 no_timer_check root=UUID=01582c00-2b49-4e9b-86ee-75f418a4b720 crashkernel=2G-64G:256M,64G-:512M
```
:::

- ==grubby --set-default /boot/vmlinuz-VERSION== changes the default kernel
  - It stores the entry as `saved_entry` in `/boot/grub2/grubenv` (`sudo grub2-editenv list` prints it), so it persists
  - `grub2-reboot ENTRY` picks an entry for the next boot only

### Kernel arguments that persist
- ==grubby --update-kernel=ALL --args='...'== appends arguments to the `options` line of every entry
  - `--remove-args='...'` takes them out again
  - `--update-kernel=DEFAULT` or a kernel path limits the change to one entry
- grubby writes the ==BLS entries== directly: no `grub2-mkconfig` afterward
- A kernel installed later inherits the arguments of the one already there
- Arguments typed at the GRUB menu with `e` last one boot only (objective 4.1)

:::wide
```console label="Terminal"
$ sudo grubby --update-kernel=ALL --args='audit=1 audit_backlog_limit=8192'
$ sudo grubby --info=DEFAULT | grep args
args="console=ttyS0,115200n8 no_timer_check crashkernel=2G-64G:256M,64G-:512M audit=1 audit_backlog_limit=8192"
```
:::

### Menu settings in /etc/default/grub
- ==/etc/default/grub== holds settings for the whole menu
- Changes there do nothing until you rebuild the menu script with ==grub2-mkconfig==

:::wide
| Key | Controls |
|---|---|
| `GRUB_TIMEOUT` | seconds the menu waits before booting the default |
| `GRUB_DEFAULT=saved` | boot the entry named by `saved_entry` (what `grubby --set-default` writes) |
| `GRUB_CMDLINE_LINUX` | arguments for every entry, applied with `--update-bls-cmdline` (`_DEFAULT` on cloud images) |
| `GRUB_ENABLE_BLSCFG=true` | build the menu from `/boot/loader/entries/` |
:::

:::wide
```console label="Terminal"
$ cat /etc/default/grub
GRUB_DEFAULT=saved
GRUB_CMDLINE_LINUX_DEFAULT="console=ttyS0,115200n8 no_timer_check crashkernel=1G-4G:192M,4G-64G:256M,64G-:512M"
GRUB_ENABLE_BLSCFG=true
GRUB_TIMEOUT=1
$ sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=10/' /etc/default/grub; grep TIMEOUT /etc/default/grub
GRUB_TIMEOUT=10
$ sudo grub2-mkconfig -o /boot/grub2/grub.cfg 2>&1 | tail -3
Generating grub configuration file ...
Adding boot menu entry for UEFI Firmware Settings ...
done
```
:::

- The output path is ==/boot/grub2/grub.cfg== on BIOS and UEFI alike
  - The UEFI `grub.cfg` under `/boot/efi/EFI/` is a stub that loads it; never overwrite the stub
- Plain `grub2-mkconfig` leaves the BLS `options` lines alone
  - To push a changed `GRUB_CMDLINE_LINUX` into every entry, add ==--update-bls-cmdline==

### Proving it after a reboot
- `/proc/cmdline` after the reboot is the proof: the `audit` arguments added with grubby reached the kernel. `--remove-args` undoes them.

:::wide
```console label="Terminal (after reboot)"
$ cat /proc/cmdline
BOOT_IMAGE=(hd0,gpt3)/vmlinuz-6.12.0-211.67.1.el10_2.x86_64 console=ttyS0,115200n8 no_timer_check root=UUID=01582c00-2b49-4e9b-86ee-75f418a4b720 crashkernel=2G-64G:256M,64G-:512M audit=1 audit_backlog_limit=8192
$ sudo grubby --update-kernel=ALL --remove-args='audit=1 audit_backlog_limit=8192'
$ sudo grubby --info=DEFAULT | grep args
args="console=ttyS0,115200n8 no_timer_check crashkernel=2G-64G:256M,64G-:512M"
```
:::

:::exam
- "Add the kernel argument X so that it persists across reboots" is `grubby --update-kernel=ALL --args='X'`; check `/proc/cmdline` after the reboot.
- A menu timeout task is `/etc/default/grub` plus `grub2-mkconfig -o /boot/grub2/grub.cfg`; hand edits to `grub.cfg` are lost at the next rebuild.
- On RHEL 10, `grub2-mkconfig` writes to `/boot/grub2/grub.cfg` on UEFI machines too; the `/boot/efi/EFI/` path is a RHEL 7 and 8 habit.
:::

:::try
On servera, configure the boot loader so that every kernel boots with the argument `audit=1` and the GRUB menu waits 10 seconds, with both changes persisting across reboots. Reboot and confirm the argument appears in `/proc/cmdline`, then remove it.
:::
