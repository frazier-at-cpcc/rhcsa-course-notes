### Three places packages come from
- The objective: ==install and update software packages from Red Hat Content Delivery Network, a remote repository, or from the local file system==
- `dnf repolist` shows every enabled repository; the repo ID column is what other commands take

| Source | How dnf reaches it |
|---|---|
| ==Red Hat CDN== | registration writes `redhat.repo` |
| Remote repository | a `.repo` file with an `https://` baseurl |
| Local repository | a `.repo` file with a `file://` baseurl |
| Single RPM file | `dnf install /path/file.rpm` |

- The lab machine for these captures ran Rocky Linux 10.2, so its repositories come from Rocky mirrors and it has no `subscription-manager`

:::wide
```console label="Terminal"
$ dnf repolist
repo id                                           repo name
appstream                                         Rocky Linux 10 - AppStream
baseos                                            Rocky Linux 10 - BaseOS
extras                                            Rocky Linux 10 - Extras
repo.almalinux.org_almalinux_10_extras_x86_64_os_ created by dnf config-manager from https://repo.almalinux.org/almalinux/10/extras/x86_64/os/
```
:::

### Registering with the Red Hat CDN
- A subscribed RHEL 10 system gets BaseOS and AppStream from the ==Content Delivery Network== (`cdn.redhat.com`)
- Registration ties the machine to a Red Hat organization; under ==Simple Content Access== there is no "attach a subscription" step
- Two front ends: ==subscription-manager== (registration and repositories) and ==rhc== (registration plus Red Hat Lightspeed / Insights)

:::wide
| Task | Command (as root) |
|---|---|
| Register with an account | `subscription-manager register --username=USER --password=PASS` |
| Register with an activation key | `subscription-manager register --activationkey=KEY --org=ORG_ID` |
| Register with rhc | `rhc connect --activation-key=KEY --organization=ORG_ID` |
| Check registration | `subscription-manager status` or `rhc status` |
| Repositories turned on | `subscription-manager repos --list-enabled` |
| Turn one on | `subscription-manager repos --enable=codeready-builder-for-rhel-10-x86_64-rpms` |
| Unregister | `subscription-manager unregister` or `rhc disconnect` |
:::

- Registered repo IDs look like `rhel-10-for-x86_64-baseos-rpms` and `rhel-10-for-x86_64-appstream-rpms`
- subscription-manager owns ==/etc/yum.repos.d/redhat.repo==
  - Change it with `subscription-manager repos`, never by hand: it is regenerated
- Exam machines are not registered. Their content comes from a classroom URL, which makes it a remote repository (below)

### Updates
- ==dnf upgrade== updates every package that has a newer version; `dnf upgrade PKG` updates one
  - `dnf check-update` lists what would change and exits 100 when updates exist
  - `--assumeno` runs the whole calculation and stops at the prompt
  - `dnf upgrade --security` applies only security errata (Red Hat repositories carry them)
- A new ==kernel== is installed beside the old ones; reboot to run it
- Every install, update, and removal lands in ==dnf history==, so `dnf history undo ID` can reverse it (objective 2.1)
- The lab machine was already current, so the upgrade had nothing to do

```console label="Terminal"
$ sudo dnf upgrade --assumeno 2>&1 | tail -4
Dependencies resolved.
Nothing to do.
Complete!
```

### Install a package from the local file system
- Give `dnf install` a path to an ==.rpm file== instead of a name
  - dnf still pulls any dependencies from the enabled repositories
  - `rpm -ivh file.rpm` installs only that file and stops at a missing dependency
- ==rpm -qip FILE== reads the package's header before you install it
- `dnf download PKG` saves an RPM from a repository into the current directory

:::wide
```console label="Terminal"
$ cd /tmp && dnf download tree 2>&1 | tail -1; ls /tmp/tree-*.rpm
tree-2.1.0-8.el10.x86_64.rpm                    142 kB/s |  56 kB     00:00
/tmp/tree-2.1.0-8.el10.x86_64.rpm
$ rpm -qip /tmp/tree-*.rpm | head -6
Name        : tree
Version     : 2.1.0
Release     : 8.el10
Architecture: x86_64
Install Date: (not installed)
$ sudo dnf install -y /tmp/tree-*.rpm 2>&1 | tail -3
  tree-2.1.0-8.el10.x86_64

Complete!
$ rpm -q tree
tree-2.1.0-8.el10.x86_64
```
:::

### A repository on the local file system
- A pile of RPM files is not yet a repository; dnf needs the ==repodata/== index
  1. Copy the RPMs into one directory (`dnf download`, a share, or a DVD)
  2. Run ==createrepo_c DIR== to write `repodata/`
  3. Add a `.repo` file whose ==baseurl== is `file://` plus the absolute path (three slashes in total)
- Rerun `createrepo_c` whenever packages are added; dnf reads only the index

```console label="Terminal"
$ sudo createrepo_c /srv/localrepo | tail -1
Pool finished
```

```ini label="/etc/yum.repos.d/localrepo.repo"
[localrepo]
name=Local packages
baseurl=file:///srv/localrepo
enabled=1
gpgcheck=0
```

- The new ID appears in `dnf repolist` at once; `.repo` files are read on every run, so they persist across reboots
- A mounted RHEL DVD works the same way: it already has `repodata/` in its `BaseOS` and `AppStream` directories, so it needs two `[sections]` and no `createrepo_c`

### Add a remote repository by URL
- ==dnf config-manager --add-repo URL== writes a `.repo` file for you
  - The repo ID and file name come from the URL: the `https://` is dropped and each `/` becomes `_`
  - `name=` becomes "created by dnf config-manager from URL"
  - No `gpgcheck` line is written, so the global `gpgcheck=1` from `dnf.conf` applies (objective 2.1)
- Copy the generated ==repo ID== from `dnf repolist`: here it ends in `_`, and the same ID without it gave `Error: Unknown repo`

:::wide
```console label="Terminal"
$ sudo dnf config-manager --add-repo https://repo.almalinux.org/almalinux/10/extras/x86_64/os/ 2>&1 | tail -2
Adding repo from: https://repo.almalinux.org/almalinux/10/extras/x86_64/os/
$ ls /etc/yum.repos.d/
localrepo.repo
repo.almalinux.org_almalinux_10_extras_x86_64_os_.repo
rocky.repo
```
:::

- Signed packages need the key: `rpm --import URL`, or a `gpgkey=URL` line so dnf imports it on first install
- Writing the file by hand gives you the ID you want; the exam usually supplies two URLs, one for BaseOS and one for AppStream

:::exam
- "Configure your system to use http://content.example.com/rhel10/x86_64/dnf/BaseOS and .../AppStream as repositories" is two `.repo` sections (or two `--add-repo` runs). Finish with `dnf repolist` and a test install before any other package task.
- A task that hands you an `.rpm` file wants `dnf install ./file.rpm`, so dependencies resolve. `rpm -i` fails when anything is missing.
- On a subscribed system the CDN path is `subscription-manager register`, then `subscription-manager repos --enable=REPO_ID`, with no attach step.
:::
