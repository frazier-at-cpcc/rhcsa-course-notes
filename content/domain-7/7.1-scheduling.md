### Three ways to schedule
- The objective: ==schedule tasks using at, cron, and systemd timer units==
- Pick the tool by the wording of the task

| Tool | Runs | Catches up? |
|---|---|---|
| `at` | once | yes, when atd starts |
| cron | on a schedule | no |
| anacron | daily or slower | yes |
| systemd timer | on a schedule or event | with `Persistent=true` |

- All of them keep their jobs on disk, so scheduled work survives a reboot
  - `atd` and `crond` are enabled by default; a timer you write must be enabled

### One-time jobs with at
- ==`at TIME`== reads commands from standard input, or interactively until Ctrl+D
  - Times: `now + 1 minute`, `23:30`, `4pm tomorrow`
  - `at -f script.sh 02:00` reads them from a file
- Jobs run under `/bin/sh` with your environment and directory
- ==`atq`== lists pending jobs; ==`atrm N`== deletes job N; `at -c N` prints it
- Jobs wait in `/var/spool/at/` and survive a reboot

```console label="Terminal"
$ systemctl is-active atd
active
$ echo 'date >> /tmp/at-demo.txt' | at now + 1 minute
warning: commands will be executed using /bin/sh
job 3 at Wed Oct 21 18:59:00 2026
$ echo 'tar czf /tmp/etc-backup.tgz /etc 2>/dev/null' | at 23:30
warning: commands will be executed using /bin/sh
job 4 at Wed Oct 21 23:30:00 2026
$ atq
3	Wed Oct 21 18:59:00 2026 a student
4	Wed Oct 21 23:30:00 2026 a student
$ atrm $(atq | sort -n | tail -1 | cut -f1); atq
3	Wed Oct 21 18:59:00 2026 a student
$ sleep 75; cat /tmp/at-demo.txt
Wed Oct 21 06:59:00 PM UTC 2026
```

- The `atrm` line picks the newest job number; on the exam you would type `atrm 4`

### Recurring jobs with cron
- `crond` checks every minute for jobs that match the current time
- Each user has a ==crontab==: `crontab -e` edits it, `crontab -l` lists it, `crontab -r` removes it
  - Root manages anyone's: ==`crontab -u alice -e`==
  - `crontab FILE` installs a file you wrote as the whole crontab
- Five time fields, then the command

:::wide
| Field | Range | Example | Meaning of the example |
|---|---|---|---|
| minute | 0-59 | `*/5` | every 5 minutes |
| hour | 0-23 | `2` | 02:00 |
| day of month | 1-31 | `1,15` | the 1st and the 15th |
| month | 1-12 or `jan`-`dec` | `*` | every month |
| day of week | 0-7 (0 and 7 are Sunday) or `mon`-`sun` | `1-5` | Monday to Friday |
:::

- `*` any, `,` a list, `-` a range, `/` a step
- If both day fields are restricted, the job runs when ==either== matches
  - `0 3 1 * 1` runs on the 1st and on every Monday
- Shortcuts: `@reboot`, `@hourly`, `@daily`, `@weekly`, `@monthly`
- cron's `PATH` is short; use full paths, and escape `%` as `\%`

```text label="mycron"
*/5 * * * * df -h / >> /tmp/df.log
30 2 * * 1-5 /usr/local/bin/backup.sh
```

```console label="Terminal"
$ crontab mycron
$ crontab -l
*/5 * * * * df -h / >> /tmp/df.log
30 2 * * 1-5 /usr/local/bin/backup.sh
$ sudo ls -l /var/spool/cron/
total 4
-rw-------. 1 student student 73 Oct 21 18:59 student
$ crontab -r; crontab -l
Backup of student's previous crontab saved to /home/student/.cache/crontab/crontab.bak
no crontab for student
```

- RHEL 10's cronie saves a backup when you run `crontab -r`
- System jobs go in ==`/etc/cron.d/`== (or `/etc/crontab`)
  - These lines have a ==sixth field, the user==, between the time and the command

```text label="/etc/cron.d/weekly-cache"
0 1 * * 0 root /usr/bin/dnf -y -q makecache
```

- `/etc/cron.allow` and `/etc/cron.deny` control who may have a crontab

### anacron
- cron skips a job if the machine was off at that minute; ==anacron== runs it late instead
- `/etc/cron.hourly/0anacron` starts anacron once an hour
- `/etc/anacrontab` runs the scripts in `/etc/cron.daily`, `cron.weekly`, and `cron.monthly`
  - Columns: period in days, delay in minutes, job name, command
  - `START_HOURS_RANGE=3-22`: only between 03:00 and 22:00
  - `RANDOM_DELAY=45`: up to 45 more minutes, so machines do not all start together
  - The last run of each job is recorded in `/var/spool/anacron/`
- To add a daily job, drop an executable script into `/etc/cron.daily/`

```console label="Terminal"
$ grep -v '^#' /etc/anacrontab | grep -v '^$'
RANDOM_DELAY=45
START_HOURS_RANGE=3-22
1	5	cron.daily		nice run-parts /etc/cron.daily
7	25	cron.weekly		nice run-parts /etc/cron.weekly
@monthly 45	cron.monthly		nice run-parts /etc/cron.monthly
```

### systemd timer units
- Two units with the same name
  - The `.service` says ==what== runs (`Type=oneshot` for a task that finishes)
  - The `.timer` says ==when== and activates the service of the same name
- ==`OnCalendar=`== takes `DayOfWeek Year-Month-Day Hour:Minute:Second`
  - `*-*-* *:*:00` every minute; `Mon..Fri 02:30`; `daily`; `*:0/15` every 15 minutes
- ==`Persistent=true`== stores the last run on disk; if the machine was off when the timer was due, the job runs once at the next boot
- Monotonic timers count from an event: `OnBootSec=10min`, `OnUnitActiveSec=1h`

```ini label="/etc/systemd/system/disk-usage.service"
[Unit]
Description=Record disk usage

[Service]
Type=oneshot
ExecStart=/usr/bin/sh -c "df -h / >> /var/log/disk-usage.log"
```

```ini label="/etc/systemd/system/disk-usage.timer"
[Unit]
Description=Record disk usage every minute

[Timer]
OnCalendar=*-*-* *:*:00
Persistent=true

[Install]
WantedBy=timers.target
```

- Enable the ==timer==, not the service
  - `WantedBy=timers.target` is what brings it back after a reboot
- Each run is logged: `journalctl -u disk-usage.service`

:::wide
```console label="Terminal"
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now disk-usage.timer
$ systemctl list-timers disk-usage.timer --no-pager
NEXT                        LEFT LAST                           PASSED UNIT             ACTIVATES
Wed 2026-10-21 19:00:00 UTC  25s Wed 2026-10-21 18:59:34 UTC 149ms ago disk-usage.timer disk-usage.service
$ sleep 65; sudo tail -2 /var/log/disk-usage.log
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda4        19G  2.0G   17G  11% /
```
:::

- ==`systemd-analyze calendar`== checks an expression before you trust it
  - It prints the normalized form and the next time it fires

```console label="Terminal"
$ systemd-analyze calendar 'Mon..Fri 02:30' \
  'daily' '*:0/15' --iterations=2
  Original form: Mon..Fri 02:30
Normalized form: Mon..Fri *-*-* 02:30:00
    Next elapse: Thu 2026-10-22 02:30:00 UTC

  Original form: *:0/15
Normalized form: *-*-* *:00/15:00
    Next elapse: Wed 2026-10-21 19:15:00 UTC
```

- `daily` normalizes to `*-*-* 00:00:00`
- `systemctl list-timers --all` also shows the timers RHEL ships, such as `logrotate` and `fstrim`

:::exam
- "Run this command every day at 14:23 as natasha" is a user crontab: `crontab -u natasha -e` with `23 14 * * *`. Mind the field order: minute first.
- A file in `/etc/cron.d/` without the user field never runs. A timer that was started but not enabled is gone after the reboot.
- "Once, at a given time" is `at`. "Even if the machine was off" points to anacron or `Persistent=true`.
:::

:::try
Create a systemd timer named disk-usage.timer that runs `df -h /` and appends the output to /var/log/disk-usage.log every weekday at 02:30. Configure it so that it persists across reboots, then confirm the next run with `systemctl list-timers`.
:::
