### Clock status with timedatectl
- The objective: ==configure time service clients==
- RHEL 10 keeps time with ==chronyd== from the `chrony` package
  - Installed, enabled, and running on a default install
  - There is no `ntpd` package; chrony is the only NTP client
- ==timedatectl== with no arguments shows the whole picture

:::wide
```console label="Terminal"
$ timedatectl
               Local time: Wed 2026-10-21 19:02:04 UTC
           Universal time: Wed 2026-10-21 19:02:04 UTC
                 RTC time: Wed 2026-10-21 19:02:04
                Time zone: UTC (UTC, +0000)
System clock synchronized: yes
              NTP service: active
          RTC in local TZ: no
```
:::

- Read it line by line
  - `RTC time` is the hardware clock, kept in UTC
  - ==System clock synchronized: yes== means chronyd has locked onto a source
  - `NTP service: active` means chronyd is enabled and running

### Time zones
- Zone names are `Region/City` from `/usr/share/zoneinfo`
  - ==timedatectl list-timezones== lists them; filter with `grep`
- ==timedatectl set-timezone ZONE== changes it immediately and permanently
  - It points the ==/etc/localtime== symlink at the zone file, which is what persists
- The clock itself does not move: UTC stays the same, only the local display changes

```console label="Terminal"
$ timedatectl list-timezones | \
    grep -E 'America/(New_York|Chicago)'
America/Chicago
America/New_York
$ sudo timedatectl set-timezone America/New_York
$ timedatectl | grep 'Time zone'
                Time zone: America/New_York (EDT, -0400)
$ ls -l /etc/localtime
lrwxrwxrwx. 1 root root 38 Oct 21 15:02 /etc/localtime -> ../usr/share/zoneinfo/America/New_York
```

### Checking synchronization
- ==chronyc sources== lists every time source and its state
  - The first two characters: mode (`^` server) and state
  - `Reach` is an octal record of the last eight polls; `377` means all answered
  - `Last sample` is the measured offset and its error margin
- `chronyc sources -v` adds a legend above the table

| Mark | State |
|---|---|
| `^*` | the source the clock follows now |
| `^+` | good, combined with the `*` source |
| `^-` | reachable, left out of the calculation |
| `^?` | no reply yet, or unreachable |
| `^x` | disagrees with the others; ignored |

:::wide
```console label="Terminal"
$ chronyc sources
MS Name/IP address         Stratum Poll Reach LastRx Last sample
===============================================================================
^- ntp.maxhost.io                2   6    17    47  -1541us[-1226us] +/-   60ms
^+ 69.197.177.234                2   6    17    47  +1346us[+1661us] +/-   33ms
^? h135-134-111-122.mdsnwi.>     0   7     0     -     +0ns[   +0ns] +/-    0ns
^* mr3.itdivision.org            5   6    17    48   -401us[  -85us] +/-   14ms
```
:::

- ==chronyc tracking== reports on the chosen source
  - `Reference ID` names it; `System time` is how far the clock is off right now
- `timedatectl show -p NTPSynchronized` gives a yes or no for scripts

```console label="Terminal"
$ chronyc tracking | head -6
Reference ID    : AC106E03 (mr3.itdivision.org)
Stratum         : 6
Ref time (UTC)  : Wed Oct 21 19:02:12 2026
System time     : 0.000000046 seconds fast of NTP time
Last offset     : -0.000062556 seconds
$ timedatectl show -p NTPSynchronized
NTPSynchronized=yes
```

### Pointing the client at a server
- Sources come from ==/etc/chrony.conf==
  - ==server HOST iburst==: one specific NTP server
  - ==pool NAME iburst==: a DNS name that resolves to many servers; chronyd uses several of them
  - ==iburst== sends a quick burst of requests at startup, so the first sync takes seconds
- The default file has a single `pool` line pointing at the distribution's pool (a Red Hat system uses `2.rhel.pool.ntp.org`; this Rocky lab machine shows Rocky's)
- An exam task names a server: comment out the `pool` line, add a `server` line, restart

```console label="Terminal"
$ grep -E '^(pool|server)' /etc/chrony.conf
pool 2.rocky.pool.ntp.org iburst
$ sudo sed -i 's/^pool /#pool /' /etc/chrony.conf
$ echo 'server time.cloudflare.com iburst' | \
    sudo tee -a /etc/chrony.conf
server time.cloudflare.com iburst
$ grep -E '^(pool|server|#pool)' /etc/chrony.conf
#pool 2.rocky.pool.ntp.org iburst
server time.cloudflare.com iburst
$ sudo systemctl restart chronyd
```

- chronyd reads the file only at start: restart after every edit, then confirm with `chronyc sources` that the named server is listed and, after a few polls, marked `^*`
- Leave the other default lines alone: `driftfile`, `makestep` (lets chronyd jump a badly wrong clock at startup), `rtcsync`
- A client needs no firewall change: it only sends to UDP port 123 (an `allow` line is for NTP servers)

### NTP on and off, and persistence
- ==timedatectl set-ntp true== enables and starts chronyd; `false` stops and disables it
  - `timedatectl set-time` refuses to run while NTP is active
- What survives a reboot
  - The `server` line, because it is in `/etc/chrony.conf`
  - The time zone, because it is the `/etc/localtime` link
  - Synchronization, because chronyd is ==enabled== (`systemctl is-enabled chronyd`)

```console label="Terminal"
$ systemctl is-active chronyd; \
    systemctl is-enabled chronyd
active
enabled
$ sudo timedatectl set-ntp false; \
    timedatectl | grep NTP
              NTP service: inactive
$ sudo timedatectl set-ntp true; \
    timedatectl | grep NTP
              NTP service: active
```

:::exam
- "Configure servera as an NTP client of classroom.example.com" is a `server classroom.example.com iburst` line in `/etc/chrony.conf`, a chronyd restart, and chronyd enabled. A leftover `pool` line can keep the named server from getting the `*`.
- Time zone tasks are `timedatectl set-timezone`. Check the spelling with `list-timezones`; the name is case-sensitive.
- `System clock synchronized: no` just after a restart is normal for a few seconds; check `chronyc sources` before changing anything else.
:::
