### Running now versus starting at boot
- The objective: ==start and stop services and configure services to start automatically at boot==
- A unit carries two independent states
  - ==Active==: running at this moment (`start`, `stop`, `restart`, covered in 4.4)
  - ==Enabled==: started on every boot (`enable`, `disable`)
- `start` alone is lost at the next reboot; `enable` alone waits for the next boot
- ==systemctl enable --now== sets both in one command
  - `disable --now` is the reverse: stop it and drop it from boot
- `systemctl is-enabled` and `is-active` answer one question each, one word per line

```console label="Terminal"
$ systemctl is-enabled httpd; \
    systemctl is-active httpd
disabled
inactive
$ sudo systemctl enable --now httpd
Created symlink '/etc/systemd/system/multi-user.target.wants/httpd.service' → '/usr/lib/systemd/system/httpd.service'.
$ systemctl is-enabled httpd; \
    systemctl is-active httpd
enabled
active
```

| Command | Now | Next boot |
|---|---|---|
| `start` / `stop` | changes | no change |
| `enable` / `disable` | no change | changes |
| `enable --now` | starts | starts |
| `mask` | blocks starts | blocks starts |

### What enable actually writes
- A service's ==[Install]== section names the target that should pull it in
  - httpd has `WantedBy=multi-user.target`
- `enable` creates a ==symlink== in that target's `.wants/` directory under `/etc/systemd/system`
- `disable` deletes the link; the unit file itself is untouched
- Package unit files live in `/usr/lib/systemd/system`; your changes go in `/etc/systemd/system`, which takes priority

:::figure wide 7.2-enable-symlinks.svg | Each persistent systemctl change is a symlink under /etc/systemd/system. The vendor unit file stays as the package installed it.

```console label="Terminal"
$ sudo systemctl disable httpd
Removed '/etc/systemd/system/multi-user.target.wants/httpd.service'.
$ sudo systemctl enable httpd
Created symlink '/etc/systemd/system/multi-user.target.wants/httpd.service' → '/usr/lib/systemd/system/httpd.service'.
```

- List everything set to start at boot with `list-unit-files`
  - ==PRESET== is the distribution's default; httpd ships disabled, so enabling it is always your job

```console label="Terminal"
$ systemctl list-unit-files --state=enabled \
    --type=service --no-pager | head -8
UNIT FILE                          STATE   PRESET
atd.service                        enabled enabled
audit-rules.service                enabled enabled
auditd.service                     enabled enabled
```

### Masking a service
- ==systemctl mask== links the unit name to `/dev/null`
  - No one can start it: not you, not a dependency, not the next boot
  - Use it when two services must never run together, or a task says a service must stay off
- `mask --now` also stops it if it is running
- Masking works even for a unit that is not installed yet (cups below), so a later package install cannot start it
- ==unmask== removes the link and nothing else; the service is still stopped and not enabled

```console label="Terminal"
$ sudo systemctl mask --now cups 2>&1; \
    sudo systemctl mask nfs-server
Unit cups.service does not exist, proceeding anyway.
Created symlink '/etc/systemd/system/cups.service' → '/dev/null'.
Created symlink '/etc/systemd/system/nfs-server.service' → '/dev/null'.
$ sudo systemctl start nfs-server
Failed to start nfs-server.service: Unit nfs-server.service is masked.
$ systemctl is-enabled nfs-server
masked
$ sudo systemctl unmask nfs-server
Removed '/etc/systemd/system/nfs-server.service'.
```

### Unit files and dependencies
- ==systemctl cat UNIT== prints the unit file and any drop-ins, each under a comment naming its path
- Never edit the copy in `/usr/lib`: a package update replaces it
  - ==systemctl edit UNIT== opens a drop-in, `/etc/systemd/system/UNIT.d/override.conf`, and reloads systemd when you save

```console label="Terminal"
$ systemctl cat httpd --no-pager | head -12
# /usr/lib/systemd/system/httpd.service
# Modifying this file in-place is not recommended, because changes
# will be overwritten during package upgrades.  To customize the
# behaviour, run "systemctl edit httpd" to create an override unit.
```

- Ordering and pulling in are separate settings
  - `Wants=` and `Requires=` decide what else gets started
  - `After=` and `Before=` decide only the order
- `systemctl list-dependencies TARGET` shows the tree; `●` active, `○` inactive
- `systemctl show -p PROPERTY UNIT` prints one setting as systemd parsed it

```console label="Terminal"
$ systemctl list-dependencies multi-user.target \
    --no-pager | head -10
multi-user.target
● ├─atd.service
○ ├─audit-rules.service
● ├─auditd.service
● ├─chronyd.service
● ├─crond.service
$ systemctl show -p WantedBy -p After httpd
WantedBy=multi-user.target
After=httpd-init.service network.target -.mount basic.target systemd-tmpfiles-setup.service sysinit.target tmp.mount nss-lookup.target remote-fs.target system.slice systemd-journald.socket
```

### Boot into a specific target automatically
- The objective: ==configure systems to boot into a specific target automatically==
- At boot systemd starts ==default.target==, a symlink in `/etc/systemd/system`
- ==systemctl set-default TARGET== rewrites that link; `get-default` reads it
  - When the target changes, it prints the `Removed` and `Created symlink` lines; setting the current value prints nothing

| Target | Gives you |
|---|---|
| `multi-user.target` | text logins, networking, all servers |
| `graphical.target` | multi-user plus a desktop login |
| `rescue.target` | single-user root shell, few services |
| `emergency.target` | root shell, root file system read-only |

- `systemctl isolate TARGET` switches only the running system; the default is unchanged (objective 4.1)
- `graphical.target` needs a desktop installed; on a minimal server it has nothing extra to start

```console label="Terminal"
$ systemctl get-default
multi-user.target
$ sudo systemctl set-default multi-user.target
$ ls -l /etc/systemd/system/default.target
lrwxrwxrwx. 1 root root 37 May 26 00:18 /etc/systemd/system/default.target -> /lib/systemd/system/multi-user.target
```

### Proving it after a reboot
- Enabled services, masks, and the default target are all links on disk, so they persist with no further step
- After `reboot`, check all three at once
  - `Loaded:` shows ==enabled== and the vendor ==preset==; `Active:` shows when it started

```console label="Terminal (after reboot)"
$ systemctl get-default
multi-user.target
$ systemctl is-active httpd
active
$ systemctl status httpd --no-pager | head -4
● httpd.service - The Apache HTTP Server
     Loaded: loaded (/usr/lib/systemd/system/httpd.service; enabled; preset: disabled)
     Active: active (running) since Wed 2026-10-21 19:01:10 UTC; 49s ago
```

:::exam
- "Ensure the service starts automatically at boot" is graded after a reboot. `systemctl start` passes a quick check and fails the grader; use `enable --now` and confirm with `is-enabled`.
- A service that refuses to start with "Unit ... is masked" needs `unmask` first, then `enable --now`. `unmask` by itself leaves it stopped.
- "Configure the system to boot into the multi-user target by default" is `set-default`, not `isolate`. `isolate` changes the running system and is gone after the reboot.
:::

:::try
On servera, configure httpd so that it is running now and starts automatically at every boot, mask nfs-server so that no one can start it, and configure the system to boot into multi-user.target by default. Reboot and confirm all three persist across the reboot.
:::
