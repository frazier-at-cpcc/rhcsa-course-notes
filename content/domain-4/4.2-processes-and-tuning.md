### Find the busy processes
- The objective: ==identify CPU/memory intensive processes and kill processes==
- ==`ps`== takes one snapshot; sort it to put the worst offender first
  - `ps aux --sort=-%cpu`: every process, highest CPU first
  - `ps -eo pid,user,%cpu,%mem,rss,comm --sort=-%mem`: pick the columns, highest memory first
  - The minus in `--sort=-` means descending
- `pgrep` turns a name into PIDs; `-l` adds the name, `-a` the full command line
- ==`top`== refreshes live; `-b -n 1` prints one screen for a script
  - Inside top: `P` sort by CPU, `M` by memory, `k` kill, `r` renice, `q` quit
- ==Load average==: runnable processes averaged over 1, 5, and 15 minutes
  - Compare to the CPU count (`nproc`); this VM has 2, so 1.20 is not overloaded yet
- `free -h` shows memory; ==available== is what new work can still get
- Here two checksum loops burn CPU and a Python process holds 400 MiB

```console label="Terminal"
$ ps -eo pid,user,%cpu,%mem,rss,comm --sort=-%mem | head -5
    PID USER     %CPU %MEM   RSS COMMAND
   2203 student   1.8 11.1 418072 python3
    832 root      1.0  1.1 43384 firewalld
    658 root      0.2  0.9 36108 systemd-journal
      1 root      4.0  0.9 35704 systemd
$ pgrep -l sum
2170 sha256sum
2171 sha1sum
$ uptime
 18:47:13 up 1 min,  0 user,  load average: 1.20, 0.43, 0.16
```

### Nice values and renice
- The objective: ==adjust process scheduling==
- Every process has a ==nice value== from -20 (most CPU) to 19 (least); the default is 0
  - Only matters when processes compete for a busy CPU
  - `top` shows it as `NI`; its `PR` column is 20 + NI
- ==`nice -n 15 command`== starts a command with a value
- ==`renice -n 10 -p PID`== changes a running process (also `-u user` for all of a user's processes)
- Rules for a regular user
  - Only your own processes, and only upward (nicer)
  - Once raised, you cannot bring it back down, not even from 10 to 5
  - Negative values need root

```console label="Terminal"
$ ps -o pid,ni,pri,%cpu,comm -C sha256sum,sha1sum
    PID  NI PRI %CPU COMMAND
   2170   0  19 92.6 sha256sum
   2171   0  19 93.1 sha1sum
$ renice -n 10 -p $(pgrep sha256sum)
2170 (process ID) old priority 0, new priority 10
$ renice -n 5 -p $(pgrep sha256sum)
renice: failed to set priority for 2170 (process ID): Permission denied
$ sudo renice -n -5 -p $(pgrep sha1sum)
2171 (process ID) old priority 0, new priority -5
$ ps -o pid,ni,pri,%cpu,comm -C sha256sum,sha1sum
    PID  NI PRI %CPU COMMAND
   2170  10   9 89.4 sha256sum
   2171  -5  24 91.5 sha1sum
$ nice -n 15 sleep 300 & ps -o pid,ni,comm -C sleep
    PID  NI COMMAND
   2624  15 sleep
$ nice -n -5 sleep 1
nice: cannot set niceness: Permission denied
```

- That last `nice` still ran `sleep` and exited 0, at the normal value 0
  - Read the warning; the command did not get the priority you asked for
- `ps -o pri` counts the other way from `top`'s `PR`: higher `PRI` is more favored

### Signals and killing processes
- `kill` sends a ==signal==; the default is ==SIGTERM== (15), a polite request to exit
- ==SIGKILL== (9) cannot be caught or ignored; use it only after TERM fails
  - No cleanup: temp files and locks stay behind

| No. | Signal | Effect |
|---|---|---|
| 1 | `HUP` | hang up; many daemons reload config |
| 2 | `INT` | interrupt, sent by `Ctrl+C` |
| 9 | `KILL` | stop now, cannot be blocked |
| 15 | `TERM` | ask to exit cleanly (default) |
| 18 | `CONT` | resume a stopped process |
| 19 | `STOP` | pause, cannot be blocked |

- Three ways to name the target
  - `kill PID`: one process, by number
  - ==`pkill pattern`==: every process whose name matches (`-u user`, `-t tty`, `-f` full command line)
  - ==`killall name`==: exact process name
- Check what `pkill -f` would match with `pgrep -af pattern` first; the full command line of your own shell can match too
- Your own processes need no sudo; anyone else's need root

```console label="Terminal"
$ kill $(pgrep sha1sum)
$ pgrep -l sum
2170 sha256sum
$ kill -SIGTERM $(pgrep sha256sum); sleep 1; pgrep -l sum || echo 'no sum processes left'
no sum processes left
$ pkill sleep; killall -v sleep 2>&1 | head -2
sleep: no process found
$ kill -9 999999
-bash: line 1: kill: (999999) - No such process
```

- `kill -9`, `kill -KILL`, and `kill -SIGKILL` are the same request; `kill -l` lists every signal and its number
  - `Ctrl+Z` sends `TSTP` (20), a stop the program may catch

### Tuning profiles
- The objective: ==manage tuning profiles==
- ==`tuned`== applies a set of kernel and device settings (a ==profile==) for a workload
  - Shipped profiles live in `/usr/lib/tuned/profiles/`; custom ones in `/etc/tuned/profiles/`
- `tuned-adm list`, `active`, ==`recommend`==, `profile NAME`, `off`

| Profile | For |
|---|---|
| `balanced` | general use, between speed and power |
| `powersave` | lowest power draw |
| `throughput-performance` | busy servers, the usual server pick |
| `latency-performance` | fast response over power savings |
| `virtual-guest` | a VM; the recommendation inside one |
| `virtual-host` | a KVM host running guests |

```console label="Terminal"
$ systemctl is-active tuned
active
$ tuned-adm active
Current active profile: virtual-guest
$ tuned-adm recommend
virtual-guest
$ sudo tuned-adm profile throughput-performance
$ tuned-adm active
Current active profile: throughput-performance
$ sudo tuned-adm profile $(tuned-adm recommend)
$ tuned-adm active
Current active profile: virtual-guest
$ sudo tuned-adm off; tuned-adm active
No current active profile.
$ sudo tuned-adm auto_profile; tuned-adm profile_mode
Profile selection mode: auto
```

- Persistence
  - `tuned-adm profile` saves the choice in `/etc/tuned/active_profile` and sets the mode to manual
  - `tuned.service` is enabled, so it reapplies that profile at every boot
  - `tuned-adm off` stops tuning until a profile is chosen again
- `tuned-adm verify` compares live settings with the profile
  - Run right after a switch, it reported `Verification failed` and pointed to `/var/log/tuned/tuned.log`

:::exam
- "Set the recommended tuning profile" means `tuned-adm recommend`, then `tuned-adm profile` with that name. Check with `tuned-adm active`, and make sure `tuned` is enabled so it survives a reboot.
- "Find the process using the most CPU and set its niceness to 10" is `ps aux --sort=-%cpu` (or `top`), then `renice -n 10 -p PID`. Confirm in the `NI` column.
- A regular user cannot lower a nice value. A task that wants a negative value, or wants a value undone, needs `sudo`.
:::
