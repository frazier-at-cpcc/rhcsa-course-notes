### The boot sequence
- Each stage hands off to the next; the arguments GRUB passes to the kernel decide where you land

:::figure 4.1-boot-sequence.svg | One-time kernel arguments typed at the GRUB menu choose where the boot stops. Nothing typed there survives the next reboot.

- The ==initramfs== (built by `dracut`) holds the drivers needed to find the real root file system
  - It mounts that file system read-only at ==`/sysroot`==, then `switch_root` makes it `/`
- systemd then starts units until it reaches the default target (`Reached target multi-user.target` in the journal)

### Shut down and reboot normally
- The objective: ==boot, reboot, and shut down a system normally==
- `systemctl` asks systemd to stop every unit in order, then power off
  - ==`systemctl poweroff`==, ==`systemctl reboot`==, `systemctl halt` (stops the OS, leaves power on)
  - `poweroff`, `reboot`, and `halt` are links to `systemctl` and do the same thing
- ==`shutdown`== adds a delay and a warning to logged-in users
  - `shutdown -h now` or `shutdown -r now`; `+15` is fifteen minutes; `13:59` is a clock time
  - Five minutes before the time, `/run/nologin` blocks new logins
  - `shutdown -c` cancels a pending one
  - RHEL 10's systemd also takes `systemctl poweroff --when=+15min`
- `last -x reboot shutdown` lists past boots and clean shutdowns (from `/var/log/wtmp`)

```console label="Terminal"
$ sudo shutdown -r +15 'Maintenance reboot'
Reboot scheduled for Wed 2026-10-21 19:00:42 UTC, use 'shutdown -c' to cancel.
$ sudo shutdown -c
$ systemctl is-system-running
running
```

### Targets
- A ==target== is a systemd unit that groups other units into a system state
  - Replaces SysV runlevels; `who -r` still reports the runlevel number
- `systemctl get-default` shows the target used at every boot
  - Changing it with `systemctl set-default` is objective 7.2

| Target | What you get |
|---|---|
| `graphical` | multi-user plus a desktop login |
| `multi-user` | full system, network, text logins |
| `rescue` | local file systems, no network, root shell |
| `emergency` | root read-only, almost nothing started, root shell |

```console label="Terminal"
$ systemctl get-default
multi-user.target
$ systemctl list-unit-files --type=target --no-pager | grep -E 'rescue|emergency|multi-user|graphical'
emergency.target              static   -
graphical.target              static   -
multi-user.target             indirect disabled
rescue.target                 static   -
$ systemctl cat rescue.target --no-pager | grep -E '^(Requires|After|AllowIsolate)'
Requires=sysinit.target rescue.service
After=sysinit.target rescue.service
AllowIsolate=yes
$ who -r
         run-level 3  2026-10-21 18:44
```

- ==`systemctl isolate`== switches a running system to another target now
  - Stops every unit the new target does not need
  - Works only on targets with ==`AllowIsolate=yes`==
  - `systemctl rescue` and `systemctl emergency` are shortcuts that also warn logged-in users
- Rescue and emergency both run `sulogin`, which asks for the ==root password==
  - With root locked (a RHEL 10 install can leave it with no password), `sulogin` prints `Cannot open access to console, the root account is locked.` and gives no shell

### Choose a target for one boot
- The objective: ==boot systems into different targets manually==
- At the ==GRUB menu==, edit the entry for this boot only

1. Reboot. When the menu appears, press an arrow key to stop the countdown.
2. Highlight the normal kernel entry and press `e`.
3. Move to the line that starts with `linux` and press `Ctrl+E` to reach its end.
4. Type a space and the argument, for example `systemd.unit=rescue.target`.
5. Press `Ctrl+X` to boot with the edited line.

:::wide
| Argument on the `linux` line | Result | Root password? |
|---|---|---|
| `systemd.unit=rescue.target` | rescue shell, local file systems mounted | needed |
| `systemd.unit=emergency.target` | emergency shell, root read-only | needed |
| `rd.break` | initramfs shell before `switch_root` | not needed |
| `init=/bin/bash` | bash as PID 1 instead of systemd | not needed |
:::

- The entry you edit is the BLS entry `grubby` reports; the arguments on the screen match `args=`
  - `console=ttyS0` here sends console output to the serial port; delete it if the shell never shows up on the screen you are watching
- ==`/proc/cmdline`== shows what the running kernel was booted with, so it proves an edit took effect

```console label="Terminal"
$ sudo grubby --info=DEFAULT | grep -E '^(kernel|args)'
kernel="/boot/vmlinuz-6.12.0-211.67.1.el10_2.x86_64"
args="console=ttyS0,115200n8 no_timer_check crashkernel=2G-64G:256M,64G-:512M"
```

### Reset the root password with rd.break
- The objective: ==interrupt the boot process in order to gain access to a system==
- Same steps on RHEL 9 and RHEL 10; needs the console, not SSH

1. Reboot, stop the GRUB countdown, highlight the normal entry, press `e`.
2. At the end of the `linux` line, add `rd.break`. Press `Ctrl+X`.
3. If the screen says `Press Enter for maintenance`, press Enter. The prompt is `switch_root:/#`.
4. `mount -o remount,rw /sysroot` makes the real root writable.
5. `chroot /sysroot` makes it `/` for the commands that follow.
6. `passwd root` and type the new password twice.
7. `touch /.autorelabel` so SELinux ==relabels== the disk at the next boot.
8. `exit` leaves the chroot; a second `exit` resumes the boot.
9. The relabel runs, the system reboots once more on its own, then log in as root.

- Skip step 7 and the new `/etc/shadow` has no ==SELinux label==
  - No SELinux policy is loaded in the initramfs, so `passwd` cannot label the file it writes
  - With SELinux enforcing, logins cannot read the file and fail
- RHEL 10 change: RHEL 10.0 shipped `dracut` 105, whose initramfs leaves out `chroot` (Red Hat solution 7121729)
  - `dracut` 107 in later RHEL 10 minor releases puts it back
  - No `chroot` in the shell? Use the `init=/bin/bash` method below

### The init=/bin/bash method
- Same goal, one stage later: the kernel runs bash as ==PID 1==, and systemd never starts

1. At the GRUB menu press `e` and add `init=/bin/bash` to the end of the `linux` line. `Ctrl+X`.
2. `mount -o remount,rw /` (the root file system starts read-only).
3. `passwd root`, then `touch /.autorelabel`.
4. ==`exec /sbin/init`== hands PID 1 to systemd, which relabels and reboots.

- A normal system has `/etc/shadow` labeled `shadow_t`; after a completed relabel, `/.autorelabel` is gone again

```console label="Terminal"
$ ls -lZ /etc/shadow
----------. 1 root root system_u:object_r:shadow_t:s0 985 Oct 21 18:45 /etc/shadow
$ ls /.autorelabel 2>&1
ls: cannot access '/.autorelabel': No such file or directory
```

- After a normal reboot, every one-time argument is gone and the default target is back

```console label="Terminal (after a reboot)"
$ last -x reboot | head -3
reboot   system boot  6.12.0-211.67.1. Wed Oct 21 18:46   still running
reboot   system boot  6.12.0-211.67.1. Wed Oct 21 18:44 - 18:45  (00:01)
$ systemctl is-system-running
running
```

:::exam
- "Reset the root password of serverb to `redhat`" is a console task. Use `rd.break`, remount `/sysroot` read-write, `chroot`, `passwd`, and do not forget `touch /.autorelabel`; without it root still cannot log in after the reboot.
- Rescue and emergency targets ask for the root password you do not have. When you are locked out, `rd.break` or `init=/bin/bash` is the answer; when you only need a different target, `systemd.unit=` is.
- Anything typed at the GRUB menu lasts one boot. A task that says "persists" needs `systemctl set-default` (7.2) or `grubby` (7.5).
:::

:::try
On a lab VM, boot once into `rescue.target` from the GRUB menu and confirm with `systemctl get-default` and `cat /proc/cmdline` that the default is unchanged. Then reset the root password with `rd.break`, reboot, and log in as root on the console with the new password.
:::
