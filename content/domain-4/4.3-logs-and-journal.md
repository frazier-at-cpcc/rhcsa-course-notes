### Two logging services
- The objective: ==locate and interpret system log files and journals; preserve system journals==
- ==`systemd-journald`== receives every message first and stores it in a binary, indexed ==journal==
- ==`rsyslogd`== reads the journal and writes plain-text files under ==`/var/log`==
  - Both run by default on RHEL 10, so most events land in both places

### Log files under /var/log
- Root reads most of them; use `sudo`

| File | Holds |
|---|---|
| `/var/log/messages` | general system messages (most things) |
| `/var/log/secure` | logins, `sudo`, `su`, SSH (`authpriv`) |
| `/var/log/cron` | cron and at jobs |
| `/var/log/maillog` | mail server |
| `/var/log/audit/audit.log` | SELinux denials and audit events |

- Each line: time, host, program`[PID]`, message
- Which file gets what is set by `/etc/rsyslog.conf` (and `/etc/rsyslog.d/*.conf`)
  - A rule is ==facility.priority==, then the destination
  - `*.info;mail.none;authpriv.none;cron.none` sends everything at `info` or above to `messages`, except mail, auth, and cron

  - `authpriv.* action(type="omfile" file="/var/log/secure")` sends all auth messages to `secure`

```console label="Terminal"
$ sudo grep -c 'session opened' /var/log/secure
1149
```

- ==`logger`== writes a test message; `-p` sets facility and priority, `-t` the tag
- Priorities, most to least severe: `emerg`, `alert`, `crit`, `err`, `warning`, `notice`, `info`, `debug`
- Old files rotate weekly (`logrotate`) into dated copies such as `messages-20261018`

:::figure 4.3-log-flow.svg | journald is the collector. Whether its journal survives a reboot depends on which directory it writes to.

### Reading the journal
- ==`journalctl`== with no options shows everything, oldest first, in a pager
  - Regular users see their own messages; members of `wheel` and `adm` (and root) see all of them
- Filters combine; each one narrows the result

| Option | Shows |
|---|---|
| `-n 20` | the last 20 entries |
| `-f` | new entries as they arrive |
| `-u sshd` | one unit |
| `-p err` | `err` and more severe |
| `-b`, `-b -1` | this boot, the previous boot |
| `--since`, `--until` | a time window |
| `-t tag` | one syslog tag |
| `_COMM=sshd` | any journal field |
| `-o verbose` | every field of each entry |

```console label="Terminal"
$ sudo journalctl -p err -b --no-pager | tail -3
-- No entries --
$ logger -p user.warning 'RHCSA lab: disk space check'
$ sudo journalctl --since '10 min ago' -t student --no-pager
Oct 21 18:52:27 servera.lab.example.com student[4920]: RHCSA lab: disk space check
$ journalctl --disk-usage
Archived and active journals take up 56M in the file system.
```

- `-o verbose` reveals the ==journal field== names you can filter on: `_COMM=sshd`, `_UID=0`, `PRIORITY=6`, `SYSLOG_IDENTIFIER=sshd`
- `-u sshd` on RHEL 10 shows lines tagged `sshd-session`: each login now runs in its own `sshd-session` process

### Where the journal is stored
- ==`Storage=`== in journald's configuration decides it

| Value | Journal goes to |
|---|---|
| `auto` (default) | `/var/log/journal` if that directory exists, else `/run/log/journal` |
| `persistent` | `/var/log/journal`, created if missing |
| `volatile` | `/run/log/journal` only (RAM) |
| `none` | nowhere |

- Red Hat documents the RHEL 10 default as ==`/run/log/journal`==: lost at every reboot
  - With `auto`, the result depends on whether something created `/var/log/journal`
- RHEL 10 change: `/etc/systemd/journald.conf` no longer exists
  - The defaults live in `/usr/lib/systemd/journald.conf`
  - Your settings go in a ==drop-in== under ==`/etc/systemd/journald.conf.d/`==
  - `systemd-analyze cat-config systemd/journald.conf` shows the merged result
- On this lab VM (a Rocky Linux 10.2 cloud image) `/var/log/journal` already existed, so `auto` was already persistent
  - `journalctl --list-boots` listed 13 boots, indexed `-12` to `0`
  - Do not assume; check the directory and `--list-boots`

```console label="Terminal"
$ grep -E '^#?Storage' /etc/systemd/journald.conf
grep: /etc/systemd/journald.conf: No such file or directory
$ ls -ld /var/log/journal /run/log/journal 2>&1
drwxr-sr-x+ 2 root systemd-journal 40 Oct 21 18:46 /run/log/journal
drwxr-sr-x+ 3 root systemd-journal 46 Oct 21 18:07 /var/log/journal
```

### Preserve the journal across reboots
- The objective's ==preserve system journals==: set ==`Storage=persistent`== so it no longer depends on the directory
  - Create the drop-in, then restart `systemd-journald`
  - `journalctl --flush` moves anything still in `/run` to disk
- The older habit, `mkdir /var/log/journal` and keep `auto`, also works, but leaves the result to the directory surviving

```console label="Terminal"
$ sudo mkdir -p /etc/systemd/journald.conf.d
$ printf '[Journal]\nStorage=persistent\n' | sudo tee /etc/systemd/journald.conf.d/persistent.conf
[Journal]
Storage=persistent
$ sudo systemctl restart systemd-journald
$ sudo ls /var/log/journal/
e1efc03b2eb54461826a66afe9ac7122
$ sudo journalctl --flush; journalctl --disk-usage
Archived and active journals take up 56M in the file system.
```

- The directory under `/var/log/journal` is the ==machine ID== (`/etc/machine-id`)
- Size limits: `SystemMaxUse=` (default 10% of the file system, at most 4 GiB) in the same drop-in
- Proof after a reboot: `--list-boots` now runs from `-13` to `0`, and the previous boot (`-1`) is still readable

```console label="Terminal (after a reboot)"
$ sudo journalctl -b -1 -n 3 --no-pager
Oct 21 18:52:30 servera.lab.example.com systemd-shutdown[1]: Sending SIGTERM to remaining processes...
Oct 21 18:52:30 servera.lab.example.com systemd-journald[5480]: Received SIGTERM from PID 1 (systemd-shutdow).
Oct 21 18:52:30 servera.lab.example.com systemd-journald[5480]: Journal stopped
$ sudo journalctl -b -1 --no-pager | grep -c 'RHCSA lab'
5
```

:::exam
- "Configure the journal to be preserved across reboots" is a drop-in in `/etc/systemd/journald.conf.d/` with `Storage=persistent`, then `systemctl restart systemd-journald`. The grader reboots and runs `journalctl -b -1`.
- On RHEL 10 there is no `/etc/systemd/journald.conf` to edit. Do not go looking for it; create the drop-in directory.
- "Find the log entries for the failed SSH logins" is `/var/log/secure` or `journalctl -u sshd`. Errors only: `journalctl -p err`.
:::
