### Services and systemctl
- The objective: ==start, stop, and check the status of network services==
- A network service is a daemon managed as a systemd ==service unit==: `sshd.service`, `httpd.service`, `chronyd.service`
- Changing a service's state needs root; checking it does not

| Command | Does |
|---|---|
| `systemctl start httpd` | start it now |
| `systemctl stop httpd` | stop it now |
| `systemctl restart httpd` | stop, then start (drops connections) |
| `systemctl reload httpd` | reread config, keep running |
| `systemctl status httpd` | state, main PID, latest log lines |
| `systemctl is-active httpd` | one word, exit 0 only if active |
| `systemctl enable --now httpd` | start now and at every boot (7.2) |

### Checking and changing a service
- ==`systemctl status`== reads top-down
  - `Loaded:` the unit file, then ==enabled== or disabled (starts at boot or not), then the vendor preset
  - `Active:` ==active (running)==, `inactive (dead)`, or `failed`, with the time it changed
  - The last journal lines for the unit follow (`journalctl -u` shows more)
- `is-active` is the scripting form: it prints one word and sets the exit code (3 here, for inactive)

```console label="Terminal"
$ systemctl status sshd --no-pager | head -6
● sshd.service - OpenSSH server daemon
     Loaded: loaded (/usr/lib/systemd/system/sshd.service; enabled; preset: enabled)
     Active: active (running) since Wed 2026-10-21 18:52:49 UTC; 1min 31s ago
 Invocation: b54a1f528ae549b8bf19c303eac0eb7c
       Docs: man:sshd(8)
             man:sshd_config(5)
$ systemctl is-active httpd
inactive
$ sudo systemctl start httpd
$ systemctl is-active httpd
active
$ curl -sI http://localhost/ | head -1
HTTP/1.1 403 Forbidden
$ sudo systemctl stop httpd
$ systemctl status httpd --no-pager | head -3
○ httpd.service - The Apache HTTP Server
     Loaded: loaded (/usr/lib/systemd/system/httpd.service; disabled; preset: disabled)
     Active: inactive (dead)
$ sudo systemctl restart sshd; systemctl is-active sshd
active
$ sudo systemctl reload sshd; echo $?
0
```

- The `403 Forbidden` is a good sign: Apache answered, and has no `index.html` to serve yet
- ==`start` is not persistent==: httpd above is `disabled`, so it stays down after a reboot
  - On the exam, a service that must survive a reboot gets `systemctl enable --now`, and usually a firewall rule (8.3)
- `reload` keeps existing sessions; prefer it over `restart` for `sshd` when you only changed `sshd_config`

### Copy files with scp
- The objective: ==securely transfer files between systems==
- All three tools here run over SSH: same login, same keys, traffic encrypted
- ==`scp source target`==; the remote side is `user@host:path`
  - An empty path after the colon, or a relative one, is the remote user's home directory
  - `-r` copies a directory tree, `-p` keeps times and modes, `-P 2222` sets the port (capital P)
  - Works in both directions: put the remote side first to pull
- Since OpenSSH 9.0 (RHEL 9 and 10), `scp` speaks the SFTP protocol underneath; `-O` forces the old protocol
- In the examples, student on servera copies to bob on serverb with an SSH key (objective 10.3)

```console label="Terminal (student on servera)"
$ ls -l q3
total 5124
-rw-r--r-- 1 student student 5242880 Oct 21 19:48 backup.img
-rw-r--r-- 1 student student      14 Oct 21 19:48 summary.txt
$ scp q3/summary.txt bob@serverb:
$ ssh bob@serverb ls -l
total 4
-rw-r--r-- 1 bob bob 14 Oct 21 19:48 summary.txt
$ scp -r q3 bob@serverb:/tmp/
$ ssh bob@serverb ls /tmp/q3
backup.img
summary.txt
$ scp bob@serverb:/etc/hostname sb-name; cat sb-name
serverb.lab.example.com
```

- A successful `scp` prints nothing in a script or batch job; check the far side
- `scp -B` (batch mode) never asks for a password; with no key for the account it fails with `Permission denied (publickey,...)` and `scp: Connection closed`

### sftp in batch mode
- ==`sftp user@host`== opens an interactive session: `ls`, `cd`, `get`, `put`, `mkdir`, `bye`
  - `lls` and `lcd` act on the local side
- ==`sftp -b file`== runs the commands in a file, then exits
  - Needs key login (batch mode cannot type a password)
  - Stops at the first failing command and exits 1, so a script can test it

```console label="Terminal (student on servera)"
$ cat batch.sftp
cd /tmp/q3
ls -l
get backup.img fetched.img
bye
$ sftp -b batch.sftp bob@serverb
sftp> cd /tmp/q3
sftp> ls -l
-rw-r--r--    ? bob      bob       5242880 Oct 21 19:48 backup.img
-rw-r--r--    ? bob      bob            14 Oct 21 19:48 summary.txt
sftp> get backup.img fetched.img
sftp> bye
$ ls -l fetched.img
-rw-r--r-- 1 student student 5242880 Oct 21 19:48 fetched.img
```

- A failed `get` prints, for example, `File "/tmp/q3/nosuch.txt" not found.` and ends the batch with exit status 1

### rsync over SSH
- ==`rsync`== copies only what differs, so a second run is fast
  - Needs the `rsync` package on both systems; SSH is the default transport
- ==`-a`== (archive): recursive, keeps permissions, times, links, and owner where allowed
- `-v` lists each file, ==`-n`== (`--dry-run`) shows what would happen and changes nothing
- ==`--delete`== removes files on the target that are gone from the source

```console label="Terminal (student on servera)"
$ rsync -av q3/ bob@serverb:q3/
sending incremental file list
created directory q3
./
backup.img
summary.txt

sent 5,244,365 bytes  received 82 bytes  3,496,298.00 bytes/sec
total size is 5,242,894  speedup is 1.00
$ echo appended >> q3/summary.txt
$ rsync -av q3/ bob@serverb:q3/
sending incremental file list
summary.txt

sent 180 bytes  received 41 bytes  147.33 bytes/sec
total size is 5,242,903  speedup is 23,723.54
```

- The second run sent 180 bytes: only the changed file
- Run `--delete` with `-n` first; a wrong source path empties the target

```console label="Terminal (student on servera)"
$ rm q3/backup.img
$ rsync -avn --delete q3/ bob@serverb:q3/
sending incremental file list
deleting backup.img
./

sent 96 bytes  received 40 bytes  272.00 bytes/sec
total size is 23  speedup is 0.17 (DRY RUN)
```

- The ==trailing slash== on the source matters
  - `q3/` copies the contents of q3 into the target
  - `q3` copies the directory itself: `rsync -a q3 bob@serverb:archive/` made `archive/q3/summary.txt`

:::exam
- "Ensure httpd is running now and after a reboot" needs both halves: `systemctl enable --now httpd`, then check `systemctl is-enabled` and `is-active`. A plain `start` passes until the grader reboots.
- "Copy /etc/hosts from serverb into /root on servera" works with `scp root@serverb:/etc/hosts /root/` run on servera. Read which side is the source.
- A task that says "synchronize" or "only changed files" points to `rsync -a`. Mind the trailing slash on the source.
:::

Configure httpd on servera so that it starts now and persists across reboots, and confirm with `systemctl status`. Then copy `/usr/share/doc/rsync` from servera into `/tmp/docs/` on serverb with `rsync -av` over SSH, run it again, and confirm the second run transfers almost nothing.
