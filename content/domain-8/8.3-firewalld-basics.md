### firewalld and firewall-cmd
- The objective: ==restrict network access using firewalld and firewall-cmd==
- ==firewalld== is the firewall daemon; it programs the kernel's ==nftables== rules
  - `firewall-cmd` is its command-line client; run it with `sudo`
  - Incoming traffic that nothing allows is rejected
- Running and enabled by default on RHEL 10
  - If not: `sudo systemctl enable --now firewalld`
- Rules are grouped into ==zones==; each network interface belongs to one
  - The ==default zone== is `public`, and it holds `ens18` here
  - Zone choice, sources, and rich rules are objective 10.1; this topic is the daily service and port work

```console label="Terminal"
$ systemctl is-active firewalld
active
$ systemctl is-enabled firewalld
enabled
$ sudo firewall-cmd --state
running
$ sudo firewall-cmd --get-default-zone
public
$ sudo firewall-cmd --get-active-zones
public (default)
  interfaces: ens18
```

### Reading a zone with --list-all
- ==`--list-all`== prints everything a zone allows; add `--zone=NAME` for one other than the default
- The lines that matter here
  - `interfaces`: devices whose traffic this zone judges
  - `services`: named services allowed in
  - `ports`: raw port numbers allowed in

```console label="Terminal"
$ sudo firewall-cmd --list-all
public (default, active)
  target: default
  ingress-priority: 0
  egress-priority: 0
  icmp-block-inversion: no
  interfaces: ens18
  sources:
  services: cockpit dhcpv6-client ssh
  ports:
  protocols:
  forward: yes
  masquerade: no
  forward-ports:
  source-ports:
  icmp-blocks:
  rich rules:
```

- A ==service== is a named list of ports (and helper modules) kept in XML
  - Shipped definitions live in `/usr/lib/firewalld/services/`
  - `--get-services` lists every name; `--info-service=NAME` shows its ports

```console label="Terminal"
$ sudo firewall-cmd --info-service=http
http
  ports: 80/tcp
```

### Runtime versus permanent
- firewalld keeps two configurations
  - ==Runtime==: what is enforced now; lost at `--reload`, a service restart, or a reboot
  - ==Permanent==: saved under `/etc/firewalld/`; loaded at start and at `--reload`
- Without `--permanent`, a change is live but unsaved
- With ==`--permanent`==, a change is saved but not live until ==`--reload`==

| Command | Live now | After reboot |
|---|---|---|
| `--add-service=http` | yes | no |
| `--permanent --add-service=http` | no | yes |
| `--permanent ...`, then `--reload` | yes | yes |

- A test from the server itself proves nothing about the firewall
  - Local traffic, even to its own `172.18.8.117`, is never filtered
  - The `403` below is Apache's welcome page answering locally; test from serverb

```console label="Terminal"
$ sudo systemctl start httpd
$ curl -s -o /dev/null -w '%{http_code}\n' \
    http://172.18.8.117/
403
$ sudo firewall-cmd --add-service=http
success
$ sudo firewall-cmd --list-services
cockpit dhcpv6-client http ssh
$ sudo firewall-cmd --list-services \
    --permanent
cockpit dhcpv6-client ssh
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --list-services
cockpit dhcpv6-client ssh
```

- The runtime-only `http` vanished at `--reload`; now save it, then reload

```console label="Terminal"
$ sudo firewall-cmd --permanent \
    --add-service=http
success
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --list-services
cockpit dhcpv6-client http ssh
```

### Opening a port
- ==`--add-port=PORT/PROTOCOL`== when no service definition fits
  - `8080/tcp`, `514/udp`, or a range such as `5000-5010/tcp`
  - Prefer a service name when one exists; the listing reads better and covers every port the service needs
- `--query-service=NAME` and ==`--query-port=PORT/PROTOCOL`== answer `yes` or `no`
- A web server on a nonstandard port also needs an SELinux port label (objective 10.5)

```console label="Terminal"
$ sudo firewall-cmd --permanent \
    --add-port=8080/tcp
success
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --list-ports
8080/tcp
$ sudo firewall-cmd --query-port=8080/tcp
yes
```

### Removing access, and where it is saved
- ==`--remove-service`== and `--remove-port` undo the matching `--add-`
  - Same rule: `--permanent` plus `--reload`, or the change comes back at boot
- Check both views: `--list-all` (runtime) and `--permanent --list-all` (saved)
- Never remove `ssh` from the zone you are connected through

```console label="Terminal"
$ sudo firewall-cmd --permanent \
    --remove-port=8080/tcp
success
$ sudo firewall-cmd --permanent \
    --remove-service=http
success
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --list-all \
    | grep -E 'services|ports'
  services: cockpit dhcpv6-client ssh
  ports:
$ sudo firewall-cmd --permanent --list-all \
    | grep -E 'services|ports'
  services: cockpit dhcpv6-client ssh
  ports:
```

- Permanent settings are XML files in ==`/etc/firewalld/zones/`==
  - Shipped defaults stay in `/usr/lib/firewalld/zones/`; a file in `/etc` overrides them
  - The directory is root-only: a plain `ls /etc/firewalld/zones/` gets `Permission denied`

```console label="Terminal"
$ sudo cat /etc/firewalld/zones/$(sudo \
    firewall-cmd --get-default-zone).xml
<?xml version="1.0" encoding="utf-8"?>
<zone>
  <short>Public</short>
  <service name="ssh"/>
  <service name="dhcpv6-client"/>
  <service name="cockpit"/>
  <forward/>
</zone>
```

:::exam
- "Configure the firewall to allow HTTP and HTTPS so that it persists across reboots" is `--permanent --add-service=http` and `https`, then `--reload`. Check with `--list-services` both with and without `--permanent`.
- A change made without `--permanent` passes every check you run, then disappears when the grader reboots. A change made only with `--permanent` is not live until `--reload`.
- When the task names a port number instead of a service, use `--add-port=8080/tcp`, and remember the SELinux side of a nonstandard port.
:::

On servera, install and start httpd. Configure the firewall in the default zone so that the http service and port 8080/tcp are allowed, and the configuration persists across reboots. From serverb, confirm with `curl http://servera.lab.example.com/`, then reboot servera and confirm again.
:::
