### Devices, connections, and keyfiles
- The objective: ==configure IPv4 and IPv6 addresses== and ==configure network services to start automatically at boot==
- ==NetworkManager== runs the network on RHEL 10; `nmcli` is its command-line client
  - A ==device== is an interface the kernel sees: `ens18`, `ens19`, `lo`
  - A ==connection== (or profile) is a saved set of settings applied to a device; one is active per device
- `nmcli device status` and `nmcli connection show` (`--active` for those in use) show both sides
- `ip -br addr` and `ip route` report what the kernel holds right now, whoever put it there

:::wide
```console label="Terminal"
$ nmcli device status
DEVICE  TYPE      STATE                   CONNECTION
ens18   ethernet  connected               cloud-init eth0
lo      loopback  connected (externally)  lo
ens19   ethernet  disconnected            --
$ nmcli connection show
NAME             UUID                                  TYPE      DEVICE
cloud-init eth0  1dd9a779-d327-56e1-8454-c65e2556c12c  ethernet  ens18
lo               2403fb93-b670-4ba9-ac02-18c8df5ff60e  loopback  lo
$ ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128
ens18            UP             172.18.8.117/24 fe80::be24:11ff:fedc:bcd0/64
ens19            UP
$ ip route

172.18.8.0/24 dev ens18 proto kernel scope link src 172.18.8.117 metric 100
$ ls /etc/NetworkManager/system-connections/ /etc/sysconfig/network-scripts/ 2>&1
ls: cannot access '/etc/sysconfig/network-scripts/': No such file or directory
/etc/NetworkManager/system-connections/:
cloud-init-eth0.nmconnection
```
:::

- `ens19` is this lab's spare NIC: link up, no profile, no address
- Profile names and device names are separate: the profile `cloud-init eth0` runs on the device `ens18`
  - `nmcli connection` commands take the NAME column; quote names with spaces
- Each profile is a ==keyfile==: `/etc/NetworkManager/system-connections/NAME.nmconnection`, readable by root only
- ==RHEL 10 removed ifcfg support== from NetworkManager
  - No `/etc/sysconfig/network-scripts/`, no `ifcfg-ens19`, no `ifup` scripts
  - RHEL 9 still read old ifcfg files but saved new profiles as keyfiles

### Add a static IPv4 and IPv6 connection
- ==`nmcli connection add`== creates the profile and writes its keyfile in one step
- `method manual` means static; `auto` means DHCP (IPv4) or router advertisements and DHCPv6 (IPv6)

:::wide
| Property | Example | What it sets |
|---|---|---|
| `type`, `con-name`, `ifname` | `ethernet`, `lab-static`, `ens19` | Kind of link, profile name, the device it binds to |
| `ipv4.method`, `ipv4.addresses` | `manual`, `192.0.2.10/24` | Static IPv4 address and prefix; commas separate several |
| `ipv4.gateway`, `ipv4.dns` | `192.0.2.1`, `192.0.2.53` | Default gateway; DNS servers (objective 8.2) |
| `ipv6.method`, `ipv6.addresses` | `manual`, `2001:db8::10/64` | Static IPv6 address |
| `ipv6.gateway`, `ipv6.dns` | `2001:db8::1`, `2001:db8::53` | IPv6 gateway and DNS |
| `connection.autoconnect` | `yes` | Activate at boot (the default) |
:::

- `ip4`, `gw4`, `ip6`, `gw6` are short aliases for the address and gateway properties
- The lab set no gateway on `ens19`
  - A second default route would compete with the one on `ens18`
  - On the exam, add `ipv4.gateway` (and `ipv6.gateway`) whenever the task gives one

:::wide
```console label="Terminal"
$ sudo nmcli connection add type ethernet con-name lab-static ifname ens19 \
    ipv4.method manual ipv4.addresses 192.0.2.10/24 ipv4.dns 192.0.2.53 \
    ipv6.method manual ipv6.addresses 2001:db8::10/64 connection.autoconnect yes
Connection 'lab-static' (d08679b3-ef79-47bd-a113-60799debda65) successfully added.
$ sudo nmcli connection up lab-static
Connection successfully activated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/4)
$ ip -br addr show ens19
ens19            UP             192.0.2.10/24 2001:db8::10/64 fe80::be24:11ff:fea6:3c68/64
```
:::

### The keyfile on disk
- One INI section per settings group; the properties map across directly
  - `ipv4.addresses` becomes `address1=`, `ipv4.dns` becomes `dns=`
  - Defaults are left out, so `autoconnect=yes` does not appear

```ini label="lab-static.nmconnection"
[connection]
id=lab-static
uuid=d08679b3-ef79-47bd-a113-60799debda65
type=ethernet
interface-name=ens19

[ipv4]
address1=192.0.2.10/24
dns=192.0.2.53;
method=manual

[ipv6]
addr-gen-mode=default
address1=2001:db8::10/64
method=manual
```

- Hand edits are allowed: edit, run ==`nmcli connection reload`==, then bring the profile up
- `nmtui` is a menu front end that writes the same keyfile

### Change a connection
- ==`nmcli connection modify NAME property value`== rewrites the profile
  - `+ipv4.addresses` adds a value to a list; `-ipv4.addresses` removes one
- `modify` touches the profile only
  - The device keeps its old settings until `nmcli connection up NAME` applies the new ones
  - After a reboot the new settings appear anyway, which can hide a missed `up`

:::wide
```console label="Terminal"
$ sudo nmcli connection modify lab-static +ipv4.addresses 192.0.2.11/24
$ sudo nmcli connection up lab-static; ip -br addr show ens19
Connection successfully activated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/5)
ens19            UP             192.0.2.10/24 192.0.2.11/24 2001:db8::10/64 fe80::be24:11ff:fea6:3c68/64
```
:::

:::figure 8.1-profile-to-device.svg | nmcli edits the keyfile; only activation pushes it to the device. At boot NetworkManager activates every profile set to autoconnect.

### Start at boot
- The network comes up at boot when two things hold
  - `NetworkManager.service` is ==enabled== (the default; `systemctl is-enabled NetworkManager` says `enabled`)
  - The profile has ==`connection.autoconnect yes`== (the default for new profiles)
- Turn it on for an existing profile: `nmcli connection modify NAME connection.autoconnect yes`

:::wide
```console label="Terminal (after reboot)"
$ nmcli connection show --active
NAME             UUID                                  TYPE      DEVICE
cloud-init eth0  1dd9a779-d327-56e1-8454-c65e2556c12c  ethernet  ens18
lab-static       d08679b3-ef79-47bd-a113-60799debda65  ethernet  ens19
lo               785d13c0-423e-4934-af74-80697bad444c  loopback  lo
$ ip -br addr show ens19
ens19            UP             192.0.2.10/24 2001:db8::10/64 fe80::be24:11ff:fea6:3c68/64
```
:::

:::exam
- A static IPv4 and IPv6 address with a gateway is one `nmcli connection add` with `method manual` for both families, then `up`. Check with `ip -br addr`.
- `ip addr add` is the distractor: it works until the grader reboots. Only a profile persists.
- After `modify`, run `nmcli connection up`; otherwise the profile and `ip addr` disagree until the next boot.
:::
