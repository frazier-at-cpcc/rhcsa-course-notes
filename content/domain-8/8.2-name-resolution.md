### The host name
- The objective: ==configure hostname resolution==, which starts with the machine's own name
- `hostname` prints the full name, `-s` the short name, `-I` every address
- ==`hostnamectl hostname NAME`== sets the ==static hostname==
  - Written to `/etc/hostname`, so it persists across reboots
  - The older `hostnamectl set-hostname` spelling still works but is no longer listed in `--help`
  - `nmcli general hostname NAME` does the same job through NetworkManager
- Plain `hostname NAME` changes only the running kernel's name; it is lost at reboot

```console label="Terminal"
$ hostname; hostname -s; hostname -I
servera.lab.example.com
servera
172.18.8.117
$ hostnamectl
     Static hostname: servera.lab.example.com
      Virtualization: kvm
```

```console label="Terminal"
$ sudo hostnamectl hostname \
    serverx.lab.example.com
$ hostnamectl --static
serverx.lab.example.com
$ cat /etc/hostname
serverx.lab.example.com
$ sudo hostnamectl hostname \
    servera.lab.example.com
$ cat /etc/hostname
servera.lab.example.com
```

- A shell that is already open keeps the old name in its prompt; open a new one to see the change

### The lookup order
- Programs resolve names through the C library's ==Name Service Switch==
- The `hosts:` line in ==`/etc/nsswitch.conf`== sets the order of sources
  - `files`: `/etc/hosts`, checked first; a match there ends the lookup
  - `dns`: the servers in `/etc/resolv.conf`
  - `myhostname`: the machine's own name always resolves, even with no entries anywhere

```console label="Terminal"
$ grep '^hosts:' /etc/nsswitch.conf
hosts:      files  dns myhostname
```

:::figure 8.2-lookup-order.svg | getent, ping, ssh, and curl walk the hosts: line in order and stop at the first answer. host and dig skip it and ask a DNS server directly.

### Static entries in /etc/hosts
- One line per address: ==`IP  FQDN  aliases`==
  - Put the full name first; it becomes the canonical name
- Takes effect immediately; no service to restart
- ==`getent hosts NAME`== resolves exactly the way applications do, so it is the right check

:::wide
```console label="Terminal"
$ cat /etc/hosts
127.0.0.1   localhost localhost.localdomain localhost4 localhost4.localdomain4
::1         localhost localhost.localdomain localhost6 localhost6.localdomain6
172.18.8.117 servera.lab.example.com servera
$ echo '192.0.2.20  serverb.lab.example.com serverb' | sudo tee -a /etc/hosts
192.0.2.20  serverb.lab.example.com serverb
$ getent hosts serverb
192.0.2.20      serverb.lab.example.com serverb
$ ping -c1 -W1 serverb | head -1
PING serverb.lab.example.com (192.0.2.20) 56(84) bytes of data.
```
:::

- `ping serverb` found the address and expanded the alias to the full name
- `host serverb` and `dig +short serverb` returned nothing in the same session
  - Both query DNS directly and never read `/etc/hosts`

| Tool | Reads /etc/hosts? |
|---|---|
| `getent hosts` | yes, follows nsswitch |
| `ping`, `ssh`, `curl` | yes, follows nsswitch |
| `host`, `dig`, `nslookup` | no, DNS only |

### DNS servers and search domains
- ==`/etc/resolv.conf`== is written by NetworkManager from the active profiles
  - Hand edits are overwritten at the next reconnect or reboot
  - `nameserver` lines are the servers; `search` lists domains tried for short names
- Set DNS on the connection profile, then activate it

| Property | Effect |
|---|---|
| `ipv4.dns` | DNS servers (`+ipv4.dns` appends) |
| `ipv4.dns-search` | search domains |
| `ipv4.ignore-auto-dns` | `yes` drops DHCP-supplied servers |
| `ipv6.dns` | IPv6 DNS servers |

```console label="Terminal"
$ cat /etc/resolv.conf
# Generated by NetworkManager
search pm.itdivision.org lab.example.com
nameserver 172.16.121.130
nameserver 172.16.121.131
$ dig +short www.redhat.com | tail -2
e3396.dscx.akamaiedge.net.
23.7.63.83
```

- Changing the DNS servers of the lab's main connection would cut it off, so the capture built a spare profile on `ens19` and left it inactive (`autoconnect no`)

```console label="Terminal"
$ sudo nmcli connection add type ethernet \
    con-name dns-demo ifname ens19 \
    ipv4.method manual \
    ipv4.addresses 192.0.2.30/24 \
    ipv4.dns 192.0.2.53 \
    ipv4.dns-search lab.example.com \
    ipv4.ignore-auto-dns yes \
    ipv6.method disabled \
    autoconnect no >/dev/null
$ nmcli -g ipv4.dns,ipv4.dns-search,\
ipv4.ignore-auto-dns connection show dns-demo
192.0.2.53
lab.example.com
yes
```

- On the exam, modify the profile that is already active, then reapply it
  - `nmcli connection modify "NAME" ipv4.dns 192.0.2.53 ipv4.ignore-auto-dns yes ipv4.dns-search lab.example.com`
  - `nmcli connection up "NAME"`, then `cat /etc/resolv.conf` to confirm
- Without `ignore-auto-dns yes`, a DHCP profile keeps the DHCP servers alongside yours

### What persists
- Host name: `/etc/hostname`, written by `hostnamectl`
- Static entries: `/etc/hosts`, a plain file
- DNS servers and search domains: the profile's keyfile (objective 8.1); `resolv.conf` is rebuilt from it at every boot

:::exam
- "Set the hostname to serverb.lab.example.com" is `hostnamectl hostname`. Running `hostname serverb.lab.example.com` looks right until the reboot.
- "Configure the system to use 192.0.2.53 as its DNS server" belongs on the NetworkManager profile with `nmcli connection modify` and `up`. An edit to `/etc/resolv.conf` is overwritten.
- When a name must resolve without DNS, add it to `/etc/hosts` and test with `getent hosts`. `dig` will still say nothing, and that is expected.
:::
