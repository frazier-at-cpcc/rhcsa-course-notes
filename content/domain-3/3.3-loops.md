### for loops over a list
- ==for== runs the body once per word in a list
  - `for VAR in WORD...; do BODY; done`
  - The list is expanded once, before the first pass
- Where the words come from
  - Typed out: `for h in servera serverb`
  - A ==brace expansion==: `{1..5}`, `{a..c}`, `{01..10}`
  - `seq FIRST [STEP] LAST`: numbers from a command
  - A glob: `*.log` matches file names, spaces and all
  - `$(command)`: split on whitespace, so file names with spaces break
- Arithmetic form for counters: `for ((i=1; i<=3; i++))`

```console label="Terminal"
$ for h in web db; do echo "check $h"; done
check web
check db
$ for i in {1..3}; do touch app$i.log; done
$ echo *.log
app1.log app2.log app3.log
$ for i in $(seq 1 2 7); do echo -n "$i "; done
1 3 5 7
$ for f in *.log; do cp "$f" "$f.bak"; done
$ echo *.bak
app1.log.bak app2.log.bak app3.log.bak
```

- `${f%.log}` strips `.log` from the end of a name
  - Batch rename: `mv "$f" "${f%.log}.txt"` inside the loop

### Loop over command line arguments
- `for f in "$@"` visits each argument once, spaces intact
  - Shorthand: `for f; do` means the same thing
- Pair the loop with a test (3.2) to skip bad input
- A ==running total== uses ==arithmetic expansion==: `total=$((total + size))`

```bash label="filesizes.sh"
#!/bin/bash
# Print the size of each file named.
total=0
for f in "$@"; do
  if [ ! -f "$f" ]; then
    echo "skip: $f" >&2
    continue
  fi
  size=$(stat -c %s "$f")
  printf '%8d  %s\n' "$size" "$f"
  total=$((total + size))
done
printf '%8d  total\n' "$total"
```

```console label="Terminal"
$ ./filesizes.sh /etc/passwd /etc/group /etc
     799  /etc/passwd
     415  /etc/group
skip: /etc
    1214  total
```

### while read: one line at a time
- ==while== repeats as long as its command succeeds
  - `read` succeeds while there is a line, and fails at end of file
  - So `while read -r line` stops by itself at the end of the input
- Redirect the file into the loop: `done < "$file"`
  - Put the redirect after `done`; a redirect on `read` reopens the file each pass and rereads line one forever
- Several names split each line into fields
  - `read -r user group` puts the first word in `user`, the rest in `group`

:::figure 3.3-while-read.svg | Each pass of the loop asks read for the next line. When the file runs out, read returns 1 and the loop ends.

- ==continue== skips to the next pass; ==break== leaves the loop
- `until CMD` is the reverse of `while`: loop while the command fails

```text label="newhires.txt"
# user   group
alice    devops
bob      devops
carol    web
alice    web
```

```bash label="mkusers.sh"
#!/bin/bash
# Create one account per line: USER GROUP
[ -r "$1" ] || {
  echo "Usage: $0 FILE" >&2; exit 2; }
while read -r user group; do
  [[ -z $user || $user == \#* ]] && continue
  if id "$user" &>/dev/null; then
    echo "skip $user: exists"
    continue
  fi
  getent group "$group" >/dev/null ||
    groupadd "$group"
  useradd -G "$group" "$user"
  echo "added $user to $group"
done < "$1"
```

```console label="Terminal"
$ sudo ./mkusers.sh newhires.txt
added alice to devops
added bob to devops
added carol to web
skip alice: exists
$ id -nG carol
carol web
```

- Running it twice is safe: every user is skipped the second time
  - Graders often run your script again; a rerun should not fail

### Loop over command output
- Feed a command into the loop with ==process substitution==
  - `done < <(command)` reads the command's output like a file
- `IFS=: read -r a b c` sets the field separator (==IFS==) to a colon for that one `read`
  - `_` is a throwaway name for fields you do not need
- `(( ))` tests integers with C-style operators
  - The upper bound drops `nobody` (UID 65534)
- A pipe into `while` runs the loop in a ==subshell==
  - Variables set inside are gone when the loop ends

```bash label="humans.sh"
#!/bin/bash
# List regular accounts (UID 1000 and up).
n=0
while IFS=: read -r user _ uid _ _ home _
do
  (( uid >= 1000 && uid < 60000 )) || continue
  echo "$user $uid $home"
  n=$((n + 1))
done < <(getent passwd)
echo "$n regular accounts"
```

```console label="Terminal"
$ ./humans.sh
student 1000 /home/student
alice 1001 /home/alice
bob 1002 /home/bob
carol 1003 /home/carol
4 regular accounts
$ n=0; seq 3 | while read -r l; do n=$l; done
$ echo "n=$n"
n=0
```

:::wide
| Input | Loop | Watch out for |
|---|---|---|
| Fixed list, range, glob | `for x in a b c`, `{1..5}`, `*.log` | Unmatched glob stays literal: `*.log` |
| Script arguments | `for f in "$@"` | Unquoted `$@` splits on spaces |
| A file | `while read -r l; do ...; done < file` | Missing last newline skips the last line |
| Command output | `while read -r l; do ...; done < <(cmd)` | `cmd \| while` loses variables |
:::

:::exam
- Expect tasks such as "Write a script that creates every user listed in /root/users.txt and sets each one's shell to /sbin/nologin." Read the file with `while read -r`, skip blank and comment lines, and make the script safe to run twice.
- "Search for files owned by alice and copy them to /root/found" can be a loop or a single `find -exec`. Either works; the grader checks the result.
- `for line in $(cat file)` splits at every space as well as every newline. Use `while read -r` for line-oriented files.
:::
