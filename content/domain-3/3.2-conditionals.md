### Exit status is the condition
- `if` runs a command and checks its ==exit status==
  - `0` takes the `then` branch; anything else takes `else`
  - Any command works: `if grep -q alice /etc/passwd; then`
- ==test== and ==[ ]== are the same command under two names
  - `[` needs `]` as its last argument
  - Spaces around every part: `[ -d "$dir" ]`, never `[-d "$dir"]`
- `test` prints nothing; it only sets `$?`

```console label="Terminal"
$ test -d /etc; echo $?
0
$ [ -d /etc/hostname ]; echo $?
1
$ [ "$(id -u)" -eq 0 ] || echo "not root"
not root
```

### Test operators
- Three families: ==file tests==, ==string tests==, ==integer tests==
  - Strings use symbols (`=`, `!=`); integers use letters (`-eq`, `-lt`)
  - `[ 10 -gt 9 ]` is true; `[ 10 \> 9 ]` compares text and is false
- `!` negates: `[ ! -e /etc/nologin ]`
- Combine whole tests with `&&` and `||` between them

:::wide
| Files | True when | Strings and integers | True when |
|---|---|---|---|
| `-e PATH` | Exists, any type | `-z "$s"` | String is empty |
| `-f PATH` | Regular file | `-n "$s"` | String is not empty |
| `-d PATH` | Directory | `"$a" = "$b"` | Strings match |
| `-L PATH` | Symbolic link | `"$a" != "$b"` | Strings differ |
| `-s PATH` | File larger than zero bytes | `$x -eq $y` | Equal numbers |
| `-r`, `-w`, `-x` | You can read, write, execute it | `-ne` `-lt` `-le` | Not equal, less than, less or equal |
| `F1 -nt F2` | F1 is newer than F2 | `-gt` `-ge` | Greater than, greater or equal |
:::

### if, elif, else
- Shape: `if CMD; then ... elif CMD; then ... else ... fi`
  - ==elif== adds another condition; ==else== catches whatever is left
  - First true branch wins; the rest are skipped
  - `then` on the same line needs the `;` before it
- Order the tests from most to least specific
  - `-f` and `-d` follow symlinks, so check `-L` first

```bash label="checkpath.sh"
#!/bin/bash
# Say what kind of thing a path is.
p=$1
if [ -z "$p" ]; then
  echo "Usage: $0 PATH" >&2
  exit 2
fi
if [ -L "$p" ]; then
  echo "$p: link to $(readlink "$p")"
elif [ -d "$p" ]; then
  echo "$p: directory"
elif [ -f "$p" ] && [ -s "$p" ]; then
  echo "$p: file, $(stat -c %s "$p") bytes"
elif [ -f "$p" ]; then
  echo "$p: empty file"
else
  echo "$p: not found" >&2
  exit 1
fi
```

```console label="Terminal"
$ ln -s /var/www/html webroot
$ ./checkpath.sh webroot
webroot: link to /var/www/html
$ ./checkpath.sh /etc
/etc: directory
$ ./checkpath.sh /etc/hostname
/etc/hostname: file, 24 bytes
$ touch notes.txt; ./checkpath.sh notes.txt
notes.txt: empty file
$ ./checkpath.sh /etc/nologin; echo $?
/etc/nologin: not found
1
```

### Quoting and [[ ]]
- `[ ]` sees variables after word splitting
  - An empty variable disappears; a value with spaces becomes several words
  - Fix: quote every variable inside `[ ]`
- ==[[ ]]== is a bash keyword with safer rules
  - No word splitting, so unquoted variables are fine
  - `==` matches a glob pattern: `[[ $host == web* ]]`
  - `=~` matches an extended regex; captures go in `BASH_REMATCH`
  - `&&` and `||` work inside the brackets
- Use `[ ]` when a script must run under `sh`; `[[ ]]` needs bash

```bash label="q.sh"
#!/bin/bash
name=""
dir="My Files"
[ $name = alice ]
[ -d $dir ]
[[ $name = alice ]] || echo "[[ ]] copes"
host=web01.lab.example.com
[[ $host =~ ^web([0-9]+) ]] &&
  echo "web node ${BASH_REMATCH[1]}"
```

```console label="Terminal"
$ ./q.sh
./q.sh: line 4: [: =: unary operator expected
./q.sh: line 5: [: My: binary operator expected
[[ ]] copes
web node 01
```

### && and || chains
- ==AND list== `A && B`: run B only if A succeeded
- ==OR list== `A || B`: run B only if A failed
  - `[ -d /srv/backup ] || mkdir -p /srv/backup`
  - `grep -q '^alice:' /etc/passwd && echo "alice exists"`
- `A && B || C` is not a true if/else
  - C also runs when A succeeds but B fails
  - Use `if` when the middle command can fail

```console label="Terminal"
$ [ -d /srv/backup ] || sudo mkdir /srv/backup
$ [ -d /srv/backup ] && echo ready
ready
$ true && false || echo "C ran anyway"
C ran anyway
```

### case
- ==case== compares one value against glob patterns
  - Each pattern ends in `)`; each branch ends in `;;`
  - `a|b)` matches either; `*)` catches everything else
  - Closes with ==esac== (case spelled backward)
- Cleaner than a long `elif` chain on the same variable

```bash label="distro.sh"
#!/bin/bash
case "$1" in
  redhat)    echo "fedora" ;;
  fedora)    echo "redhat" ;;
  -h|--help) echo "Usage: $0 redhat|fedora" ;;
  *)         echo "Usage: $0 redhat|fedora" >&2
             exit 1 ;;
esac
```

```console label="Terminal"
$ ./distro.sh redhat
fedora
$ ./distro.sh fedora
redhat
$ ./distro.sh centos; echo $?
Usage: ./distro.sh redhat|fedora
1
```

:::exam
- A classic task: "Write a script that prints fedora when given redhat, prints redhat when given fedora, and otherwise prints a usage message to standard error." A `case` with a `*)` branch and an `exit 1` covers every path the grader tries, including no argument at all.
- `-eq` versus `=`: integers versus strings. `[ "$count" = 0 ]` fails for `00`; `-eq` treats both as zero.
- An unquoted empty variable inside `[ ]` produces "unary operator expected". Quote it or use `[[ ]]`.
:::

:::
