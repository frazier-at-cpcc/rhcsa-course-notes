### A script is a file of commands
- First line is the ==shebang==: `#!/bin/bash`
  - Tells the kernel which interpreter runs the rest of the file
  - Without it, the calling shell has to guess
- Make it ==executable== with `chmod +x` (or `chmod 755`)
  - Run it as `./name.sh` from its own directory
  - Or by bare name from a directory on `$PATH`
- `$PATH` on RHEL 10 already includes two places for scripts
  - `/usr/local/bin`: every user, owned by root
  - `~/bin` and `~/.local/bin`: added by the default `~/.bashrc`
- `bash name.sh` runs a file without the execute bit
  - Fine for testing; exam tasks name a path and expect an executable file there
- Scripts are files, so nothing extra is needed to survive a reboot
  - The grader checks the path, the mode, and what the script prints

### Positional parameters
- Arguments on the command line land in ==positional parameters==
  - `$1` is the first, `$2` the second, `${10}` needs braces past nine
- Special parameters the shell fills in for you

:::wide
| Parameter | Holds | Example value |
|---|---|---|
| `$0` | How the script was called | `./args.sh` |
| `$1` to `$9`, `${10}` | One argument each | `web server` |
| `$#` | Number of arguments | `3` |
| `"$@"` | Every argument, each kept as its own word | `"web server" "db" "cache"` |
| `"$*"` | Every argument joined into one string | `"web server db cache"` |
| `$?` | Exit status of the last command | `0` |
| `$$` | Process ID of the running script | Changes every run |
:::

```bash label="args.sh"
#!/bin/bash
echo "Called as: $0"
echo "Arg count: $#"
printf 'Arg: [%s]\n' "$@"
printf 'Star: [%s]\n' "$*"
shift
echo "After shift: $# left, \$1=$1"
```

```console label="Terminal"
$ ./args.sh "web server" db cache
Called as: ./args.sh
Arg count: 3
Arg: [web server]
Arg: [db]
Arg: [cache]
Star: [web server db cache]
After shift: 2 left, $1=db
```

- Quote `"$@"` whenever you pass the arguments on
  - Unquoted `$@` splits `web server` into two words
- ==shift== drops `$1` and moves every other argument down one place
  - `$#` drops by one each time; `shift 2` drops two
  - The usual way to walk through options one at a time

:::figure 3.1-shift.svg | shift discards the first argument and renumbers the rest, so the same code can always read $1.

### Capture command output
- ==Command substitution==: `$(command)` is replaced by the command's output
  - Store it: `today=$(date +%F)`
  - Trailing newlines are stripped
  - Backticks (`` `date` ``) are the old form; `$( )` nests cleanly
- Quote the result when it may hold spaces: `"$(...)"`
- ==Arithmetic expansion==: `$(( used + 5 ))` does integer math
- `${1:-/}` uses a default when the argument is missing or empty

```bash label="diskcheck.sh"
#!/bin/bash
# Report how full a file system is.
mount=${1:-/}
limit=${2:-80}
used=$(df --output=pcent "$mount" |
  tail -1 | tr -dc '0-9')
echo "$mount is ${used}% full (limit $limit%)"
[ "$used" -lt "$limit" ]
```

```console label="Terminal"
$ ./diskcheck.sh
/ is 66% full (limit 80%)
$ echo $?
0
$ ./diskcheck.sh / 5
/ is 66% full (limit 5%)
$ echo $?
1
```

- The last command's status becomes the script's status
  - Here the `[ ]` test (3.2) decides whether the script succeeds

### Exit codes and $?
- Every command returns an ==exit status== from 0 to 255
  - `0` means success; anything else is a failure code
- `$?` holds the status of the command that just finished
  - Read it right away: the next command, even `echo`, replaces it
- `exit N` ends the script with status `N`
  - Common habit: `1` for a failed lookup, `2` for bad usage
- Send error messages to ==standard error== with `>&2`
  - Keeps them out of pipes and `$(...)` captures

```bash label="userinfo.sh"
#!/bin/bash
# Show account details for one user.
if [ $# -ne 1 ]; then
  echo "Usage: $0 USERNAME" >&2
  exit 2
fi
entry=$(getent passwd "$1") || {
  echo "$0: no such user: $1" >&2
  exit 1
}
uid=$(cut -d: -f3 <<< "$entry")
home=$(cut -d: -f6 <<< "$entry")
echo "User:   $1 (UID $uid)"
echo "Home:   $home"
echo "Groups: $(id -nG "$1")"
```

```console label="Terminal"
$ ./userinfo.sh
Usage: ./userinfo.sh USERNAME
$ echo $?
2
$ ./userinfo.sh alice
User:   alice (UID 1001)
Home:   /home/alice
Groups: alice devops
$ ./userinfo.sh carol; echo "status $?"
./userinfo.sh: no such user: carol
status 1
```

- `cmd || { ...; exit 1; }` runs the block only when `cmd` fails
  - `getent` returns 2 for an unknown user, so the lookup doubles as the test

### Read input with read
- ==read== takes one line of standard input and stores it in variables
  - `read -r line`: `-r` keeps backslashes as typed; use it by default
  - `read -p "Owner: " owner` prints a prompt first
- Several names split the line on whitespace (`$IFS`)
  - The last variable gets whatever is left over
- Input can come from the keyboard, a pipe, a file, or a ==here-string== (`<<<`)
  - The `-p` prompt appears only when input is a terminal

```bash label="newproj.sh"
#!/bin/bash
# Create a shared project directory.
read -r -p "Project name: " name
read -r -p "Owning group: " group
dir=/srv/projects/$name
mkdir -p "$dir"
chgrp "$group" "$dir" && chmod 2770 "$dir"
stat -c '%A %U:%G %n' "$dir"
```

```console label="Terminal"
$ printf 'atlas\ndevops\n' | sudo ./newproj.sh
drwxrws--- root:devops /srv/projects/atlas
$ read -r first rest <<< "web db cache"
$ echo "$first / $rest"
web / db cache
```

- Piped input makes a script testable without typing at a prompt
  - Loops that read a whole file line by line are in 3.3

:::exam
- Tasks read like "Create a script /usr/local/bin/userinfo that takes a user name as its only argument." The grader runs it with good, bad, and missing arguments, so check `$#`, quote `"$1"`, and set the exit status the task asks for.
- `$?` is overwritten by every command. A script that runs `echo` or `[ ]` before checking `$?` is testing the wrong command.
- `"$@"` keeps each argument whole; `$*` and unquoted `$@` split arguments that contain spaces.
:::

:::
