### Two layers to grow
- The objective: ==extend existing logical volumes==
- An LV and the file system on it have separate sizes
  - ==`lvextend`== gives the LV more extents from its volume group
  - The file system keeps its old size until it is grown too
- Growing the file system uses its own tool
  - XFS: ==`xfs_growfs MOUNTPOINT`==, only while mounted
  - ext4: ==`resize2fs DEVICE`==, mounted or not
- ==`lvextend -r`== (`--resizefs`) runs the right tool for you, so one command does both
- Both grow online, with the file system mounted and in use

:::figure 6.3-extend-steps.svg | After step 1 the LV is bigger but df still shows the old size. The space only becomes usable once the file system is grown into it.

### Check the space first
- `df -h` shows the file system's size; `lvs` the LV's; `vgs` the free space left in the group
  - Here `vg_app` (one 1 GiB PV) holds an XFS LV on `/srv/web` and an ext4 LV on `/srv/logs`

:::wide
```console label="Terminal"
$ df -h /srv/web /srv/logs
Filesystem                  Size  Used Avail Use% Mounted on
/dev/mapper/vg_app-lv_web   336M   27M  310M   8% /srv/web
/dev/mapper/vg_app-lv_logs  272M   14K  253M   1% /srv/logs
$ sudo lvs vg_app; sudo vgs vg_app
  LV      VG     Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  lv_logs vg_app -wi-ao---- 300.00m
  lv_web  vg_app -wi-ao---- 400.00m
  VG     #PV #LV #SN Attr   VSize    VFree
  vg_app   1   2   0 wz--n- 1020.00m 320.00m
```
:::


### Growing XFS with lvextend -r
- Size the request one of four ways

| Option | Meaning |
|---|---|
| `-L 600M` | make the LV exactly 600 MiB |
| `-L +200M` | add 200 MiB to its current size |
| `-l +50` | add 50 extents |
| `-l +100%FREE` | take every free extent in the VG |

- Watch the ==plus sign==: `-L 200M` on a 400 MiB LV asks to shrink it, and `lvextend` refuses

:::wide
```console label="Terminal"
$ sudo lvextend -r -L +200M /dev/vg_app/lv_web
  File system xfs found on vg_app/lv_web mounted at /srv/web.
  Size of logical volume vg_app/lv_web changed from 400.00 MiB (100 extents) to 600.00 MiB (150 extents).
  Extending file system xfs to 600.00 MiB (629145600 bytes) on vg_app/lv_web...
xfs_growfs /dev/vg_app/lv_web
...
data blocks changed from 102400 to 153600
xfs_growfs done
  Extended file system xfs on vg_app/lv_web.
  Logical volume vg_app/lv_web successfully resized.
$ df -h /srv/web
Filesystem                 Size  Used Avail Use% Mounted on
/dev/mapper/vg_app-lv_web  536M   31M  506M   6% /srv/web
```
:::

- The `xfs_growfs` lines are `-r` at work (its geometry dump is trimmed); without `-r`, run `sudo xfs_growfs /srv/web` yourself

### Growing ext4
- Two steps
  - First the LV: `sudo lvextend -L 450M /dev/vg_app/lv_logs`
  - Then the file system: `sudo resize2fs /dev/vg_app/lv_logs` grows it to fill the LV
- Or one: `sudo lvextend -r -L 450M /dev/vg_app/lv_logs`, which calls `resize2fs` for ext4
- In the lab run, step 1 failed for lack of space (next section), so step 2 had nothing to grow into

```console label="Terminal"
$ sudo resize2fs /dev/vg_app/lv_logs
resize2fs 1.47.1 (20-May-2024)
The filesystem is already 307200 (1k) blocks long.  Nothing to do!
```

- That is the lesson: `resize2fs` only fills space the LV already has, and reports ==Nothing to do!== otherwise

### When the volume group is full
- ==`Insufficient free space`== comes from the volume group: it has fewer free extents than the request needs
  - After the XFS step only 30 extents (120 MiB) were free; `lv_logs` at 452 MiB needed 38
- Add a disk: partition it, `pvcreate`, then ==`vgextend`== the VG (objective 5.2); `-l +100%FREE` then takes all of it

:::wide
```console label="Terminal"
$ sudo lvextend -L 450M /dev/vg_app/lv_logs
  Rounding size to boundary between physical extents: 452.00 MiB.
  Insufficient free space: 38 extents needed, but only 30 available
$ sudo lvextend -r -L +500M /dev/vg_app/lv_web
  File system xfs found on vg_app/lv_web mounted at /srv/web.
  Insufficient free space: 125 extents needed, but only 30 available
$ sudo pvcreate /dev/vdc1
  Physical volume "/dev/vdc1" successfully created.
$ sudo vgextend vg_app /dev/vdc1
  Volume group "vg_app" successfully extended
$ sudo vgs vg_app
  VG     #PV #LV #SN Attr   VSize VFree
  vg_app   2   2   0 wz--n- 1.99g 1.11g
$ sudo lvextend -r -l +100%FREE /dev/vg_app/lv_web
  File system xfs found on vg_app/lv_web mounted at /srv/web.
  Size of logical volume vg_app/lv_web changed from 600.00 MiB (150 extents) to <1.70 GiB (435 extents).
...
  Logical volume vg_app/lv_web successfully resized.
$ df -h /srv/web
Filesystem                 Size  Used Avail Use% Mounted on
/dev/mapper/vg_app-lv_web  1.7G   54M  1.6G   4% /srv/web
```
:::

- `lv_web` now spans both PVs; nothing about the mount changed

### Shrinking, and persistence
- ==XFS cannot shrink==; `lvreduce -r` checks first and stops before touching anything
- ext4 can shrink, but only unmounted; the exam objective is about extending

```console label="Terminal"
$ sudo lvreduce -r -L 300M /dev/vg_app/lv_web
...
  File system reduce is required and not supported (xfs).
```

- The new sizes are stored on disk, in the LVM metadata and the file system, so they persist across reboots with nothing else to do
- The `/etc/fstab` line still matches: the UUID and the `/dev/vg_app/lv_web` path do not change when an LV grows

:::exam
- "Resize lv_web to 600 MiB" is graded on both layers: `lvs` for the LV and `df -h` for the file system. Without `-r` the file system stays at the old size.
- Sizes come with a tolerance ("between 570 and 630 MiB") because extents round. Read whether the task wants a total (`-L 600M`) or an increase (`-L +200M`).
- Out of space in the VG: add a PV with `vgextend`; never delete other LVs to make room.
:::

:::try
Create a 300 MiB logical volume with an ext4 file system, mounted persistently at /srv/logs. Extend it to 500 MiB with `lvextend` and `resize2fs`, then by another 100 MiB with `lvextend -r`. Confirm each step with `lvs` and `df -h`, then reboot and check again.
:::
