### Three file systems, one workflow
- The objective: ==create, mount, unmount, and use VFAT, ext4, and XFS file systems==
- Same four steps for all three
  - Make it on a partition or LV: `mkfs.<type>`
  - Make a mount point: `mkdir -p /mnt/data`
  - Attach it: `mount <device> <dir>`
  - Detach it: `umount <dir>` (or the device)
- ==XFS== is the RHEL default
  - The installer puts `/` and `/boot` on XFS
  - Grows online, never shrinks
- ==ext4== is the older Linux default
  - Grows online, shrinks only while unmounted
- ==VFAT== is for USB sticks and the EFI system partition
  - Readable by Windows and macOS
  - No Unix owners, modes, or SELinux labels

:::wide
| | VFAT | ext4 | XFS |
|---|---|---|---|
| Make it | `mkfs.vfat -n USBKEY` | `mkfs.ext4 -L homes` | `mkfs.xfs -L data` |
| Relabel | `fatlabel dev NEW` | `e2label dev new` | `xfs_admin -L new dev` (unmounted) |
| Inspect | `fatlabel dev` | `tune2fs -l dev` | `xfs_info dev` |
| Grow / shrink | no / no | yes / offline only | yes / never |
| Owners and modes | faked by mount options | stored per file | stored per file |
:::

### Making the file systems
- Spare disk `/dev/vdb` already holds three GPT partitions (objective 5.1)
- Each `mkfs` command sets a label at creation time
  - VFAT: ==`-n`== (11 characters, shown in upper case)
  - ext4 and XFS: ==`-L`==

```console label="Terminal"
$ sudo mkfs.vfat -n USBKEY /dev/vdb1
mkfs.fat 4.2 (2021-01-31)
$ sudo mkfs.ext4 -L homes /dev/vdb2
mke2fs 1.47.1 (20-May-2024)
Creating journal (4096 blocks): done
$ sudo mkfs.xfs -L data /dev/vdb3
Discarding blocks...Done.
```

- ==`lsblk -f`== confirms type, label, and UUID in one view
  - A VFAT UUID is a short serial such as `EF3A-95B3`

:::wide
```console label="Terminal"
$ lsblk -f /dev/vdb
NAME   FSTYPE FSVER LABEL  UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
vdb                                                                            
├─vdb1 vfat   FAT16 USBKEY EF3A-95B3                                           
├─vdb2 ext4   1.0   homes  e6902cca-6e94-4080-acbb-16928a75dbbb                
└─vdb3 xfs          data   bbb204e1-fab6-45eb-952b-257cdbdd2db7                
```
:::

- `mkfs.xfs` refuses to overwrite an existing file system
  - ==`-f`== forces it; read the device name twice before you add it

```console label="Terminal"
$ sudo mkfs.xfs /dev/vdb3
mkfs.xfs: /dev/vdb3 appears to contain an existing filesystem (xfs).
mkfs.xfs: Use the -f option to force overwrite.
```

### Mount, use, unmount
- `mount` detects the type; `-t vfat` is only needed when detection fails
- `df -hT` shows type, size, and use for each mount point
  - XFS reserves room for its log, so a new one is never 0% used

:::wide
```console label="Terminal"
$ sudo mkdir -p /mnt/usb /mnt/homes /mnt/data
$ sudo mount /dev/vdb1 /mnt/usb
$ sudo mount /dev/vdb2 /mnt/homes
$ sudo mount /dev/vdb3 /mnt/data
$ df -hT /mnt/usb /mnt/homes /mnt/data
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/vdb1      vfat  256M     0  256M   0% /mnt/usb
/dev/vdb2      ext4  488M   24K  452M   1% /mnt/homes
/dev/vdb3      xfs   448M   35M  414M   8% /mnt/data
$ ls /mnt/homes
lost+found
```
:::

- ext4 makes ==`lost+found`==; `fsck` drops recovered files there
- `findmnt -t vfat,ext4,xfs` lists only those types, with mount options
  - ext4 and XFS show ==`seclabel`==; VFAT does not, so every file on it gets one SELinux type
- `umount` fails while anything uses the file system
  - A shell sitting in the directory is enough

```console label="Terminal (a shell is in /mnt/data)"
$ sudo umount /mnt/data
umount: /mnt/data: target is busy.
```

- Find the holder: `fuser -vm /mnt/data` or `lsof /mnt/data`
  - `cd` out, close the file, or stop the service, then retry
- `findmnt /mnt/data` prints nothing and exits 1 once it is gone

### VFAT and ownership
- FAT has no owner or mode fields, so the kernel invents them at mount time
  - Everything belongs to the user who mounted it (root), mode from `fmask`/`dmask`
  - `chown` and `chmod` cannot change that

```console label="Terminal"
$ sudo cp /etc/hosts /mnt/usb/
$ ls -l /mnt/usb
total 4
-rwxr-xr-x. 1 root root 203 Oct 21 19:13 hosts
$ sudo chown student /mnt/usb/hosts
chown: changing ownership of '/mnt/usb/hosts': Operation not permitted
$ ls -l /mnt/usb/hosts
-rwxr-xr-x. 1 root root 203 Oct 21 19:13 /mnt/usb/hosts
```

- Set ownership with mount options instead
  - ==`uid=`==, ==`gid=`==, ==`umask=`== (or `fmask=` and `dmask=`)

```console label="Terminal"
$ sudo umount /mnt/usb
$ sudo mount -o uid=student,umask=022 \
  /dev/vdb1 /mnt/usb
$ ls -l /mnt/usb
total 4
-rwxr-xr-x. 1 student root 203 Oct 21 19:13 hosts
```

### Labels after the fact
- XFS: ==`xfs_admin -L`== works only on an unmounted file system
- ext4: ==`e2label`== (or `tune2fs -L`), mounted or not
- VFAT: ==`fatlabel dev NEWLABEL`==; with no new label it prints the current one
- `blkid -s LABEL` reads it back

```console label="Terminal"
$ sudo xfs_admin -L archive /dev/vdb3
writing all SBs
new label = "archive"
$ sudo blkid -s LABEL /dev/vdb3
/dev/vdb3: LABEL="archive"
$ sudo e2label /dev/vdb2 homes2
$ sudo blkid -s LABEL /dev/vdb2
/dev/vdb2: LABEL="homes2"
$ sudo fatlabel /dev/vdb1
USBKEY
$ sudo tune2fs -l /dev/vdb2 | grep -E 'volume name|Block count|Filesystem features'
Filesystem volume name:   homes2
Block count:              131072
```

- On RHEL 10, `xfs_info` also accepts an unmounted device

### Making it persist
- `mount` at the prompt is gone after a reboot; the exam reboots
- Add one line per file system to `/etc/fstab`, by UUID or label (objective 5.3)
  - `LABEL=archive /mnt/data xfs defaults 0 0`
  - `UUID=e6902cca-... /mnt/homes ext4 defaults 0 2`
  - `UUID=EF3A-95B3 /mnt/usb vfat uid=student,umask=022 0 0`
- Prove the line before rebooting
  - `systemctl daemon-reload`, `mount -a`, then `findmnt --verify`
  - A typo in fstab can drop the next boot into emergency mode
- A label you change later must be changed in fstab too

:::exam
- "Create a 512 MiB XFS file system labeled data and mount it persistently at /mnt/data" grades three things: the type, the label, and the mount after a reboot. Use `mkfs.xfs -L`, an fstab line, and `mount -a`.
- A VFAT task that names an owner needs `uid=` in the fstab options. `chown` on the mounted files fails.
- "target is busy" means a process holds the mount. `cd /` out of it before you unmount.
:::

:::try
On a spare disk, create a 256 MiB VFAT partition labeled USBKEY. Configure it to mount at /mnt/usb, owned by student, so that it persists across reboots. Reboot and check with `ls -l /mnt/usb`.
:::
