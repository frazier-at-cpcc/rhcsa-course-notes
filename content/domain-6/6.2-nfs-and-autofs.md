### The client side of NFS
- The objective: ==mount and unmount network file systems using NFS==; ==configure autofs==
- The exam provides the NFS server; every task is on the client
  - The server name, export path, and mount point are in the task text
- Client tools come from `nfs-utils`
- ==`showmount -e server`== lists the exports
  - It asks the server's `mountd`, an NFSv3 service
  - On a server that only speaks NFSv4 it fails; mount `server:/` and `ls` it to browse instead

```console label="Terminal"
$ showmount -e servera
Export list for servera:
/exports/guests   *
/exports/projects *
$ rpm -q nfs-utils
nfs-utils-2.8.3-5.el10.x86_64
```

### Mounting by hand
- `mount -t nfs server:/export /mountpoint`
  - The mount point must exist first
  - ==`-t nfs`== negotiates the highest version both sides support: ==NFS 4.2== here
  - Pin a version with `-o vers=4.2` or `-o vers=3` only when told to
- `nfsstat -m` lists each NFS mount with its full option list; among them
  - `hard`: a stalled server makes processes wait instead of failing writes
  - `proto=tcp` and `sec=sys` (trust the client's UID and GID numbers)

```console label="Terminal"
$ sudo mkdir -p /mnt/projects
$ sudo mount -t nfs servera:/exports/projects /mnt/projects
$ nfsstat -m | head -3
/mnt/projects from servera:/exports/projects
 Flags:	rw,relatime,vers=4.2,rsize=524288,...
$ ls -l /mnt/projects; cat /mnt/projects/plan.txt
total 4
-rw-r--r--. 1 root root 15 Oct 21 18:56 plan.txt
quarterly plan
$ sudo umount /mnt/projects
```

- Unmount works like a local file system
  - `target is busy` means a shell or process is still inside it

### Mounting at boot with /etc/fstab
- One fstab line: ==server:/export==, mount point, `nfs`, options, `0 0`
  - The last two fields stay 0: no dump, and `fsck` has nothing to check on a network share
- ==`_netdev`== marks the mount as needing the network
  - systemd mounts it under `remote-fs.target`, after the network is up
  - systemd already treats type `nfs` as remote; `_netdev` makes the intent explicit and costs nothing
- Test before the reboot: `systemctl daemon-reload`, then `mount -a`

```console label="Terminal"
$ echo 'servera:/exports/projects  /mnt/projects  nfs  defaults,_netdev  0 0' \
  | sudo tee -a /etc/fstab
servera:/exports/projects  /mnt/projects  nfs  defaults,_netdev  0 0
$ sudo systemctl daemon-reload
$ sudo mount -a
```

- `findmnt /mnt/projects` then shows the `nfs4` mount (output under "After a reboot")

- fstab mounts stay attached all the time; autofs mounts only when someone looks

### autofs: an indirect map
- The `autofs` service runs ==automount==, which mounts a share the moment a path under it is accessed
  - Unused shares are unmounted after the ==timeout== (300 seconds by default)
  - No boot delay and no hung boot when the server is down
- Two files
  - The ==master map==: `/etc/auto.master`, plus drop-ins named `/etc/auto.master.d/*.autofs`
  - A ==map file==: one line per key, with mount options and the share
- An ==indirect map== manages one parent directory
  - Master line: `/shares  /etc/auto.shares`
  - Map line: `projects  -rw,sync  servera:/exports/projects`
  - Result: `/shares/projects` is the mount point; autofs creates it, so do not `mkdir` it

```console label="Terminal"
$ rpm -q autofs
autofs-5.1.9-13.el10.x86_64
$ echo '/shares  /etc/auto.shares' \
  | sudo tee /etc/auto.master.d/shares.autofs
/shares  /etc/auto.shares
$ echo 'projects  -rw,sync  servera:/exports/projects' \
  | sudo tee /etc/auto.shares
projects  -rw,sync  servera:/exports/projects
$ sudo systemctl enable --now autofs
$ ls /shares
$ ls /shares/projects
plan.txt
```

- ==`ls /shares` shows nothing== and that is correct
  - `browse_mode = no` in `/etc/autofs.conf` hides keys until they are used
  - Test by naming the full path: `ls /shares/projects` or `cd` into it
- After editing a map, `systemctl reload autofs`
- A ==direct map== uses `/-` in the master map; its keys are full paths such as `/mnt/docs`

:::figure wide 6.2-autofs.svg | The master map hands a directory to a map file. Nothing is mounted until a path under it is used, and an idle share is unmounted again.

### autofs: a wildcard map
- ==`*`== as the key matches any name looked up under the parent directory
- ==`&`== in the location is replaced by that name
  - `/home/guests/alice` mounts `servera:/exports/guests/alice`
  - One line covers every user's network home directory

```console label="Terminal"
$ echo '/home/guests  /etc/auto.guests' \
  | sudo tee /etc/auto.master.d/guests.autofs
/home/guests  /etc/auto.guests
$ echo '*  -rw,sync  servera:/exports/guests/&' \
  | sudo tee /etc/auto.guests
*  -rw,sync  servera:/exports/guests/&
$ sudo systemctl reload autofs
$ cat /home/guests/alice/notes.txt
alice notes
$ ls /home/guests
alice
$ grep -E '^(timeout|browse_mode)' /etc/autofs.conf
timeout = 300
browse_mode = no
```

- After the lookup, `alice` shows up in `ls`; bob's directory stays hidden until something uses it
- A per-map timeout goes in the master line: `/home/guests /etc/auto.guests --timeout=600`

### After a reboot
- The fstab share is mounted again by systemd
- autofs comes back only because it was ==enabled==; `enable --now` also started it for this boot

:::wide
```console label="Terminal (after reboot)"
$ findmnt /mnt/projects
TARGET        SOURCE                    FSTYPE OPTIONS
/mnt/projects servera:/exports/projects nfs4   rw,relatime,vers=4.2,...
$ systemctl is-enabled autofs; systemctl is-active autofs
enabled
active
$ ls /shares/projects; cat /home/guests/alice/notes.txt
plan.txt
alice notes
```
:::

:::exam
- "Configure autofs so that remoteuser's home directory, /rhome/remoteuser, is mounted from servera:/rhome/remoteuser" is a master line for `/rhome` plus a map. Use `*` and `&` when every user needs one.
- An empty `ls` of the autofs parent directory is not a failure. Access the full path, and remember to `systemctl enable` autofs or the grader finds nothing after its reboot.
- For a permanent NFS mount, the fstab line needs the type `nfs` and `_netdev`. Run `mount -a` to catch typos.
:::

:::try
Assume servera exports /exports/projects. Configure autofs on your client so that /shares/projects mounts that export read-write on access, and so that the configuration persists across reboots. Reboot, then run `ls /shares/projects`.
:::
