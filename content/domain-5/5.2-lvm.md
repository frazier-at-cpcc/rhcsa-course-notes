### The layers
- The objective: ==create and remove physical volumes; assign physical volumes to volume groups; create and delete logical volumes==
- ==LVM== puts a flexible layer between disks and file systems
  - Grow a volume later, add a disk to a full pool, or move data off a disk, all without repartitioning
- ==Physical volume (PV)==: a partition or whole disk that `pvcreate` has labeled for LVM
- ==Volume group (VG)==: a pool built from one or more PVs
  - The pool is cut into equal ==physical extents (PEs)==, 4 MiB unless `vgcreate -s` says otherwise
- ==Logical volume (LV)==: a block device made of extents taken from the pool
  - Its extents can come from any PV in the group, so one LV can span two disks
  - File systems and swap go on the LV, exactly as they would on a partition

:::figure wide 5.2-lvm-layers.svg | Each layer is made from the one above it. The volume group hides which disk an extent lives on: lv_db takes some extents from vdb1 and the rest from vdc1.

- An LV has two equivalent names, both links to a `/dev/dm-N` device
  - `/dev/vg_data/lv_db` and `/dev/mapper/vg_data-lv_db` (in the lab both pointed at `../dm-1`)

:::wide
| Layer | Create | List | Details | Remove |
|---|---|---|---|---|
| PV | `pvcreate /dev/vdb1` | `pvs` | `pvdisplay` | `pvremove` |
| VG | `vgcreate vg_data /dev/vdb1`, `vgextend` | `vgs` | `vgdisplay` | `vgreduce` (one PV), `vgremove` |
| LV | `lvcreate -n lv_web -L 500M vg_data` | `lvs` | `lvdisplay` | `lvremove` |
:::

### Physical volumes
- Give LVM a partition with the ==`lvm` flag== (objective 5.1), or a whole unpartitioned disk
- ==`pvcreate`== writes the LVM label; one command can take several devices
- `pvs` is the one-line-per-PV summary; `pvdisplay` the long form
  - A PV that belongs to no VG shows an empty `VG` column and `Allocatable NO`

```console label="Terminal"
$ sudo parted -s /dev/vdb mklabel gpt mkpart lvm1 1MiB 100% set 1 lvm on
$ sudo pvcreate /dev/vdb1 /dev/vdc1
  Physical volume "/dev/vdb1" successfully created.
  Physical volume "/dev/vdc1" successfully created.
$ sudo pvs
  PV         VG Fmt  Attr PSize  PFree
  /dev/vdb1     lvm2 ---  <5.00g <5.00g
  /dev/vdc1     lvm2 ---  <5.00g <5.00g
$ sudo pvdisplay /dev/vdb1
  --- NEW Physical volume ---
  PV Name               /dev/vdb1
  VG Name
  PV Size               <5.00 GiB
  Allocatable           NO
  PE Size               0
```

- RHEL 10 keeps a list of the devices LVM may use, the ==LVM devices file== `/etc/lvm/devices/system.devices`
  - On by default (`use_devicesfile=1` in `lvm.conf`); disks missing from it are ignored by every LVM command
  - `pvcreate`, `vgcreate`, and `vgextend` add their devices automatically
  - `lvmdevices` lists it, `lvmdevices --adddev` and `--deldev` change it; never edit the file by hand
  - `vgimportdevices vg_name` adds a VG's disks, for example after moving disks from another system

### Volume groups
- ==`vgcreate NAME PV...`== builds the pool; `-s 8M` sets the extent size
  - The extent size is fixed for the VG's life; every LV size is a whole number of extents
- `vgcreate` runs `pvcreate` itself if a device is not a PV yet
- ==`vgextend`== adds another PV to an existing group

```console label="Terminal"
$ sudo vgcreate -s 8M vg_data /dev/vdb1
  Volume group "vg_data" successfully created
$ sudo vgdisplay vg_data | grep -E 'VG Name|PE Size|Total PE|Free  PE'
  VG Name               vg_data
  PE Size               8.00 MiB
  Total PE              639
  Free  PE / Size       639 / 4.99 GiB
$ sudo vgextend vg_data /dev/vdc1
  Volume group "vg_data" successfully extended
$ sudo vgs vg_data
  VG      #PV #LV #SN Attr   VSize VFree
  vg_data   2   0   0 wz--n- 9.98g 9.98g
```

### Logical volumes
- ==`lvcreate -n NAME`== plus a size, then the VG name
  - ==`-L`== takes a size (`500M`, `2G`); LVM rounds up to a whole extent and says so
  - ==`-l`== takes extents (`-l 40`) or a percentage (`-l 50%FREE`, `-l 100%VG`)
- An exam task that gives a size in extents ("40 extents of 8 MiB") wants `vgcreate -s 8M` and `lvcreate -l 40`

:::wide
```console label="Terminal"
$ sudo lvcreate -n lv_web -L 500M vg_data
  Rounding up size to full physical extent 504.00 MiB
  Logical volume "lv_web" created.
$ sudo lvcreate -n lv_db -l 40 vg_data
  Logical volume "lv_db" created.
$ sudo lvcreate -n lv_rest -l 50%FREE vg_data
  Logical volume "lv_rest" created.
$ sudo lvs
  LV      VG      Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  lv_db   vg_data -wi-a----- 320.00m
  lv_rest vg_data -wi-a-----  <4.59g
  lv_web  vg_data -wi-a----- 504.00m
$ sudo lvcreate -n lv_big -L 20G vg_data
  Volume group "vg_data" has insufficient free space (588 extents): 2560 required.
```
:::

- `lv_db` is 40 extents of 8 MiB, so 320 MiB
- `lvdisplay` shows the same numbers in long form: `LV Size 320.00 MiB`, `Current LE 40`
- In the `Attr` column, `a` means active; an `o` appears once the LV is mounted or in use

### Removing LVs, VGs, and PVs
- Work from the top down: file system, then LV, then VG, then PV
  - `umount` and remove the `/etc/fstab` line first
- ==`lvremove`== deletes one LV, or every LV in a VG when given only the VG name; `-y` skips the question
- To take one disk out of a VG that stays in use
  - ==`pvmove`== migrates its extents to the other PVs (it needs free space there)
  - ==`vgreduce`== drops the empty PV from the group
  - `pvremove` wipes its LVM label
- `vgremove` deletes the group once it has no LVs left

```console label="Terminal"
$ sudo lvremove -y vg_data/lv_rest
  Logical volume "lv_rest" successfully removed.
$ sudo pvmove /dev/vdc1
  No data to move for vg_data.
$ sudo vgreduce vg_data /dev/vdc1
  Removed "/dev/vdc1" from volume group "vg_data"
$ sudo pvremove /dev/vdc1
  Labels on physical volume "/dev/vdc1" successfully wiped.
$ sudo lvremove -y vg_data
  Logical volume "lv_web" successfully removed.
  Logical volume "lv_db" successfully removed.
$ sudo vgremove vg_data
  Volume group "vg_data" successfully removed
$ sudo pvremove /dev/vdb1
  Labels on physical volume "/dev/vdb1" successfully wiped.
$ sudo pvs; sudo vgs
```

- `pvmove` exited with an error here because `lv_rest` had been the only LV on `vdc1`; nothing was left to move
- The empty output of `pvs` and `vgs` at the end is the proof that nothing remains
- LVM metadata lives on the PVs themselves, so PVs, VGs, and LVs survive a reboot with no extra step; only the mount needs `/etc/fstab`

:::exam
- Read the size unit carefully. "A volume group with 16 MiB extents" and "a logical volume of 50 extents" means `vgcreate -s 16M` and `lvcreate -l 50`; `-L 50M` is a different answer.
- Exact names matter: the grader looks for the VG and LV names the task gives, under `/dev/VG/LV`.
- Deleting is graded too. If an LV is in `/etc/fstab` and you remove it without removing the line, the next boot stops in emergency mode.
:::
