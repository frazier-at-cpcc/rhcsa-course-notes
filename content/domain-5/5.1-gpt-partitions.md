### Listing disks and partitions
- The objective: ==list, create, and delete partitions on GPT disks==
- ==`lsblk`== draws the tree of disks, partitions, and what sits on them
  - `TYPE` is `disk` or `part`; `MOUNTPOINTS` shows where each is in use
  - The lab system boots from `vda`; `vdb` and `vdc` are blank spares
- `parted /dev/vdb print` and `fdisk -l /dev/vdb` show the partition table
  - A brand-new disk has no label yet: `Partition Table: unknown`

```console label="Terminal"
$ lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sr0     11:0    1    4M  0 rom
vda    252:0    0   20G  0 disk
├─vda1 252:1    0    2M  0 part
├─vda2 252:2    0  200M  0 part /boot/efi
├─vda3 252:3    0 1000M  0 part /boot
└─vda4 252:4    0 18.8G  0 part /
vdb    252:16   0    5G  0 disk
vdc    252:32   0    5G  0 disk
$ sudo parted /dev/vdb print
Error: /dev/vdb: unrecognised disk label
Model: Virtio Block Device (virtblk)
Disk /dev/vdb: 5369MB
...
Partition Table: unknown
Disk Flags:
```

### GPT and MBR
- The ==partition table== (disk label) is the map at the start of a disk that says where each partition begins and ends
- ==GPT== is the current format and the one this objective names
  - UEFI firmware boots from a GPT disk through an EFI System Partition (`vda2` above, mounted on `/boot/efi`)
- ==MBR== (`msdos` in parted, `dos` in fdisk) is the older format; know it to recognize it

:::wide
| | GPT | MBR (msdos) |
|---|---|---|
| Partitions | 128 by default, all equal | 4 primary, or 3 primary plus an extended one that holds logical partitions |
| Largest disk | far beyond any real disk | 2 TiB with 512-byte sectors |
| Copies of the table | primary at the start, backup at the end | one, in the first sector |
| Partition type | a GUID (Linux filesystem, Linux LVM, Linux swap) | a one-byte code (`83`, `8e`, `82`) |
| Partition names | yes (`data`, `logs`) | no |
| New table | `parted DISK mklabel gpt`, fdisk `g` | `parted DISK mklabel msdos`, fdisk `o` |
:::

- `mklabel` on a disk that already has partitions throws away the whole map
  - Only ever run it on a disk you were told is blank

### Creating partitions with parted
- ==`parted`== works from the command line, one action per call; changes are written immediately (there is no "save" step)
- `mklabel gpt` writes an empty GPT
- `mkpart NAME FSTYPE START END` adds a partition
  - On GPT the first word is the partition's ==name==
  - `FSTYPE` (`xfs`, `ext4`, `linux-swap`) only sets the type hint; it does not format anything
  - Give `START` and `END` in `MiB` so partitions line up on 1 MiB boundaries; `100%` means the end of the disk
- `-s` (script mode) never prompts, handy for one-liners
- The `Information: You may need to update /etc/fstab.` line after every change is only a reminder
- `parted` defaults to decimal units (MB); add `unit MiB` to read sizes the way you typed them
- ==`print free`== shows the gaps, which is where the next partition goes

:::wide
```console label="Terminal"
$ sudo parted /dev/vdb mklabel gpt
Information: You may need to update /etc/fstab.
$ sudo parted /dev/vdb mkpart data xfs 1MiB 1025MiB
$ sudo parted /dev/vdb mkpart logs ext4 1025MiB 1537MiB
$ sudo parted -s /dev/vdb unit MiB print free
...
Partition Table: gpt
Disk Flags:

Number  Start    End      Size     File system  Name  Flags
        0.02MiB  1.00MiB  0.98MiB  Free Space
 1      1.00MiB  1025MiB  1024MiB               data
 2      1025MiB  1537MiB  512MiB                logs
        1537MiB  5120MiB  3583MiB  Free Space
```
:::

### Partition types and flags
- A partition meant for LVM or swap should carry the matching ==type==
- In parted the type is a ==flag==: `set 2 lvm on`, `set 3 swap on`
- `fdisk -l` shows the same thing in its `Type` column
- Behind each type name is a GUID; `blkid -p` reads it from the partition entry

:::wide
```console label="Terminal"
$ sudo parted /dev/vdb set 2 lvm on
$ sudo parted /dev/vdb print | tail -4
Number  Start   End     Size    File system  Name  Flags
 1      1049kB  1075MB  1074MB               data
 2      1075MB  1612MB  537MB                logs  lvm
$ sudo fdisk -l /dev/vdb | tail -3
Device       Start     End Sectors  Size Type
/dev/vdb1     2048 2099199 2097152    1G Linux filesystem
/dev/vdb2  2099200 3147775 1048576  512M Linux LVM
$ sudo blkid -p -s PART_ENTRY_NAME -s PART_ENTRY_TYPE /dev/vdb1 /dev/vdb2
/dev/vdb1: PART_ENTRY_NAME="data" PART_ENTRY_TYPE="0fc63daf-8483-4772-8e79-3d69d8477de4"
/dev/vdb2: PART_ENTRY_NAME="logs" PART_ENTRY_TYPE="e6d6d379-f507-44c2-a23c-238f2a3df928"
```
:::

### Deleting a partition
- `parted DISK rm N` removes partition N at once, without a confirmation
- Before deleting, take it out of service
  - `umount` it, and delete its line from `/etc/fstab`
  - `swapoff` it if it is swap; `vgreduce` and `pvremove` it if it is an LVM physical volume
- GPT does not renumber: after `rm 2`, partition 1 stays `vdb1`
- `udevadm settle` waits for udev to finish updating `/dev`, so `lsblk` shows the change

```console label="Terminal"
$ sudo parted /dev/vdb rm 2
$ sudo udevadm settle; lsblk /dev/vdb
NAME   MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
vdb    252:16   0   5G  0 disk
└─vdb1 252:17   0   1G  0 part
$ sudo parted /dev/vdb rm 1
$ sudo parted /dev/vdb print | tail -3

Number  Start  End  Size  File system  Name  Flags
```

### fdisk
- ==`fdisk`== is menu driven: single-letter commands, and nothing reaches the disk until ==`w`==
  - `q` quits and discards every change, a safe way out of a mistake
  - Pressing Enter takes the default: next free number, first free sector

| Key | Action |
|---|---|
| `p` | print the table in memory |
| `g` | new empty GPT (`o` for MBR) |
| `n` | new partition: number, first sector, last sector or `+512M` |
| `t` | change type; `L` lists types and aliases such as `lvm` and `swap` |
| `d` | delete a partition |
| `w` | write and exit |

```console label="Terminal (keys g n 1 Enter +512M w)"
$ printf 'g\nn\n1\n\n+512M\nw\n' | sudo fdisk /dev/vdb | tail -6
Created a new partition 1 of type 'Linux filesystem' and of size 512 MiB.

Command (m for help): The partition table has been altered.
Calling ioctl() to re-read partition table.
Syncing disks.
$ sudo partprobe /dev/vdb; echo $?
0
```

- ==`partprobe`== asks the kernel to reread a table; use it when `lsblk` does not show a partition you just wrote

:::exam
- "Create a 512 MiB partition on /dev/vdb" usually feeds a later task (a file system, a PV, swap). Check `lsblk` first, use free space, and never relabel a disk that holds partitions.
- Sizes are graded with a tolerance. Use `MiB` in parted or `+512M` in fdisk to land close.
- The table survives a reboot by itself; what is checked after reboot is what you built on it, so finish with its `/etc/fstab` line (objective 5.3).
:::

:::try
On a spare disk, create a GPT label and two partitions: a 1 GiB partition named data and a 512 MiB partition flagged for LVM. Confirm both with `lsblk` and `fdisk -l`, then delete the second one and confirm the first keeps its number.
:::
