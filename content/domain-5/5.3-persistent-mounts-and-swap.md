### Adding storage non-destructively
- The objective: ==configure systems to mount file systems at boot by UUID or label; add new partitions, logical volumes, and swap to a system non-destructively==
- ==Non-destructively==: existing partitions, data, and mounts still work afterward
  - New partitions go in the free space that `parted DISK unit MiB print free` shows; never `mklabel` a disk in use
  - New LVs come from free extents in a VG, or from a PV added with `vgextend`
- Here `/dev/vdb` is blank, so it gets a fresh GPT, three partitions, and two labeled file systems

```console label="Terminal"
$ sudo parted -s /dev/vdb mklabel gpt
$ sudo parted -s /dev/vdb mkpart archive xfs 1MiB 513MiB
$ sudo parted -s /dev/vdb mkpart scratch ext4 513MiB 769MiB
$ sudo parted -s /dev/vdb mkpart swap1 linux-swap 769MiB 1281MiB
$ sudo mkfs.xfs -q -L archive /dev/vdb1
$ sudo mkfs.ext4 -q -L scratch /dev/vdb2
```

### UUIDs and labels
- Names such as `/dev/vdb1` follow discovery order and can change when a disk is added or removed
- A ==UUID== is generated when the file system (or swap area) is created
  - Unique, never changes until you reformat; the safest way to name a device in `/etc/fstab`
- A ==label== is a short name you choose: `mkfs.xfs -L archive`, `mkfs.ext4 -L scratch`, `mkswap -L swap1`
  - Readable, but two disks carrying the same label is a conflict nothing warns you about
  - Set or change one later: `xfs_admin -L` (unmounted XFS), `e2label`, `swaplabel -L`
- Find both with ==`blkid`== or ==`lsblk -f`== (its output is at the end of this topic)
  - `blkid -s UUID -o value DEVICE` prints the bare UUID, handy inside a command
  - `PARTUUID` and `PARTLABEL` belong to the GPT partition itself and also work in fstab

### The /etc/fstab line
- One line per file system or swap area, six fields separated by spaces or tabs

| Field | Typical values |
|---|---|
| 1 Device | `UUID=...`, `LABEL=...`, `/dev/vg_swap/lv_swap` |
| 2 Mount point | `/archive`; `none` for swap |
| 3 Type | `xfs`, `ext4`, `vfat`, `swap` |
| 4 Options | `defaults`, `nofail`, `_netdev` |
| 5 Dump | `0` (legacy backup flag) |
| 6 Check order | `0` for XFS and swap, `2` for ext4 data |

- At boot, ==systemd-fstab-generator== turns every line into a `.mount` or `.swap` unit
  - After editing fstab, run ==`systemctl daemon-reload`== so systemd rebuilds those units
- A line whose device cannot be found makes systemd wait, then drop the boot to ==emergency mode==
  - `nofail` lets boot continue without that mount (useful for removable or optional disks)

:::wide
```console label="Terminal"
$ tail -5 /etc/fstab
UUID=D779-42D2 /boot/efi vfat defaults,umask=0077,shortname=winnt 0 0
UUID=4d6895ec-307a-45a4-8ecd-d022bdad5511  /archive  xfs  defaults  0 0
LABEL=scratch  /scratch  ext4  defaults  0 2
UUID=21fbd978-63a3-408d-b49c-414baef4654d  none  swap  defaults  0 0
/dev/vg_swap/lv_swap  none  swap  defaults  0 0
```
:::

- The lab appended each line with `echo "..." | sudo tee -a /etc/fstab`; editing with `vim` works the same
  - `sudo echo "..." >> /etc/fstab` fails: the redirection runs in your shell, without root

### Test before you reboot
- ==`findmnt --verify`== parses fstab and checks every source, target, and type
- ==`mount -a`== mounts everything listed that is not mounted yet; an error here is an error at boot
- Both catch a typo in the UUID, a missing mount point, and a forgotten `daemon-reload`

:::wide
```console label="Terminal"
$ sudo mkdir -p /archive /scratch
$ sudo systemctl daemon-reload
$ sudo findmnt --verify
Success, no errors or warnings detected
$ sudo mount -a
$ df -hT /archive /scratch
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/vdb1      xfs   448M   35M  414M   8% /archive
/dev/vdb2      ext4  230M   14K  214M   1% /scratch
```
:::

:::wide
```console label="Terminal (a deliberate mistake)"
$ echo 'UUID=0000-bad  /broken  xfs  defaults  0 0' | sudo tee -a /etc/fstab
$ sudo findmnt --verify

0 parse errors, 2 errors, 1 warning
/broken
   [E] unreachable on boot required target: No such file or directory
   [E] unreachable on boot required source: UUID=0000-bad
   [W] your fstab has been modified, but systemd still uses the old version;
       use 'systemctl daemon-reload' to reload
$ sudo sed -i '/0000-bad/d' /etc/fstab; sudo systemctl daemon-reload; sudo findmnt --verify
Success, no errors or warnings detected
```
:::

### Adding swap
- ==Swap==: disk space for when RAM runs short, on a partition or an LV
- ==`mkswap`== writes the swap signature and prints the UUID
- ==`swapon`== activates it now; `swapon -a` activates every fstab line of type `swap` (mount point `none`)
- Check with `swapon --show`; an LV appears as its `dm-N` device

```console label="Terminal"
$ sudo mkswap -L swap1 /dev/vdb3
Setting up swapspace version 1, size = 512 MiB (536866816 bytes)
LABEL=swap1, UUID=21fbd978-63a3-408d-b49c-414baef4654d
$ sudo swapon /dev/vdb3
```

- A swap LV is the same; `vgcreate` also made `vdc1` a PV

```console label="Terminal"
$ sudo vgcreate vg_swap /dev/vdc1
  Physical volume "/dev/vdc1" successfully created.
  Volume group "vg_swap" successfully created
$ sudo lvcreate -n lv_swap -L 256M vg_swap
  Logical volume "lv_swap" created.
$ sudo mkswap /dev/vg_swap/lv_swap
Setting up swapspace version 1, size = 256 MiB (268431360 bytes)
no label, UUID=89ea5f35-bb46-4900-9742-90918ae7bd9a
$ sudo systemctl daemon-reload; sudo swapon -a
$ swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/vdb3 partition 512M   0B   -2
/dev/dm-0 partition 256M   0B   -3
```


### After a reboot
- Reboot, then check that every mount and swap area came back on its own

:::wide
```console label="Terminal (after reboot)"
$ lsblk -f /dev/vdb /dev/vdc
NAME                FSTYPE      FSVER    LABEL   UUID                                   FSAVAIL FSUSE% MOUNTPOINTS
vdb
├─vdb1              xfs                  archive 4d6895ec-307a-45a4-8ecd-d022bdad5511    413.5M     8% /archive
├─vdb2              ext4        1.0      scratch 55ed48f6-d32b-455a-a54d-d0636160c071    213.1M     0% /scratch
└─vdb3              swap        1        swap1   21fbd978-63a3-408d-b49c-414baef4654d                  [SWAP]
vdc
└─vdc1              LVM2_member LVM2 001         oAN0Wv-ElpQ-fou3-lDvO-4JVa-yhGp-9rc7os
  └─vg_swap-lv_swap swap        1                89ea5f35-bb46-4900-9742-90918ae7bd9a                  [SWAP]
```
:::

:::exam
- "Mount persistently by UUID": a `UUID=` line in `/etc/fstab`. A plain `mount` is gone after the grader reboots.
- "Add swap without affecting existing swap": new partition or LV, `mkswap`, fstab line, `swapon -a`.
- Run `findmnt --verify` and `mount -a` before rebooting; a bad line can stop the boot.
:::

:::
