### Create files and directories
- The objective: ==create, delete, copy, and move files and directories==; ==create hard and soft links==
- `touch file`: creates an empty file, or updates the timestamp of one that exists
- `mkdir dir`: one directory, and its parent must already exist
- ==`mkdir -p`== builds the whole path and is silent if it already exists
  - Brace expansion builds several at once: `mkdir -p projects/{app,db}/logs`

```console label="Root shell"
$ mkdir projects/web/conf
mkdir: cannot create directory 'projects/web/conf': No such file or directory
$ mkdir -p projects/web/conf
$ mkdir -p projects/{app,db}/logs
$ tree projects | tail -1
7 directories, 0 files
```

### Copy and move
- `cp src dest` copies one file; `cp a b c dir/` copies several into a directory
- Directories need ==`-r`== (recursive)
  - `cp: -r not specified; omitting directory 'projects'`
  - If the destination directory already exists, the copy lands inside it: `cp -r projects /tmp/projects` makes `/tmp/projects/projects`
- A plain `cp` makes a new file owned by you, with the current time
- ==`cp -a`== (archive) keeps owner, group, mode, timestamps, and links
  - Use it for configuration backups

```console label="Root shell"
$ cp site.conf plain.conf
$ cp -a site.conf arch.conf
$ ls -l *.conf
-rw-r----- 1 alice devops 10 Jan 15  2025 arch.conf
-rw-r----- 1 root  root   10 Oct 21 17:21 plain.conf
-rw-r----- 1 alice devops 10 Jan 15  2025 site.conf
```

- `mv` moves and renames; there is no separate rename command
  - `mv site.conf web.conf` renames in place
  - Within one file system, mv only rewrites the directory entry: the inode number stays the same
  - Across file systems, mv copies then deletes, so the file gets a new inode

### Delete
- `rm file`; `rm -r dir` for a directory and everything under it
  - `-f` never prompts and ignores missing files; there is no recycle bin
- `rmdir dir` removes only an empty directory
  - Otherwise: `rmdir: failed to remove 'projects': Directory not empty`
- Root's shell asks before it overwrites or deletes
  - `/root/.bashrc` on RHEL defines `alias rm='rm -i'`, plus the same for `cp` and `mv`
  - A root `rm` prompts; a regular user's does not

### Inodes and hard links
- An ==inode== holds everything about a file except its name
  - Type, mode, owner, size, timestamps, and where the data blocks are
- A directory is a list of name-to-inode entries
  - `ls -i` shows the inode number
- A ==hard link== is a second name for the same inode
  - `ln httpd.conf backup.conf`
  - Both names are equal; neither is "the original"
  - The ==link count== (second column of `ls -l`) counts the names
- Write through one name and the other sees it
- `rm` removes a name and lowers the count; the data is freed only when the count reaches 0
  - After `rm httpd.conf`, `backup.conf` still holds both lines with a count of 1

:::figure wide 1.6-inodes-and-links.svg | Hard links are extra names on one inode. A soft link is its own small file whose content is a path.

:::wide
```console label="Root shell"
$ ln httpd.conf backup.conf
$ ls -li httpd.conf backup.conf
1738341 -rw-r--r-- 2 root root 10 Oct 21 17:06 backup.conf
1738341 -rw-r--r-- 2 root root 10 Oct 21 17:06 httpd.conf
$ echo "Listen 8080" >> backup.conf
$ cat httpd.conf
Listen 80
Listen 8080
```
:::

- Two limits
  - Same file system only: `Invalid cross-device link`
  - No hard links to directories: `hard link not allowed for directory`
- Directories still show counts above 1
  - Each subdirectory's `..` entry points back at the parent, so `projects` with three subdirectories shows 5

### Soft links
- A ==soft link== (==symbolic link==) is a small file of type `l` that stores a path
  - `ln -s target linkname`: target first, like `cp`
  - Has its own inode; `ls -l` shows `linkname -> target`
- Works across file systems and for directories
- If the target is renamed or removed, the link ==dangles==
  - Reading it fails; `find -xtype l` lists the broken ones

:::wide
```console label="Root shell"
$ ln -s httpd.conf current.conf
$ ls -li httpd.conf current.conf
1738722 lrwxrwxrwx 1 root root 10 Oct 21 17:06 current.conf -> httpd.conf
1738690 -rw-r--r-- 1 root root 10 Oct 21 17:06 httpd.conf
$ mv httpd.conf httpd.conf.bak
$ cat current.conf
cat: current.conf: No such file or directory
$ find . -xtype l
./current.conf
```
:::

- A relative target is resolved from the ==link's directory==; where you ran `ln` does not matter
  - In /root/lab, `ln -s httpd.conf /tmp/web.conf` makes a link that looks for `/tmp/httpd.conf`
  - Use an absolute target when the link lives elsewhere: `ln -s /root/lab/httpd.conf /tmp/web.conf`
  - `ln -sf` replaces an existing link
- Removing a link never touches the target
  - `rm webdir` removes the link; `projects/web` is still there
- `readlink -f link` prints the fully resolved path

:::wide
| | Hard link | Soft link |
|---|---|---|
| Command | `ln target name` | `ln -s target name` |
| Inode | same as the target | its own |
| Across file systems | no | yes |
| To a directory | no | yes |
| Target deleted | data survives under the other name | link dangles |
| `ls -l` shows | a link count above 1 | `l` type and `-> target` |
:::

:::exam
- "Create a hard link" is checked by inode: `ls -i` on both names must print the same number. A soft link here fails the check.
- `ln -s` takes the target first and the new link name second. Reversing them is the most common mistake and gives a link that dangles.
- A link outside the target's directory needs an absolute target, or a relative path written from the link's own location.
:::
