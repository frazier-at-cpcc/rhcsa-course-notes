### Three standard streams
- The objective: ==use input-output redirection (>, >>, |, 2>, etc.)==
- Every process starts with three open file descriptors
  - 0 ==stdin==: input, the keyboard by default
  - 1 ==stdout==: normal output, the terminal by default
  - 2 ==stderr==: error messages, also the terminal
- Output and errors look alike on screen but travel separately
  - Each one can be sent somewhere different
- ==Redirection== points a descriptor at a file; a pipe connects one command's stdout to the next command's stdin
- The shell sets up redirections before the command starts
  - The command never sees `>` or the file name

### Redirecting output
- `>` sends stdout to a file and ==truncates== it first
- `>>` ==appends== to the end; creates the file if missing
- `2>` and `2>>` do the same for stderr
- A regular user's `find` across `/etc` mixes good results with permission errors

```console label="Terminal"
$ find /etc -name "*.conf" > ok.txt 2> err.txt
$ wc -l ok.txt err.txt
  39 ok.txt
   3 err.txt
  42 total
$ tail -1 err.txt
find: ‘/etc/sudoers.d’: Permission denied
```

- ==/dev/null== discards anything written to it
  - `2>/dev/null` hides the errors; the results still print
- `set -o noclobber` stops `>` from replacing an existing file
  - `>|` overrides it for one command

```console label="Terminal"
$ echo "first run" > run.log
$ echo "second run" >> run.log; cat run.log
first run
second run
$ echo "third run" > run.log; cat run.log
third run
$ set -o noclobber
$ echo "oops" > run.log
bash: run.log: cannot overwrite existing file
$ echo "forced" >| run.log; cat run.log
forced
```

### Both streams into one place
- `&>` sends stdout and stderr to one file; `&>>` appends both
- ==2>&1== means "send 2 to wherever 1 points right now"
  - Redirections are read ==left to right==
  - `> file 2>&1`: stdout moves to the file, then stderr joins it
  - `2>&1 > file`: stderr copies stdout's target while it is still the terminal; only stdout then moves to the file

```console label="Terminal"
$ ls /etc/hosts /nope > out.txt 2>&1
$ cat out.txt
ls: cannot access '/nope': No such file or directory
/etc/hosts
$ ls /etc/hosts /nope 2>&1 > out.txt
ls: cannot access '/nope': No such file or directory
$ cat out.txt
/etc/hosts
```

### Redirecting input
- `<` feeds a file to stdin; the command never learns the file name
- A ==here document== (`<< EOF`) feeds the lines that follow, up to a line holding only the marker
  - The shell shows `>` while it waits for more lines
  - `$VAR` and `$( )` expand; quote the marker (`<< "EOF"`) to keep them literal
- A ==here string== (`<<<`) feeds one string

```console label="Terminal"
$ wc -l /etc/passwd
17 /etc/passwd
$ wc -l < /etc/passwd
17
$ tr a-z A-Z <<< "servera ready"
SERVERA READY
$ cat > motd.txt <<EOT
> Welcome to $(hostname -s)
> Maintenance: Sunday 02:00
> EOT
$ cat motd.txt
Welcome to servera
Maintenance: Sunday 02:00
```

### Pipes and tee
- A ==pipe== (`|`) connects stdout of the left command to stdin of the right one
  - Chain small tools: `grep`, `cut`, `sort`, `uniq`, `wc`
  - stderr skips the pipe unless you use `|&` or `2>&1 |`
- ==tee== copies its input to a file and to stdout
  - Save a copy and keep watching; `tee -a` appends

```console label="Terminal"
$ cut -d: -f7 /etc/passwd | sort | uniq -c
      2 /bin/bash
      1 /bin/sync
      1 /sbin/halt
      1 /sbin/nologin
      1 /sbin/shutdown
     11 /usr/sbin/nologin
$ grep -c bash /etc/passwd | tee bash-users.txt
2
$ ls /nope | wc -l
ls: cannot access '/nope': No such file or directory
0
$ ls /nope |& wc -l
1
```

- A pipeline's exit status is that of its last command
  - `set -o pipefail` makes a failure anywhere fail the whole pipeline (useful in scripts, Group 3)

| Syntax | Effect |
|---|---|
| `> f` / `>> f` | stdout to f: overwrite / append |
| `2> f` / `2>> f` | stderr to f: overwrite / append |
| `&> f` / `&>> f` | both streams to f |
| `> f 2>&1` | same as `&>`, older and portable |
| `< f` | stdin from f |
| `<< EOF` | here document as stdin |
| `<<< "text"` | here string as stdin |
| `a \| b` / `a \|& b` | stdout / both streams of a into b |

### Writing root-owned files with sudo
- In `sudo cmd > /etc/file`, your own shell opens the file ==before sudo runs==
  - The redirect runs as you, so it fails with `Permission denied`
- Pipe into ==sudo tee== instead: `tee` opens the file as root
  - `-a` appends; `> /dev/null` hides the copy `tee` prints

```console label="Terminal"
$ sudo echo "Lab use only" > /etc/motd
bash: /etc/motd: Permission denied
$ echo "Lab use only" | sudo tee /etc/motd
Lab use only
$ echo "10.0.0.5 nas" | sudo tee -a /etc/hosts
10.0.0.5 nas
$ echo "10.0.0.6 nfs1" \
  | sudo tee -a /etc/hosts > /dev/null
```


:::exam
- Tasks say "save the output to /root/file" or "write the matching lines to a file". Use `>`, then read the file back, and keep error text out of it unless the task asks for it.
- Know `>` from `>>`. Rerunning a command with `>` silently replaces the file and can wipe lines an earlier task needed. A file you write stays on disk, so it persists across reboots.
- `cmd > file 2>&1` captures both streams; `cmd 2>&1 > file` does not. Expect the second order as a distractor.
:::
