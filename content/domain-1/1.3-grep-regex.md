### Searching text with grep
- The objective: ==use grep and regular expressions to analyze text==
- ==grep== prints every line that matches a pattern
  - `grep PATTERN FILE...`, or read a pipe: `cmd | grep PATTERN`
  - Exit status 0 if a line matched, 1 if none did, 2 on an error (scripts test this, Group 3)
- Matching is ==case-sensitive== unless you add `-i`
- Put the pattern in single quotes so the shell leaves `*`, `$`, `|`, and spaces alone
- `/etc/passwd` makes a good practice file: one account per line, seven fields split by `:`

```console label="Terminal"
$ grep alice /etc/passwd
alice:x:1001:1001::/home/alice:/bin/bash
$ grep -n '^root' /etc/passwd
1:root:x:0:0:Super User:/root:/bin/bash
$ grep -c nologin /etc/passwd
14
$ grep -vc nologin /etc/passwd
6
$ grep -i 'super user' /etc/passwd
root:x:0:0:Super User:/root:/bin/bash
$ grep -q bob /etc/passwd; echo $?
1
```

### The options that matter

| Option | Effect |
|---|---|
| `-i` | ignore case |
| `-v` | ==invert==: lines that do not match |
| `-c` | count matching lines |
| `-n` | add line numbers |
| `-o` | print only the matched text |
| `-w` | match whole words only |
| `-r` | ==recursive==: every file under a directory |
| `-l` | list names of files that match |
| `-q` | quiet: exit status only |
| `-E` | extended regular expressions |
| `-e` | add another pattern (either may match) |
| `-A n` / `-B n` | also n lines after / before |

- `-c` counts lines, not matches: a line with three hits counts once
- `-w` keeps `ftp` from matching inside `tftp` or `sftp`
  - A hyphen counts as a word boundary, so `ftp-data` still matches
- A file you cannot read gives `Permission denied`; grep reports it and keeps going
  - `/etc/shadow` and `sshd_config` need `sudo`

```console label="Terminal"
$ grep -c ftp /etc/services
55
$ grep -cw ftp /etc/services
17
$ grep -o '^[^:]*' /etc/passwd | head -3
root
bin
daemon
$ sudo grep -l alice /etc/{passwd,shadow,hosts}
/etc/passwd
/etc/shadow
$ grep -r '^Include' /etc/ssh
grep: /etc/ssh/sshd_config: Permission denied
grep: /etc/ssh/sshd_config.d: Permission denied
$ cd /etc/ssh; sudo grep -rl '^Include' .
./sshd_config
./sshd_config.d/40-redhat-crypto-policies.conf
```

### Regular expression building blocks
- A ==regular expression== describes text; grep tests it against each line
- Letters and digits match themselves; a few characters have special meanings

| Pattern | Matches |
|---|---|
| `^` / `$` | ==anchors==: start / end of line; `^$` is an empty line |
| `.` | any one character: `r..t` is `root` or `rest` |
| `[0-9]` | one character from a range or set (`[abc]`) |
| `[^abc]` | one character not in the set: `^[^#]` |
| `*` | the item before, zero or more times: `ro*t` |
| `.*` | any run of characters, even none |
| `+` `?` | one or more; zero or one (ERE) |
| `{n}` `{n,m}` | exactly n; n to m times (ERE) |
| `a\|b` `( )` | either side; grouping (ERE) |
| `\.` `\$` | the literal character |

- A regex `*` is not the shell's `*` glob
  - Glob `*.conf` is "any name ending in .conf"; the regex for that is `\.conf$`
- An unescaped `.` matches anything: `10.0.0.1` also matches `10a0b0c1`

### Basic versus extended regex
- Two dialects
  - ==Basic (BRE)==, the default: `+ ? { } | ( )` are plain characters until you put a backslash in front
  - ==Extended (ERE)==, with `grep -E`: they are special with no backslash
- `egrep` is the old name for `grep -E`; use `grep -E`
- The same search in both dialects; in BRE an unescaped `{4}` or `|` is literal text, so nothing matches

```console label="Terminal"
$ grep '^\(alice\|student\):' /etc/passwd
student:x:1000:1000::/home/student:/bin/bash
alice:x:1001:1001::/home/alice:/bin/bash
$ grep -Ec '^(alice|student):' /etc/passwd
2
$ grep 'x:[0-9]{4}:' /etc/passwd | wc -l
0
$ grep -E 'x:[0-9]{4}:' /etc/passwd | cut -d: -f1
student
alice
svcbackup
$ grep 'a|b' /etc/passwd | wc -l
0
```

- Anchors plus `-v`: bash accounts, and the active lines of `sshd_config` (mode 600 on RHEL 10, so `sudo`)

```console label="Terminal"
$ grep 'bash$' /etc/passwd | cut -d: -f1
root
student
alice
$ sudo grep -c '' /etc/ssh/sshd_config
130
$ sudo grep -Ev '^(#|$)' /etc/ssh/sshd_config
Include /etc/ssh/sshd_config.d/*.conf
AuthorizedKeysFile	.ssh/authorized_keys
Subsystem	sftp	/usr/libexec/openssh/sftp-server
```

### grep on command output and logs
- Pipe any command into grep to cut it down: `ip -br addr | grep UP`, `ps aux | grep httpd`, `dnf list --installed | grep kernel`
- Text logs in `/var/log` are root-only; ==/var/log/secure== records logins and `sudo`
- The ==journal== is binary, so pipe `journalctl` into grep
  - `--no-pager` keeps `journalctl` from opening `less`
  - `journalctl -g PATTERN` (`--grep`) filters with a regex inside journalctl
  - Members of `wheel` can read the whole journal; others see only their own entries
- From the RHEL 10 lab system: the time zone line, logins counted in `secure`, and `logger` test messages counted in the previous boot's journal

```console label="Terminal (lab system)"
$ timedatectl | grep 'Time zone'
Time zone: America/New_York (EDT, -0400)
$ sudo grep -c 'session opened' /var/log/secure
1149
$ sudo journalctl -b -1 --no-pager \
  | grep -c 'RHCSA lab'
5
```

### Saving matches to a file
- A classic task: ==save matching lines== from one file to another, in their original order
  - grep keeps the ==original order==; add `sort` only when asked
  - Check the result with `wc -l` and `head`

```console label="Terminal"
$ grep -w ftp /etc/services > ftp-lines.txt
$ wc -l < ftp-lines.txt; head -2 ftp-lines.txt
17
ftp-data        20/tcp
ftp-data        20/udp
$ grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' \
  /etc/hosts | head -1
127.0.0.1
```


:::exam
- Expect "find all lines containing X in file Y and copy them to /root/Z in the original order". Run `grep X Y > /root/Z`, then check the file for blank or extra lines; it persists with no further step.
- Know which characters need `-E`. `grep 'a|b'` searches for the literal text `a|b`; `grep -E 'a|b'` means a or b.
- `-v` inverts and `-c` counts lines. Anchors separate `root` anywhere in the line from `^root` at the start.
:::
