### Archive first, then compress
- The objective: ==archive, compress, unpack, and uncompress== files using `tar`, `gzip`, and `bzip2`
- Two separate jobs
  - Archiving bundles many files and directories into one file, keeping names, owners, modes, and timestamps
  - Compressing shrinks one file
- `tar` archives; `gzip`, `bzip2`, and `xz` compress
  - A compressed archive is a ==tarball==: `web.tar.gz`, `web.tar.bz2`, `web.tar.xz`
  - `tar` calls the compressor for you with one flag, so it is one command
- The exam asks for both directions
  - "Create a bzip2-compressed archive of /etc named /root/etc.tar.bz2"
  - "Extract the archive into /srv/restore"

:::figure wide 1.5-tar-pipeline.svg | tar bundles the tree into one stream and hands it to a compressor. Extraction runs the same path backward, and tar detects the compressor on its own.

### tar: create, list, extract
- Exactly one ==mode== per command
  - `-c` create, `-t` list (table of contents), `-x` extract
- `-f <file>` names the archive
  - `-f` takes the very next word as its argument, so keep it last in a bundle: `-czf`, never `-cfz`
- `-v` prints each file as it goes; with `-t` it gives a long listing with modes and owners
- Absolute paths are stored as relative
  - tar strips the leading `/` and says so; nothing is wrong
  - Extracting later never overwrites the real `/srv/web` by accident

```console label="Root shell"
$ cd /root
$ tar -czf web.tar.gz /srv/web
tar: Removing leading `/' from member names
$ tar -tf web.tar.gz
srv/web/
srv/web/index.html
srv/web/access.log
srv/web/css/
srv/web/css/site.css
```

- `-C <dir>` changes directory before working
  - On create: `tar -czf web.tar.gz -C /srv web` stores `web/...` with no `srv/` prefix
  - On extract: `tar -xf web.tar.gz -C /restore` unpacks there instead of the current directory
  - The target directory must already exist, or tar stops with `Cannot open: No such file or directory`

- Extract a single member by naming it exactly as `tar -t` lists it
  - `tar -xf web.tar.bz2 web/index.html`

:::wide
| Option | Meaning | Example |
|---|---|---|
| `-c` / `-t` / `-x` | create / list / extract | `tar -tf web.tar.gz` |
| `-f` | archive file name; always last in the bundle | `tar -cf web.tar web` |
| `-v` | verbose; long listing with `-t` | `tar -tvf web.tar.gz` |
| `-z` / `-j` / `-J` | gzip / bzip2 / xz | `tar -cjf etc.tar.bz2 /etc` |
| `-a` | pick the compressor from the suffix | `tar -caf web.tar.xz web` |
| `-C` | change to a directory first | `tar -xf web.tar -C /restore` |
| `-p` | keep stored modes (default for root) | `tar -xpf web.tar.gz` |
| `--acls`, `--selinux`, `--xattrs` | store and restore ACLs, SELinux labels, extended attributes | `tar --acls -cf d.tar d` |
:::

### Compression flags
- `-z` calls ==gzip==, `-j` calls ==bzip2==, `-J` calls ==xz==
  - Same tree, four archives: xz is the smallest, then bzip2, then gzip
  - Smaller output costs more CPU time; gzip is the fastest

```console label="Root shell"
$ wc -c web.tar*
1402880 web.tar
  53816 web.tar.bz2
  93226 web.tar.gz
  15296 web.tar.xz
```

- Extraction does not need the flag
  - `tar -xf web.tar.bz2` reads the header and calls `bzip2` itself
- The suffix is only a name; `file` reports what is really inside

```console label="Root shell"
$ file web.tar web.tar.bz2 web.tar.xz
web.tar:     POSIX tar archive (GNU)
web.tar.bz2: bzip2 compressed data, block size = 900k
web.tar.xz:  XZ compressed data, checksum CRC64
```

- The `-f` trap in action: `tar -cfz web.tgz -C /srv web`
  - Writes an archive named `z` and then fails looking for a file called `web.tgz`

```console label="Root shell"
$ tar -cfz web.tgz -C /srv web
tar: web.tgz: Cannot stat: No such file or directory
tar: Exiting with failure status due to previous errors
$ ls
z
```

### Preserving permissions and ownership
- Every member stores its mode, owner, group, and timestamp
  - `tar -tvf` shows them: `-rw-r----- alice/devops ... srv/web/index.html`
- Extracting as root restores all of it
  - Same owner and group by name, same mode: `-p` and `--same-owner` are already on for root
- Extracting as a regular user gives you a copy you own
  - Owner and group become yours; you cannot give files away
  - Your ==umask== trims the modes unless you add `-p`

```console label="Terminal (as bob)"
$ umask 077; tar -xf web.tar.gz; ls -l web
-rw------- 1 bob bob 1388894 Oct 21 17:00 access.log
drwx------ 2 bob bob    4096 Oct 21 17:00 css
-rw------- 1 bob bob      17 Oct 21 17:00 index.html
$ rm -rf web; tar -xpf web.tar.gz; ls -l web
-rw-r--r-- 1 bob bob 1388894 Oct 21 17:00 access.log
drwxr-xr-x 2 bob bob    4096 Oct 21 17:00 css
-rw-r----- 1 bob bob      17 Oct 21 17:00 index.html
```

- ACLs and SELinux labels are not stored by default
  - Add `--acls --selinux --xattrs` at create and again at extract
  - Without `--acls`, a file's `user:bob:rw-` entry is silently dropped
  - After restoring into a web or home directory without labels, run `restorecon -R` (objective 10.5)

### gzip and bzip2 on single files
- Both compress one file in place and ==remove the original==
  - `gzip access.log` leaves only `access.log.gz`
  - `-k` keeps the original as well
- Undo with `gunzip` (same as `gzip -d`) and `bunzip2` (same as `bzip2 -d`)
- Read without unpacking: `zcat`, `bzcat`, `xzcat`
- `-c` writes to standard output and leaves the input alone
- `-1` is fastest, `-9` is smallest
- `gzip -l file.gz` prints the sizes and ratio (93.3% for this log)

```console label="Root shell"
$ gzip access.log
$ ls
access.log.gz
$ gunzip access.log.gz
$ bzip2 -k access.log
$ ls
access.log
access.log.bz2
$ bunzip2 access.log.bz2
bunzip2: Output file access.log already exists.
$ bzcat access.log.bz2 | head -1
10.0.0.5 GET /index.html 200 1
```

- Neither tool archives
  - `gzip -r /srv/web` compresses every file separately; it does not make one file
  - For a directory, use `tar` with `-z` or `-j`

:::exam
- Read the file name in the task. `.tar.gz` or `.tgz` means `-z`, `.tar.bz2` means `-j`, `.tar.xz` means `-J`. A grader can check the real type with `file`, so a gzip archive with a `.bz2` name fails.
- "Extract into /srv/restore" means `-C /srv/restore`, and that directory must exist first. Confirm the result with `ls`.
- A task that says the files must keep their owners and permissions expects you to extract as root (or with `sudo`).
:::
