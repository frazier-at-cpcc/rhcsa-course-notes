### Zones
- The objective: ==configure firewall settings using firewall-cmd/firewalld==
  - Builds on 8.3 (services, ports, `--permanent`, `--reload`); this topic adds zones, rich rules, and forwarding
- A ==zone== is a trust level: a set of allowed services and ports plus a ==target== for everything else
- Shipped zones, from the XML in `/usr/lib/firewalld/zones/`

:::wide
| Zone | Unmatched traffic | Allowed by default |
|---|---|---|
| `drop`, `block` | dropped silently (`drop`) or rejected (`block`) | nothing |
| `public`, `work` | rejected | ssh, dhcpv6-client, cockpit |
| `home`, `internal` | rejected | public's list plus mdns, samba-client |
| `dmz`, `external` | rejected | ssh (`external` also masquerades) |
| `trusted` | accepted | everything |
:::

- `--get-zones` lists them (plus `nm-shared`, for NetworkManager connection sharing); `--get-active-zones` shows only zones that have an interface or source
- `--get-zone-of-interface=ens18` answers `public` here
- ==`--set-default-zone=NAME`== changes the default, live and saved in one step
- An interface's zone comes from its NetworkManager profile
  - `nmcli connection modify NAME connection.zone internal`, then `up`; empty means the default zone
  - `firewall-cmd --zone=internal --change-interface=ens19` also works

### How firewalld picks a zone
- Every incoming packet is judged by ==exactly one zone==
  1. Its source address matches a zone's ==source== list: that zone
  2. Otherwise, the zone of the interface it arrived on
  3. Otherwise, the ==default zone==
- No fall-through: if the chosen zone does not allow it, the packet is rejected, even when another zone would have allowed it
  - firewalld 2.x removed the old "zone drifting" behavior
- `--get-zone-of-source=ADDR` answers which zone owns an address

:::figure 10.1-zone-selection.svg | Sources are checked before interfaces, and the default zone catches the rest. The first zone that claims the packet is the only one consulted.

### A source-based zone
- ==`--add-source=CIDR`== binds an address or subnet to a zone
  - Then allow services in that zone only
  - Traffic from the subnet gets the zone's rules; everyone else on the same NIC stays in `public`
- Here, `http` is open to 192.0.2.0/24 and nowhere else

:::wide
```console label="Terminal"
$ sudo firewall-cmd --permanent --zone=internal --add-source=192.0.2.0/24
success
$ sudo firewall-cmd --permanent --zone=internal --add-service=http
success
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --zone=internal --list-all
internal (active)
  interfaces:
  sources: 192.0.2.0/24
  services: cockpit dhcpv6-client http mdns samba-client ssh
```
:::

- `internal` is now `(active)`: it owns a source, with no interface at all

### Rich rules
- A ==rich rule== matches on source, destination, service, or port, then accepts, rejects, or drops
  - `rule family=ipv4 source address=ADDR service name=NAME accept|reject|drop`
  - `port port=N protocol=tcp` in place of `service name=...`
  - Optional `log prefix="..."` and `limit value="3/m"`
- Quote the whole rule in single quotes; `--remove-rich-rule` takes the same text
- No `--zone` means the default zone
- ==reject and drop rules are checked before the zone's allowed services==
  - So a rich rule can refuse SSH to one subnet while `ssh` stays in `public`

:::wide
```console label="Terminal"
$ sudo firewall-cmd --permanent \
    --add-rich-rule='rule family=ipv4 source address=198.51.100.0/24 service name=ssh reject'
success
$ sudo firewall-cmd --permanent \
    --add-rich-rule='rule family=ipv4 source address=203.0.113.5 port port=8443 protocol=tcp accept'
success
$ sudo firewall-cmd --reload; sudo firewall-cmd --list-rich-rules
success
rule family="ipv4" source address="203.0.113.5" port port="8443" protocol="tcp" accept
rule family="ipv4" source address="198.51.100.0/24" service name="ssh" reject
```
:::

- `--list-rich-rules` prints the stored form, with every value quoted

### Port forwarding
- ==`--add-forward-port=port=8080:proto=tcp:toport=80`== redirects incoming 8080 to local port 80
  - Add `:toaddr=192.0.2.20` to send it to another host
  - Forwarding to another host usually needs `--add-masquerade` too
- `--list-forward-ports` shows them; an empty `toaddr=` means this machine

```console label="Terminal"
$ sudo firewall-cmd --permanent \
    --add-forward-port=port=8080:proto=tcp:toport=80
success
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --list-forward-ports
port=8080:proto=tcp:toport=80:toaddr=
```

### Runtime to permanent, and the reboot test
- Some admins test a change live first, then keep it
- ==`--runtime-to-permanent`== copies the whole runtime configuration into the permanent one
  - It saves every live change, including experiments you meant to drop
- ==`--check-config`== validates the saved XML before a reload or reboot

```console label="Terminal"
$ sudo firewall-cmd --add-port=9090/tcp
success
$ sudo firewall-cmd --list-ports
9090/tcp
$ sudo firewall-cmd --permanent --list-ports
$ sudo firewall-cmd --runtime-to-permanent
success
$ sudo firewall-cmd --permanent --list-ports
9090/tcp
$ sudo firewall-cmd --check-config
success
```

- After a reboot every rule above is back: the source zone, both rich rules, the forward, and 9090

:::wide
```console label="Terminal (after reboot)"
$ sudo firewall-cmd --get-active-zones
internal
  sources: 192.0.2.0/24
public (default)
  interfaces: ens18
$ sudo firewall-cmd --list-rich-rules; sudo firewall-cmd --list-forward-ports; sudo firewall-cmd --list-ports
rule family="ipv4" source address="203.0.113.5" port port="8443" protocol="tcp" accept
rule family="ipv4" source address="198.51.100.0/24" service name="ssh" reject
port=8080:proto=tcp:toport=80:toaddr=
9090/tcp
```
:::

:::exam
- "Allow HTTP only from 192.0.2.0/24" is either a source in a zone that allows http, or a rich rule with `source address=192.0.2.0/24 service name=http accept`. Leave `http` out of the default zone, or everyone gets in.
- "Forward TCP 8080 to port 80" is `--add-forward-port`, not a second `--add-port`.
- The grader reboots. Use `--permanent` and `--reload`, or `--runtime-to-permanent` after live testing, then compare `--list-all` with `--permanent --list-all`.
:::

:::try
Configure firewalld so that hosts in 192.0.2.0/24 are handled by the internal zone and can reach HTTP, hosts in 198.51.100.0/24 are refused SSH, and incoming TCP port 8080 is forwarded to local port 80, all persisting across reboots. Reboot, then confirm with `firewall-cmd --get-active-zones`, `--list-rich-rules`, and `--list-forward-ports`.
:::
