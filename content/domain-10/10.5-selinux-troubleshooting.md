### Symptom: a 403 from a new document root
- The objective: ==restore default file contexts==; ==manage SELinux port labels==; ==use Boolean settings== to modify system SELinux settings
- Apache's `DocumentRoot` was moved to `/web`, a directory made with `mkdir`
  - Its files are ==`default_t`==, a type `httpd_t` may not read
  - Permissions are fine (`644`), yet the page fails

```console label="Terminal"
$ curl -s -o /dev/null -w '%{http_code}\n' \
  http://localhost/index.html
403
$ ls -Zd /web /web/index.html
unconfined_u:object_r:default_t:s0 /web
unconfined_u:object_r:default_t:s0 /web/index.html
```

- Denials land in `/var/log/audit/audit.log` as `type=AVC` records
  - `sudo ausearch -m AVC -ts recent` lists the last ten minutes of them; `-i` decodes numbers into names
- What to read in an AVC record:

| Field | Tells you |
|---|---|
| `denied { read }` | the action refused |
| `comm="httpd"` | the program |
| `scontext=...httpd_t` | the process domain |
| `tcontext=...default_t` | the target's type |
| `tclass=file` | file, dir, tcp_socket |

- ==`sealert -a /var/log/audit/audit.log`== (package `setroubleshoot-server`) explains each denial
  - A summary line, `SELinux is preventing <program> from <action> access on ...`
  - Then suggested fixes, often a `semanage fcontext -a -t` and a `restorecon -v` line
  - Check the suggested type before pasting it; web content is `httpd_sys_content_t`

### How SELinux decides
- Standard rwx permissions are checked first; SELinux can only take access away
- SELinux then weighs three things
  - The process ==domain== (`httpd_t`)
  - The target's type: a file (`httpd_sys_content_t`) or a port (`http_port_t`)
  - The action: read a file, bind a port, connect out
- No rule allows it and no Boolean turns one on: enforcing mode refuses and logs an ==AVC== denial

:::figure wide 10.5-selinux-decision.svg | Each fix in this topic changes one input. A wrong file type gets a new label, a nonstandard port gets a port label, and an optional behavior gets a Boolean.

### restorecon and semanage fcontext
- ==`restorecon`== resets labels to the policy's default for each path
  - `-R` recurses, `-v` prints each change
- The first `restorecon` changed nothing: the default for `/web` is `default_t`
  - `matchpathcon` prints the default a path would get
- ==`semanage fcontext -a`== adds a local rule to the policy, so the default itself changes
  - `-t` the type, then a regular expression for the paths
  - `'/web(/.*)?'` matches the directory and everything under it; quote it
  - The rule is stored in the policy and survives reboots and relabels
- Then `restorecon -Rv` applies the new default to the existing files

```console label="Terminal"
$ sudo restorecon -Rv /web
$ matchpathcon /web /var/www/html
/web	system_u:object_r:default_t:s0
/var/www/html	system_u:object_r:httpd_sys_content_t:s0
$ sudo semanage fcontext -a \
  -t httpd_sys_content_t '/web(/.*)?'
$ sudo semanage fcontext -l -C
SELinux fcontext  type       Context
/web(/.*)?        all files  system_u:object_r:httpd_sys_content_t:s0
$ sudo restorecon -Rv /web
Relabeled /web/index.html from unconfined_u:object_r:default_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
$ curl -s http://localhost/index.html
lab site
```

- `-l -C` lists only local customizations: the quickest way to check your own work
- Remove a rule with `semanage fcontext -d '/web(/.*)?'`

### chcon and a full relabel
- ==`chcon -t TYPE file`== writes a label directly
  - The label stays on disk, but the policy does not know about it
  - The next `restorecon` or full relabel puts the default back

```console label="Terminal"
$ sudo chcon -t user_home_t /web/index.html
$ ls -Z /web/index.html
unconfined_u:object_r:user_home_t:s0 /web/index.html
$ sudo restorecon -v /web/index.html
Relabeled /web/index.html from unconfined_u:object_r:user_home_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
```

- An empty ==`/.autorelabel`== file makes the next boot relabel every file system, then delete the file
  - Slow on big disks; it also resets every `chcon`
  - Also the last step of a root password reset with `rd.break` (objective 4.1)
- The capture created the file and removed it again, so no relabel ran

```console label="Terminal"
$ sudo touch /.autorelabel
$ ls -l /.autorelabel
-rw-r--r--. 1 root root 0 Oct 21 19:15 /.autorelabel
$ sudo rm /.autorelabel
```

### Port labels
- Ports carry types too; `httpd_t` may bind only ports labeled ==`http_port_t`==
- Moving Apache to port 82 fails at restart, even as root

```console label="Terminal"
$ sudo sed -i 's/^Listen 80$/Listen 82/' \
  /etc/httpd/conf/httpd.conf
$ sudo systemctl restart httpd
Job for httpd.service failed because the control process exited with error code.
$ sudo semanage port -l | grep -w http_port_t
http_port_t   tcp   80, 81, 443, 488, 8008, 8009, 8443, 9000
http_port_t   udp   80, 443
```

- ==`semanage port -a -t http_port_t -p tcp 82`== adds the label; it persists
  - Use `-m` instead of `-a` when the port already has another type
  - `-d` removes it
- SELinux and firewalld are separate gates: open the port in the firewall too

```console label="Terminal"
$ sudo semanage port -a -t http_port_t \
  -p tcp 82
$ sudo semanage port -l -C
SELinux Port Type   Proto   Port Number
http_port_t         tcp     82
$ sudo systemctl restart httpd
$ systemctl is-active httpd
active
$ sudo firewall-cmd --permanent \
  --add-port=82/tcp
success
$ sudo firewall-cmd --reload
success
$ curl -s http://servera:82/index.html
lab site
```

### Booleans
- A ==Boolean== switches an optional part of the policy on or off
  - `httpd_enable_homedirs`: Apache may serve `~/public_html`
  - `httpd_can_network_connect`: Apache may open outbound connections (a proxy)
- ==`getsebool -a`== lists them all; `getsebool name` shows one
- `semanage boolean -l` adds a description and two values: (current, default at boot)
- ==`setsebool`== without `-P` changes only the running value; `-P` writes it to the policy for every boot
  - `semanage boolean -l -C` shows the difference: `(on, off)` is a change a reboot will undo

```console label="Terminal"
$ sudo setsebool httpd_enable_homedirs on
$ sudo semanage boolean -l -C
SELinux boolean        State  Default Description
httpd_enable_homedirs  (on   ,  off)  Allow httpd to enable homedirs
$ sudo setsebool -P httpd_enable_homedirs on
$ sudo semanage boolean -l -C
SELinux boolean        State  Default Description
httpd_enable_homedirs  (on   ,   on)  Allow httpd to enable homedirs
```

### Proving it after a reboot
- `semanage fcontext`, `semanage port`, and `setsebool -P` all write to the policy store, so they survive a reboot
- `httpd` came back `inactive` because the lab never enabled it; on the exam, `systemctl enable --now httpd`

```console label="Terminal (after a reboot)"
$ getsebool httpd_enable_homedirs
httpd_enable_homedirs --> on
$ sudo semanage port -l -C
SELinux Port Type   Proto   Port Number
http_port_t         tcp     82
$ systemctl is-active httpd || \
  sudo systemctl start httpd
inactive
$ curl -s http://servera:82/index.html
lab site
```

:::exam
- "The web server must serve content from /web" means `semanage fcontext -a -t httpd_sys_content_t '/web(/.*)?'` then `restorecon -Rv /web`. A `chcon` label lasts only until something relabels the disk.
- "The service must listen on port 82" is three steps: the service config, `semanage port -a -t http_port_t -p tcp 82`, and `firewall-cmd --permanent --add-port=82/tcp`. Missing any one breaks it.
- A Boolean set without `-P` is gone after the reboot the grader performs. Check with `semanage boolean -l -C` or `getsebool` after a reboot.
:::
