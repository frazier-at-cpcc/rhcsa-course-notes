### States and modes
- The objective: ==set enforcing and permissive modes for SELinux==; ==list and identify SELinux file and process context==
- SELinux is mandatory access control layered on top of rwx permissions
  - Every process and every file, port, and socket carries a label
  - The policy says which process labels may touch which object labels
- Two states: enabled or disabled
- An enabled system runs in one of two modes
  - ==Enforcing==: denies what the policy does not allow and logs it
  - ==Permissive==: allows everything, still logs what it would have denied
- RHEL 10 ships the ==targeted== policy: network services are confined, logged-in users mostly are not
- `getenforce` prints one word; `sestatus` adds the config file's mode and the policy name

```console label="Terminal"
$ getenforce
Enforcing
$ sestatus
SELinux status:                 enabled
SELinuxfs mount:                /sys/fs/selinux
Loaded policy name:             targeted
Current mode:                   enforcing
Mode from config file:          enforcing
```

### Switching modes now
- ==`setenforce 0`== goes permissive, `setenforce 1` back to enforcing
  - `Permissive` and `Enforcing` work as arguments too
  - Root only; it lasts until the next reboot
  - It cannot disable SELinux; it only flips the mode
- The kernel exposes the live mode in `/sys/fs/selinux/enforce` (1 is enforcing)
- The last `setenforce` below ran without `sudo` on purpose: an ordinary user is refused

```console label="Terminal"
$ sudo setenforce 0; getenforce
Permissive
$ sudo setenforce 1; getenforce
Enforcing
$ setenforce 0
setenforce:  security_setenforce() failed:  Permission denied
$ cat /sys/fs/selinux/enforce
1
```

- Permissive is a troubleshooting switch: if the problem goes away, SELinux caused it
  - Put it back with `setenforce 1` before you move on

### The mode at boot
- ==`/etc/selinux/config`== sets the mode for every boot
  - `SELINUX=` takes `enforcing` or `permissive`
  - `SELINUXTYPE=targeted` names the policy; leave it alone
- To change the mode now and at boot, edit the file and run `setenforce` to match
- The capture set permissive in the file, rebooted, and read it back

```console label="Terminal"
$ grep -E '^SELINUX(TYPE)?=' \
  /etc/selinux/config
SELINUX=enforcing
SELINUXTYPE=targeted
$ sudo sed -i \
  's/^SELINUX=.*/SELINUX=permissive/' \
  /etc/selinux/config
$ grep ^SELINUX= /etc/selinux/config
SELINUX=permissive
```

```console label="Terminal (after a reboot)"
$ getenforce
Permissive
$ sudo sed -i \
  's/^SELINUX=.*/SELINUX=enforcing/' \
  /etc/selinux/config
$ sudo setenforce 1; getenforce
Enforcing
```

| Setting | Takes effect | Result |
|---|---|---|
| `setenforce 0` / `1` | now, until reboot | permissive / enforcing |
| `SELINUX=` in the config | every boot | the mode named |
| `enforcing=0` kernel argument | that boot, over the config | permissive |
| `selinux=0` kernel argument | every boot it is set | disabled |

### Disabling SELinux on RHEL 10
- `SELINUX=disabled` in the config file ==no longer disables SELinux== in the kernel (a change made in RHEL 9)
  - The system still boots with SELinux enabled and simply loads no policy
- Red Hat's RHEL 10 documentation disables it with the ==`selinux=0`== kernel argument, set through `grubby`:
  1. `sudo grubby --update-kernel ALL --args selinux=0`
  2. Reboot
  3. `getenforce` reports `Disabled`
- To undo it, remove the argument with `grubby --update-kernel ALL --remove-args selinux=0`
  - Files created while disabled have no label, so boot permissive first and relabel (objective 10.5)
- `/proc/cmdline` shows the running kernel's arguments; the capture machine had neither `selinux=` nor `enforcing=`

### File contexts
- A label (==context==) has four fields: `user:role:type:level`

| Field | Example | Meaning |
|---|---|---|
| user | `system_u` | SELinux user |
| role | `object_r` | always this on files |
| type | `passwd_file_t` | what the policy checks |
| level | `s0` | MLS/MCS level |

- In the targeted policy the ==type== field decides access; read it first
- ==`ls -Z`== shows file labels; add `-d` for a directory itself
- `stat -c %C` prints just the context

```console label="Terminal"
$ ls -Z /etc/passwd /etc/shadow
system_u:object_r:passwd_file_t:s0 /etc/passwd
system_u:object_r:shadow_t:s0 /etc/shadow
$ ls -dZ /var/www/html /home/student /tmp
unconfined_u:object_r:user_home_dir_t:s0 /home/student
system_u:object_r:tmp_t:s0 /tmp
system_u:object_r:httpd_sys_content_t:s0 /var/www/html
$ stat -c '%n %C' /etc/ssh/sshd_config
/etc/ssh/sshd_config system_u:object_r:etc_t:s0
```

### Copy versus move
- A new file gets its type from the directory it is created in
  - Usually the parent's type; some directories have a rule instead (files in a home directory become `user_home_t`)
- ==`cp`== creates a new file, so the copy gets the destination's type
- ==`mv`== keeps the same inode, so the file keeps its old label
  - A page moved from a home directory into `/var/www/html` stays `user_home_t`, and Apache cannot read it

```console label="Terminal"
$ echo hello > notes.txt; ls -Z notes.txt
system_u:object_r:user_home_t:s0 notes.txt
$ sudo cp notes.txt /var/www/html/
$ sudo mv /home/student/notes.txt \
  /var/www/html/moved.txt
$ ls -Z /var/www/html/
system_u:object_r:user_home_t:s0 moved.txt
system_u:object_r:httpd_sys_content_t:s0 notes.txt
```

:::figure 10.4-copy-vs-move.svg | cp writes a new file that is labeled where it lands. mv carries the old label along.

- `cp -a` also preserves the old context, the same trap as `mv`
- Fix a moved file with `restorecon` (objective 10.5)

### Process and user contexts
- ==`ps -eZ`== (or `ps axZ`) adds the label column to every process
  - The type of a process is its ==domain==: `httpd_t`, `sshd_t`
- ==`id -Z`== shows your own context
  - A normal SSH or console login is `unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023`
  - The lab capture ran from a systemd service, so its `id -Z` read `initrc_t`: a process label depends on what started it

```console label="Terminal"
$ ps -eZ | grep -E 'httpd|sshd' | head -4
system_u:system_r:sshd_t:s0-s0:c0.c1023 860 ? 00:00:00 sshd
system_u:system_r:httpd_t:s0 2185 ? 00:00:00 httpd
system_u:system_r:httpd_t:s0 2186 ? 00:00:00 httpd
```

- `semanage login -l` maps Linux users to SELinux users; everyone defaults to `unconfined_u`

```console label="Terminal"
$ sudo semanage login -l | head -6
Login Name   SELinux User  MLS/MCS Range   Service
__default__  unconfined_u  s0-s0:c0.c1023  *
root         unconfined_u  s0-s0:c0.c1023  *
```

:::exam
- "Set SELinux to permissive and make sure it stays that way after a reboot" needs both: `setenforce 0` for now and `SELINUX=permissive` in `/etc/selinux/config` for later. The grader checks after a reboot.
- `SELINUX=disabled` in the config file does not turn SELinux off on RHEL 10. The working method is the `selinux=0` kernel argument through `grubby`. Red Hat recommends permissive over disabling, and the exam rarely wants it.
- Reading a label means reading its type: `httpd_sys_content_t` on a file, `httpd_t` on a process. A file moved with `mv` keeps its old type.
:::
