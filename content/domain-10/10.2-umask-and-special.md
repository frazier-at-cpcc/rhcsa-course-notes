### How the umask sets default permissions
- Programs ask for a generous mode when they create something
  - New files: `666` (`rw-rw-rw-`); new directories: `777` (`rwxrwxrwx`)
- The ==umask== lists the bits to remove from that request
  - Result = requested mode with every umask bit switched off
  - Not subtraction: `666` with umask `033` gives `644`, not `633`
- This is how you ==manage default file permissions==: no `chmod` after every `touch`

:::figure 10.2-umask-math.svg | With umask 027 the group loses write and other loses everything.

| umask | New file | New directory | Typical use |
|---|---|---|---|
| `022` | `644` | `755` | RHEL 10 default |
| `002` | `664` | `775` | group can edit |
| `027` | `640` | `750` | group reads, others nothing |
| `007` | `660` | `770` | team share, others nothing |
| `077` | `600` | `700` | private |

### Checking and changing it
- `umask` prints the current value in octal; ==umask -S== prints it as letters
- `umask 027` changes it for the current shell and its children only
  - Gone at the next login

```console label="Terminal (alice)"
$ umask; umask -S
0022
u=rwx,g=rx,o=rx
$ umask 027; touch f2; mkdir d2; ls -ld f2 d2
drwxr-x--- 2 alice alice 4096 Oct 21 17:26 d2
-rw-r----- 1 alice alice    0 Oct 21 17:26 f2
```

- The leading `0` is the special-permission digit; `umask 27` and `umask 027` are the same
- Even `umask 000` gives files `rw-rw-rw-`: execute is never added to a new file

### Making the umask persist
- ==Per user==: add `umask 007` to that user's `~/.bashrc`
  - Read by every interactive bash shell, after the system-wide settings, so it wins
- ==System wide== on RHEL 10: the `UMASK` line in ==/etc/login.defs==
  - `pam_umask` in `/etc/pam.d/postlogin` applies it at every login: console, SSH, `su -`
  - Covers root too
- RHEL 10 gives root and regular users the same `0022`
  - Older releases gave regular users `0002` from the shell startup files; on RHEL 10 `/etc/bashrc` only sets `022` when the umask is still `0`

```console label="Terminal"
$ grep ^UMASK /etc/login.defs; grep pam_umask /etc/pam.d/postlogin
UMASK		022
session     optional                   pam_umask.so silent
$ sudo sed -i 's/^UMASK.*/UMASK\t\t027/' /etc/login.defs
```

```console label="Next login, as bob"
$ umask
0027
```

- Alternative: a file such as `/etc/profile.d/umask.sh` containing `umask 027`
  - Login shells only: `su bob` without the `-` skips it and keeps `0022`
- Home directories ignore the umask: `useradd` uses `HOME_MODE 0700` from `/etc/login.defs`
- Prove persistence by logging in again (`su - bob`) and running `umask`; a reboot changes nothing more

### Special permissions: setuid, setgid, sticky

| Bit | Octal | On a file | On a directory |
|---|---|---|---|
| ==setuid== | `4` | runs as the file's owner | (no effect) |
| ==setgid== | `2` | runs as the file's group | new files inherit the directory's group |
| ==sticky== | `1` | (no effect) | only the owner can delete or rename a file |

- Shown in the execute position of `ls -l`: `s` for setuid/setgid, `t` for sticky
  - Capital `S` or `T`: the special bit is set but execute is not, usually a mistake
- Set with a fourth leading octal digit (`chmod 2770 dir`) or symbolically (`u+s`, `g+s`, `o+t`)

```console label="Terminal"
$ ls -l /usr/bin/passwd /usr/bin/write
-rwsr-xr-x 1 root root 91424 Feb 23  2026 /usr/bin/passwd
-rwxr-sr-x 1 root tty  24160 Jan 15  2026 /usr/bin/write
$ ls -ld /tmp
drwxrwxrwt 1 root root 4096 Oct 21 17:26 /tmp
```

- `passwd` is setuid root so a regular user can update `/etc/shadow`
- On `/tmp`, the sticky bit stops bob from deleting alice's file even though the file is mode `666`

```console label="Terminal (bob)"
$ rm -f /tmp/alice.txt
rm: cannot remove '/tmp/alice.txt': Operation not permitted
```

### A shared group directory
- The classic exam task: a directory owned by group `devops`, where members can share files
  - ==setgid on the directory==: every new file belongs to `devops`, whatever the creator's primary group
  - New subdirectories inherit the setgid bit too

```console label="Terminal"
$ sudo mkdir -p /srv/devops /srv/plain
$ sudo chgrp devops /srv/devops /srv/plain
$ sudo chmod 770 /srv/plain; sudo chmod 2770 /srv/devops
$ ls -ld /srv/plain /srv/devops
drwxrws--- 2 root devops 4096 Oct 21 17:26 /srv/devops
drwxrwx--- 2 root devops 4096 Oct 21 17:26 /srv/plain
```

- After bob runs `touch` in each, `/srv/plain/a.txt` belongs to group `bob` and `/srv/devops/b.txt` to group `devops`
- Add sticky (`chmod 3770`) so members cannot delete each other's files; `ls` then shows `drwxrws--T`
- With the default umask `022`, new files are still `rw-r--r--`: the group can read but not edit
  - Fix with a `007` umask for the team, or with a default ACL

### Default ACLs
- An ==ACL== adds permission entries beyond owner, group, and other
  - `setfacl -m u:carol:rx dir` grants one more user; `getfacl` lists the entries
  - `ls -l` shows a `+` after the mode when extra entries exist
- A ==default ACL== (`d:` prefix, directories only) is copied onto everything created inside
  - Where it exists it replaces the umask for new files

```console label="Terminal"
$ sudo setfacl -m d:g::rwx,d:o::- /srv/devops
```

```console label="Terminal (bob)"
$ umask; touch /srv/devops/c.txt; ls -l /srv/devops/c.txt
0022
-rw-rw---- 1 bob devops 0 Oct 21 17:28 /srv/devops/c.txt
```

```console label="Terminal"
$ sudo setfacl -m u:carol:rx /srv/devops
$ getfacl /srv/devops
# file: srv/devops
# owner: root
# group: devops
# flags: -s-
user::rwx
user:carol:r-x
group::rwx
mask::rwx
other::---
default:user::rwx
default:group::rwx
default:other::---
```

- The ==mask== entry caps every named entry and the group entry
- `setfacl -x u:carol` removes one entry, `-k` the default ACL, `-b` all extra entries

:::exam
- "Files created in /srv/devops must belong to group devops" is setgid on the directory (`chmod 2770` or `g+s`). "Only the owner may delete" adds the sticky bit.
- "New files for user alice must be rw for owner and group, nothing for others" is `umask 007` in `~alice/.bashrc`. A system-wide value goes in `UMASK` in `/etc/login.defs`.
- Check the result with a fresh login (`su - alice`) and a real `touch`, not by rereading the file you edited.
:::
