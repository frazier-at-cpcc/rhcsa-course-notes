### How the umask sets default permissions
- Programs ask for a generous mode when they create something
  - New files: `666` (`rw-rw-rw-`); new directories: `777` (`rwxrwxrwx`)
- The ==umask== lists the bits to switch off in that request
  - Not subtraction: `666` with umask `033` gives `644`, not `633`
  - A umask never adds a bit, so new files never start executable
- Setting the umask is how you ==manage default file permissions==: no `chmod` after every `touch`

:::figure 10.2-umask-math.svg | With umask 027 the group loses write and other loses everything.

| umask | New file | New directory | Typical use |
|---|---|---|---|
| `022` | `644` | `755` | RHEL 10 default |
| `002` | `664` | `775` | group can edit |
| `027` | `640` | `750` | group reads, others nothing |
| `007` | `660` | `770` | team share, others nothing |
| `077` | `600` | `700` | private |

### Checking and changing it
- `umask` prints the value in octal; ==umask -S== prints the bits that stay on, as letters
- `umask 027` changes the current shell and the programs it starts
  - Gone at the next login
- The leading `0` is the special-permission digit; `umask 27` and `umask 027` are the same

```console label="Terminal (alice)"
$ umask; umask -S
0022
u=rwx,g=rx,o=rx
$ umask 027; touch f2; mkdir d2; ls -ld f2 d2
drwxr-x--- 2 alice alice 4096 Oct 21 19:54 d2
-rw-r----- 1 alice alice    0 Oct 21 19:54 f2
```

### Making the umask persist
- ==Per user==: add `umask 007` to that user's `~/.bashrc`
  - Read by every interactive bash shell after the system-wide settings, so it wins
- ==System wide== on RHEL 10: the `UMASK` line in ==/etc/login.defs==
  - `pam_umask` (in `/etc/pam.d/postlogin`, from the default authselect profile) applies it at every login: console, SSH, `su -`
  - Covers root too: RHEL 10 gives root and regular users the same `0022`
- A RHEL 9 habit that changed
  - RHEL 9 shell startup files gave regular users `0002`
  - On RHEL 10, `/etc/bashrc` sets `022` only when the umask is still `0`; `login.defs` decides

```console label="After editing /etc/login.defs"
$ grep ^UMASK /etc/login.defs
UMASK		027
```

```console label="Next login, as bob"
$ umask
0027
```

- Alternative: `/etc/profile.d/umask.sh` containing `umask 027`
  - Login shells only: `su bob` without the `-` skips it
- Home directories ignore the umask: `useradd` applies `HOME_MODE 0700` from `login.defs`
- Persistence: both files are read at each login, so a reboot changes nothing; prove it with `su - bob` and `umask`

### Special permissions: setuid, setgid, sticky

| Bit | Octal | On a file | On a directory |
|---|---|---|---|
| ==setuid== | `4` | runs as the file's owner | (no effect) |
| ==setgid== | `2` | runs as the file's group | new files inherit the directory's group |
| ==sticky== | `1` | (no effect) | only a file's owner can delete or rename it |

- Shown in the execute position: `s` for setuid and setgid, `t` for sticky
  - Capital `S` or `T`: special bit set but execute missing, usually a mistake
- Set with a leading fourth digit (`chmod 2770 dir`) or symbolically (`u+s`, `g+s`, `o+t`)

```console label="Terminal"
$ stat -c '%A %G %n' /usr/bin/{passwd,write} /tmp
-rwsr-xr-x root /usr/bin/passwd
-rwxr-sr-x tty /usr/bin/write
drwxrwxrwt root /tmp
```

- `passwd` is setuid root, so a regular user can update `/etc/shadow`
- The sticky bit on `/tmp` stops bob from deleting alice's file, even one with mode `666`

```console label="Terminal (bob)"
$ rm -f /tmp/alice.txt
rm: cannot remove '/tmp/alice.txt': Operation not permitted
```

### A shared group directory
- The classic task: a directory for group `devops` where members share files
  - ==setgid on the directory==: each new file gets group `devops`, whatever the creator's primary group
  - New subdirectories inherit the setgid bit too

```console label="Terminal"
$ sudo mkdir -p /srv/devops /srv/plain
$ sudo chgrp devops /srv/devops /srv/plain
$ sudo chmod 770 /srv/plain
$ sudo chmod 2770 /srv/devops
$ stat -c '%a %A %G %n' /srv/plain /srv/devops
770 drwxrwx--- devops /srv/plain
2770 drwxrws--- devops /srv/devops
```

- bob (primary group `bob`) then creates a file in each, plus a subdirectory

```console label="Terminal"
$ sudo ls -l /srv/plain /srv/devops
/srv/devops:
total 4
-rw-r--r-- 1 bob devops    0 Oct 21 19:54 b.txt
drwxr-sr-x 2 bob devops 4096 Oct 21 19:54 sub

/srv/plain:
total 0
-rw-r--r-- 1 bob bob 0 Oct 21 19:54 a.txt
```

- Add sticky so members cannot delete each other's files

```console label="Terminal"
$ sudo chmod 3770 /srv/devops
$ stat -c '%a %A' /srv/devops
3770 drwxrws--T
```

```console label="Terminal (alice)"
$ rm -f /srv/devops/b.txt
rm: cannot remove '/srv/devops/b.txt': Operation not permitted
```

- `T` is capital because other has no execute here; that is expected on a `770` share
- With umask `022`, new files are `rw-r--r--`: the group can read but not edit
  - Fix with a `007` umask for the team, or with a default ACL

### Default ACLs
- A ==default ACL== (`d:` entries, directories only) is copied onto everything created inside
  - Where one exists, the umask is ignored for new entries in that directory
  - `getfacl` lists the entries; `setfacl -k` removes the default ACL, `-b` every extra entry

```console label="Terminal"
$ sudo setfacl -m d:g::rwx,d:o::- /srv/devops
$ getfacl -cp /srv/devops
user::rwx
group::rwx
other::---
default:user::rwx
default:group::rwx
default:other::---
```

```console label="Terminal (bob)"
$ cd /srv/devops; umask; touch c.txt; ls -l c.txt
0022
-rw-rw---- 1 bob devops 0 Oct 21 19:54 c.txt
```

:::exam
- "Files created in /srv/devops must belong to group devops" is setgid on the directory (`chmod 2770` or `g+s`). "Users may delete only their own files" adds the sticky bit.
- "New files for alice must be readable and writable by owner and group only" is `umask 007` in `~alice/.bashrc`. "All users" means `UMASK` in `/etc/login.defs`.
- Check with a fresh login (`su - alice`) and a real `touch`. A `umask` typed at the prompt is lost when the shell exits.
:::
